## MODIFIED Requirements

### Requirement: 代码问答默认以业务语言呈现并在后台保留证据
代码问答的 Skill、工具说明和 Runtime 回答约束 MUST 一致要求默认按结论、触发条件、操作影响和必要待确认项组织回答，保留环境、SVN 版本、适用业务端、完整条件、例外和影响结论的未知项。配置或操作问题 SHALL 优先按已核验的页面位置、可见控件/选项、填写内容、生效动作与预期结果说明步骤，再解释必要原理；页面可见名称、必须原样填写的文字和变量表达式属于业务操作信息，应按证据保留。正文 MUST NOT 主动展示源码、文件路径、行号、函数名、内部字段/枚举、接口/工具名、原始错误码、hash、内部 ID 或检索/保存/索引过程；依赖失败影响结论时以业务语言说明实际影响，用户明确要求保存但失败时须如实说明。状态名称、配置和现场根因未经核验不得猜测为事实。仅在用户明确要求技术分析且当前授权允许时可展开相关技术证据，不能借此扩大授权或披露凭据。

后端取值规则 MUST NOT 单独用来推断前端入口、控件选择方式、配置项名称、填写要求或刷新/执行步骤；未核验的操作须限制为待确认范围，不得先作为确定指南给出再在末尾笼统声明未核验。用户提供的操作经验 SHALL 明确来源，不能当作已读取的目标版本源码证据。

保存的业务标题、正文和结论 SHALL 使用业务语言，详细证据继续保存在后台结构化记录中。命中历史知识时 SHALL 按相同规则重述，不照搬历史技术细节，不丢失适用条件。复用前 MUST 确认完整答案覆盖当前所问操作及其界面/执行证据；只描述后端的答案不得直接扩写为配置指南。缺少必要证据时按现有同 Job 源码流程补查，无法补齐则限制结论；覆盖充分时无需重复读源码或保存。实际采用的完整答案引用 SHALL 通过内部标记关联，平台 MUST 核验同任务、同环境、来源与版本下真实成功读取或保存的记录，并在会话消息、报告、Job 结果和投递前移除标记；不得把候选、失败或未采用的答案自动记为依据。

#### Scenario: 普通用户询问操作被阻止
- **WHEN** 已核验页面操作在某质量状态下被阻止，但该状态业务名称或后续校验尚未确认
- **THEN** 用页面、操作步骤和业务影响解释已确认规则，保留未知范围，不输出代码或把推测名称当事实

#### Scenario: 复用含技术细节的历史答案
- **WHEN** 当前环境、版本和条件匹配的完整答案含文件路径、内部字段或工具回执
- **THEN** 重述为业务解释并保留条件与未知项，详细证据和经核验的引用仍在后台保留

#### Scenario: 隐藏引用但保持可追溯
- **WHEN** 最终结果包含本任务实际采用答案的内部引用
- **THEN** 后台保存经核验的结构化关联，用户可见会话、报告、Job 结果与投递正文不含内部标记和 ID

#### Scenario: 配置操作需要原样填写文字
- **WHEN** 已核验某数值控件需勾选指定复选框并在相邻输入框填写指定业务名称，执行后另一页面读取结果
- **THEN** 回答明确控件所在页面、复选框可见文字、输入框位置和准确填写内容、执行动作及下游结果，不用内部字段描述代替操作步骤

#### Scenario: 旧答案只覆盖后端读取
- **WHEN** 用户追问如何配置，但同版本完整答案只说明后端按变量标识取值
- **THEN** 补查相关配置与执行链，或明确缺少可确认的操作步骤；不得推断必须使用变量选择器或不能手工输入
