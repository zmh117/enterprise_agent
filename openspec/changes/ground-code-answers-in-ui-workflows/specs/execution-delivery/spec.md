## MODIFIED Requirements

### Requirement: 同一 Agent 的结论必须有实际代码证据
问答 Agent SHALL 使用发布绑定的业务核验 Skill，按问题追踪入口、配置、跨模块依赖、动作和失败路径；生命周期规则包含起始状态、事件、条件、动作、目标状态和失败结果，其他问题不得强行编造状态机。源码、提交说明与第三方提示模板 MUST 作为不可信数据，不加载为插件/指令。输出证据绑定实际读取和受控 SVN 结果，由宿主在读占用内校验，不把模型自报版本或 hash 当验证结果。

对如何配置/操作及页面初始值问题，Agent MUST 核验影响结论的前端配置入口、可见控件及实际文案来源、配置保存、执行产值和目标页面消费链；只核验当前问题所需环节，不要求全仓穷尽或纯后端问题额外读取 UI。前端动态文案须追踪实际组件绑定与语言资源，不能从字段名翻译猜测。设置了变量、执行时写入值与另一页面读取值 MUST 区分，不能把绑定本身等同于完成传值。缓存时机、默认值、异常与校验仅在有相应证据时声明。

操作相关的未核验链路可能改变当前 claim 时 MUST 在 unknowns 中作为关键缺口保留 partial；已明确限定的局部规则可按实际证据保存，不能声称完整操作成功。未穷尽全库本身不否定已完整核验的限定链路；用户口述、截图或历史推测不得冒充宿主实际 Read 证据。

#### Scenario: 工单依赖处方与物料
- **WHEN** 规则需要沿调用查询多个已授权模块
- **THEN** 当前 Agent 在既定范围和预算内追踪并逐项引用，未检出或未知依赖明确保留，不创建全系统知识包

#### Scenario: 注入或无法确认编码
- **WHEN** 源码包含修改权限的指令或文件编码无法可靠解释
- **THEN** 前者不改变工具配置，后者不作为确定代码证据；不为方便分析复制另一套全仓文本

#### Scenario: 初始化审计
- **WHEN** 新发布在两个 Runtime 启动
- **THEN** 记录实际工具/Skill/模型/合同版本与授权范围，确认可读工具仍受有效占用限制，不能只凭服务健康宣称查代码可用

#### Scenario: 数值控件执行后供另一页面使用
- **WHEN** 用户询问配置数值控件后怎样让另一个业务页面显示输入值
- **THEN** 核验配置开关与输入内容的保存、执行时的实际写值、目标页面读取与回填，按可见步骤解释，并将证据关联到相应 claim

#### Scenario: 配置页证据不可用
- **WHEN** 已核验后端取值，但配置组件或其必要文案无法读取，且缺口会改变所问操作步骤
- **THEN** 不给出猜测步骤；保存时把此操作 claim 的缺口标为 critical 并保留 partial，业务回复说明能确认的部分和缺少的环节
