## Context

当前 Skill 具体描述报错追踪；共享 `CODE_ANSWER_PRESENTATION_INSTRUCTIONS` 已进入知识工具说明和 Runtime 提示，但仅约束业务措辞。配置问题需要补齐证据取得和使用规则，不能只调整最终格式。现有 claims、conditions、coverage、unknowns 和宿主 Read 证据足以承载结果。

## Goals / Non-Goals

**目标：** 用户能按已核验的页面位置、可见控件和操作顺序执行；初始值问题能说明值在哪里配置、何时产生、何时被读取。未核验环节不进入确定操作指南。

**非目标：** 不新增浏览器、截图或源码执行能力，不构建全库 UI 索引，不添加强制所有问题读取前端的规则，不把用户纠正直接作为确定知识，不自动覆盖旧答案。

## Decisions

1. **按问题追踪完整但有界的链路。** 配置/操作/页面初始值问题，读取前端配置组件及实际显示文案（动态文案追踪语言资源）、控件值保存、执行时产值和下游消费。先用页面可见词定位，再按绑定与调用继续；不要求穷尽仓库。只问纯后端规则时无需额外找 UI。
2. **直接证据与业务说明分层。** 配置标记是否必须勾选、旁边输入框填写什么、需执行或刷新哪些动作，都属于待证明的 claim。未知项影响这些步骤时必须 critical/partial；不能在正文断言后仅在末尾注明“页面未核验”。仅确认局部规则时明确范围。未读到标签不能由内部字段猜中文。用户报告的步骤可作为已注明来源的线索，不伪造 Read 证据。
3. **共享短约束加 Skill 详细流程。** 在共享说明中提供完整的最小边界，使无 Skill 的发现阶段和缓存命中也获得规则；详细追踪步骤只放 Skill。复用旧知识前检查覆盖，缺少所需 UI 证据时沿现有同 Job 流程补查，完整已验证答案仍可直接复用。不设计按文件后缀计数的“前端校验器”，因为文件存在不能证明操作语义。
4. **回答采用操作顺序。** 配置类优先“位置 → 控件/选项 → 填写内容 → 生效动作 → 预期结果”，再解释必要原理和未知项。可见标签、必填字面值和变量表达式属于操作信息，不受内部代码信息隐藏规则误删。禁止把未核验的上级菜单补成完整路径。
5. **显式版本与验证边界。** 提示模板升至 v22；测试检查新规则从共享说明进入工具、发现阶段、源码阶段、发布 Skill 和内部引用清理后的业务文本。合成测试证明接线与保留，不证明真实模型已遵守，真实模型及目标版本案例另列验收。

## Risks / Trade-offs

- 前端查找消耗预算 → 优先当前问题必要链路、重用已读证据；预算不足保留缺口，不新增任务补查。
- 旧答案虽为 supported 但缺少新问题所需步骤 → 检查完整答案的 coverage/conditions/unknowns，不能凭状态直接生成指南。
- 规则仍依赖模型落实 → 本地验证明确限于规则传播；部署后检查真实回答及后台证据。

## Migration Plan

无数据库迁移或重新 Embedding 要求。协调更新产生 Prompt/工具合同的 API、Worker、Dispatcher、knowledge-mcp 与两个 Runtime；重新发布版本化 Skill 并更新应用绑定，以新 Job 验收。旧发布/任务不改写。回退时协调回退服务及发布绑定，不混用提示版本。

## Open Questions

无实现规格待定项；目标环境部署与真实问答验收仍需执行。
