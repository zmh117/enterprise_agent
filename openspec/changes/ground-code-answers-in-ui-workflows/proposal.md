## Why

当前代码问答要求业务表达，但 Skill 的具体核验流程偏重报错分支，没有把配置界面、控件执行和值的消费串起来。只查后端取值规则时，模型仍可能推断出未经核验的变量选择、填写或刷新步骤，用户无法照着页面操作。

## What Changes

- 配置、操作和页面初始值问题按相关前端入口、可见控件/文案、配置保存、执行产值、下游取值追踪；只核验影响当前问题的链路。
- 操作回答优先说明位置、控件、填写内容、生效动作与预期结果，保留业务上需要原样填写的文字或变量表达式。
- 前端证据缺失时限制结论，不从后端字段推断操作方法；相关缺口影响当前 claim 时保留 partial。用户描述单独标明来源，不能冒充已读代码证据。
- 复用旧答案前核对是否覆盖当前操作问题；缺少界面或执行链证据时按既有流程补查，而不是仅换成业务措辞。
- 同步 Skill、共享工具/Runtime 约束及提示版本，增加传播回归与真实问答验收指引。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `builtin-tool-resource`：代码问答的业务表达与历史答案复用须以已核验的界面步骤为依据。
- `execution-delivery`：操作类结论须追踪前端配置、执行和消费链，正确限定缺失证据的影响。

## Impact

涉及 `.claude/skills/code-business-query/SKILL.md`、共享代码问答说明、Runtime 提示模板版本、回归测试与运行手册。不增加工具、数据表、证据类型或独立分析任务；不自动修改历史答案。更新服务并重新发布 Skill/应用后使用新 Job 验收，现有冻结任务不改写。
