## ADDED Requirements

### Requirement: 知识库网页运维必须通过独立受限执行器
系统 SHALL 提供同机知识库独立 Compose 的构建、启动、停止、状态和日志入口。主程序侧常驻执行器 MUST 仅执行固定知识项目及服务的允许操作；普通 API 不持有 Docker socket，网页不得传任意命令、源码路径、Compose 文件或凭据。停止 MUST 保留数据卷、模型、同步进度及控制入口；构建 MUST 不隐式应用版本或触发采集。

#### Scenario: 停止后再启动
- **WHEN** 管理员停止整套知识库服务
- **THEN** 同步先保存断点，知识服务有序停止，主程序与执行器继续运行，管理员可以再次从网页启动

#### Scenario: 请求绕过操作边界
- **WHEN** 请求未获管理权限、缺少 CSRF 或带任意命令/路径/多余参数
- **THEN** 系统拒绝请求，不执行 Docker 操作

### Requirement: 知识运维任务与真实进度必须持久化
系统 SHALL 在执行前保存操作身份、幂等键、固定参数、执行人和状态，并保存安全事件及心跳。网页和 CLI MUST 共用任务与互斥。页面刷新不得停止任务；失联 MUST 显示未知，构建没有可靠总量时不得伪造百分比。执行器重启 MUST 先核对服务状态，无法证明完成的变更操作报告中断；重试不能重复创建内容修订。

#### Scenario: 重复提交与刷新
- **WHEN** 客户端重复提交相同幂等键或刷新进度页面
- **THEN** 返回同一个操作，任务在后台继续，进度可重新读取

#### Scenario: 查看日志
- **WHEN** 用户按任务或服务读取事件
- **THEN** 有界返回安全阶段、计数、标识与错误码，不返回原始构建输出、认证材料或业务正文

### Requirement: 采集计划必须协调三库调度与排队补采
系统 SHALL 复用采集绑定中的类型到知识库映射，由一个常驻调度进程执行首次全量、小时同步和指定创建日补采。首次启用 SHALL 立即进入调度；暂停自动调度只影响后续定时触发，不打断当前任务，不改变检索发布。补采 MUST 等待同来源活动任务完成，固定参数续跑，不修改常规最近七日策略。单文档进度按知识库聚合，成功内容不因其它文档失败撤回，未变文档不重新索引。

#### Scenario: 三库仅缺陷有变化
- **WHEN** 同一计划下缺陷新增三条，需求及工单无变化
- **THEN** 页面显示缺陷三条处理进度，另外两个库无需处理，集合与发布修订不变

#### Scenario: 小时任务期间提交补采
- **WHEN** 当前来源有活动同步且管理员提交指定日期补采
- **THEN** 补采排队，当前同步先完成，再执行固定范围补采，之后遵循原自动调度开关

#### Scenario: 同步重启
- **WHEN** 同步进程在补采中停止或重启
- **THEN** 复用同一任务范围与未完成 run，保留成功文档，不把补采误当常规窗口

#### Scenario: 自定义内容库
- **WHEN** 资源实际指向外部内容数据库
- **THEN** 页面不得自动将其纳入受管采集，继续保留现有同平台写入约束
