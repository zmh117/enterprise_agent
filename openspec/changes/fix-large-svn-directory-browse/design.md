## Context

浏览经受管 SVN operation、knowledge-sync 和有界内存结果端点执行。现实现用递归 list 生成全树，8 MiB XML 上限会在大型分支浏览时触发。文件树不持久化到数据库。

## Goals / Non-Goals

目标是只读取用户实际展开的层级、复用原连接和固定 revision、保持文件与目录勾选及对齐。不开通任意命令，不提高全局 XML/内存上限，不改变完整检出的容量和工作副本校验限制，不新增数据表或 Agent 工具。

## Decisions

1. 首次 browse 和子目录 browse 都使用 `svn list --xml --depth immediates -r N URL@N`。相对路径校验、逐层目录类型检查、取消、超时和输出限制继续有效。保留递归 inventory 供现有检出预检调用。
2. 增加管理端 `browse-children` 提交，参数仅根 browse ID、相对目录与幂等键。服务端验证同操作者、同资源当前草稿、根操作成功且为根目录，继承来源、连接摘要与固定修订。执行前照常复核连接和配置，不能自行指定新 URL、凭据或版本。
3. 前端展开时提交并轮询该层；折叠不丢选择，重复展开复用本次浏览已取得结果；失败显示重试。修改仓库/认证/版本或重新浏览时销毁旧树，旧响应不能混入新树。父目录勾选包含所有子项，未展开目录也能整目录检出。
4. 目录结果继续短暂留在内存，数据库仅保存操作元数据与所请求目录。单层超限或缓冲区满明确提示，绝不截断后宣称完整；巨大单层与完整检出的容量限制仍可能拒绝。

## Risks / Trade-offs

按层请求增加网络往返，换取与展开范围相关的开销。根元数据在原配置不变时可固定后续子层，不依赖已过期的全树结果。目标环境尚未访问，现场原始响应是否由 stdout 或 stderr 超限不能从通用错误码判断；用合成大树和真实隔离 SVN 验证实现，不宣称已修复现场部署。

## Migration Plan

验证后协调更新 API、knowledge-sync 与 admin-web，无数据库迁移，不重放失败任务。首次刷新重新浏览。暂不更新本机或远端容器；提供目标机器构建更新命令。
