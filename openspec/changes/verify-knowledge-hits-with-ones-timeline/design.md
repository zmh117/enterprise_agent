## Context

知识检索输出历史片段。消息工具目前单次 GET 后裁剪到模型指定 limit，详情也存在无提示的正文截断。ONES 官方消息文档明确 count 最大 100、send_time 微秒倒序且唯一，续页 max 为上一页最后一条时间戳（不含边界）：https://docs.ones.cn/project/open-api-doc/project/message.html 。

## Goals / Non-Goals

**Goals:** 对用于诊断结论的相关命中核验最新详情和评论，服务自动收集时间线，并诚实暴露收集与实际阅读边界。

**Non-Goals:** 不把全部命中无条件展开、不采集附件正文、不将评论批量写入知识库、不改权限、不增加独立 Agent 或新容器。

## Decisions

- Agent 编排：按症状/条件选择相关候选，按来源及 UUID 去重；对准备采用的工作项先读详情，再读消息文件。每项追踪根因、方案、修复版本、现场换包、回归及重开信息。用户明确仅查历史快照时不强制在线核验。
- 复用现有两个 ONES 工具，不在 knowledge_search 内自动产生 ONES 查询。这样知识检索权限与本人 ONES 权限保持独立；缺少工具/绑定/权限或服务失败时可保留历史线索，但不得伪称已核验。
- 消息公开输入仅 work_item_uuid；内部固定 count=100，通过 max 向历史翻页，最多 1000 条、50 页、90 秒和 8 MiB 规范化内容。总数仅表示已收集数，不误用上游当前页 count 为全量总数。
- 校验页条数、has_next、UUID 唯一性、严格递减微秒时间及跨页 max 进展。重复页、空续页、协议/权限/网络失败返回安全错误，不包装此前部分页面为成功。数量或页数上限返回明确截断原因；超时/容量失败明确未完成。
- 评论正文每条最多 16000 字符，输入解析仍有界；保留脱敏和富文本去除。返回 text_truncated、text_truncated_count、messages_complete、complete、incomplete_reasons、page_count 和起止时间。complete 仅表示工具收集投影完整，不代表模型已阅读整个结果文件或附件。
- 复用 ONES Job 临时只读文件桥，将消息正文留在文件，完整性元数据直接返回模型；Job 结束清理。详情继续有界输出并增加 description_truncated/related_items_truncated。
- Skill 与共享 Prompt 同步，记录核验成功/未读完整/核验失败的工单范围；消息合同比较及 Prompt 升级，部署后仅切换 assist03。

## Risks / Trade-offs

- 旧私有部署可能不遵守公开分页协议 → 用合成多页测试和部署后真实调用分别验证；协议异常明确失败，不猜测游标。
- 活跃工单读取时继续有新评论 → 覆盖截至首个响应最新消息的历史，不宣称原子快照或持续实时。
- 增加查询耗时 → 只核验相关且用于结论的候选，保留 Job 预算；尚未核验项必须单列。
- 工具参数变化 → 同步更新合同使用方容器和应用发布，保留既有权限及执行策略。无需数据库迁移，回退须同时回退镜像和应用绑定。
