## Context

`code_checkout_reader` 在截取行之前通过 `SENSITIVE_NAME` 和 `SENSITIVE_CONTENT` 拒绝整个文件，Grep 复用此校验并跳过文件。`code_svn_history` 同样阻断文本 diff，并省略匹配正则的提交说明。语言资源中的 `password: '请输入密码'` 已用合成数据证实会被误判。

## Goals / Non-Goals

**Goals:**
- 按用户要求移除源码查询的文件名、内容正则阻断，使已授权的配置和语言资源可核验。
- Read、Grep、SVN diff/log 行为一致，移除不再适用的 Skill 指令和覆盖描述。
- 用合成 SVN 文件和历史结果验证新行为及保留边界，不读取现场凭据或业务内容。

**Non-Goals:**
- 不扩大知识库、环境、路径、版本、操作授权，不允许 Runtime 写源码。
- 不修改平台凭据解析、业务文档脱敏、普通操作日志或受控完整审计的既有规则。
- 不新建开关、白名单服务或内容分类器，不迁移数据或重建索引。

## Decisions

1. 删除两个启发式正则及源码访问调用点，不用更复杂的文案判别替换。调用者已明确选择按授权范围访问内容。
2. 源码读依然先验证受 SVN 跟踪、精确版本、原始文件摘要、工作副本内容及格式，再输出有限片段；二进制、超限和扫描预算不足继续报告不完整。
3. SVN 历史仍要求单文件 diff、授权内端点和固定版本；log 对越权路径、超长说明的省略继续生效，普通字段词不再使说明消失。
4. 保留历史错误码的固定中文解释供已完成任务审计使用，新源码查询不再产生该错误。不改工具 Schema。

## Risks / Trade-offs

- 授权源码中的字符串将按普通内容提供给分析任务，不再做凭据启发式筛查；继续依靠知识库路径授权及平台凭据与源码隔离的原有边界。
- 旧 Skill 发布仍可能描述旧规则；同步仓库 Skill，并在部署说明中明确容器代码和不可变 Skill 发布需分别更新。

## Migration Plan

完成针对性回归和规范校验后，部署方构建两个 Runtime 与 knowledge-sync，按既有发布流程更新使用该 Skill 的应用。无数据迁移；本次本地验证不代表真实环境部署或原问题模型验收。
