## Context

Runtime 的 `build_system_prompt` 汇总统一报告结构与可选 Skill。ONES 列表可通过只读临时文件提供完整数据，但模型仍可能只读或只展示其中一部分。结果服务原样保存最终回复，现有 Delivery 按字符无损分片；这两层不能恢复模型从未输出的记录。

## Goals / Non-Goals

目标：所有工具来源、包括无 Skill 的运行，均收到明确的明细完整性、稳定 ID 自检、范围说明与长标题格式约束；保留摘要/样例请求的原有简洁行为。

非目标：新增结构化报告协议、自由文本计数器、强制二次模型调用、无条件自动重试、扩展工具权限或预算、修改 ONES 状态历史口径、改变消息分片算法。

## Decisions

1. 使用 Runtime 通用系统 Prompt，而不是 ONES Skill；明细输出是通用回答责任，不能依赖某个 Skill 是否启用。已有“证据摘要”报告结构仍保留，但不得替代用户明确要求的明细。
2. 在 Prompt 中要求先读取完成相关的有界结果，再按筛选后稳定 ID 集合核对明细数量、遗漏和重复；区分上游总数、实际获取数、筛选数和展示数。示例说明获取 29 条筛选为 20 条时，应列 20 条，而不是 29 条。
3. 不识别或删除最终文本中的所有省略号：标题本身可能合法含有这些字符。禁止的是模型自行用“其余略”等替代记录或截短所需字段。只有上游本身缺失或截短时说明局限，不能补造。
4. 长标题默认采用编号列表。通用 Runtime 不应假定每个渠道均支持分片，因此仅对支持长报告分片的目标（如现有钉钉 Delivery）说明可使用既有分片；不自行声明后续消息已投递，不调用写入工具规避长度限制。
5. Prompt template version 从 v6 升为 v7，使审计区分语义变化；不修改 MCP Schema/权限、Runtime 协议或历史 Job。部署需保持 Worker/Runtime 的共享 Prompt 版本一致，不借此放宽漂移校验。

## Risks / Trade-offs

- Prompt 属于模型软约束 → 自动测试只能证明注入内容、既有结果保存与分片无损；真实模型仍需用独立验收确认，不承诺程序级不漏行。
- 明细可能较长 → 保留用户明确要求的汇总/前 N 条/样例范围，并在模型上下文、工具预算或输出限制不足时诚实标注部分结果。
- 组件版本不一致 → 相关控制面/Worker/Runtime 使用同一构建；不改历史快照或 MCP 工具契约。

## Migration Plan

无数据库迁移，无 Skill 配置修改。验证后部署兼容代码并以新 Job 验收；保持旧 Job 审计原值。若将来需要硬保证，应单独确认“结构化记录集 → 程序渲染”设计，而不是扩大本次范围。
