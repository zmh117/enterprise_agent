## Context

当前共享上限映射把标准工作项查询归为1000条、50次请求；服务按该映射执行，Runtime按共享输出schema校验后物化只读结果文件。用户要求仅提高 `ones_query_work_items` 到10000。

## Goals / Non-Goals

**Goals:**

- 正常预算内自动取得4715条；10000完整、10001明确截断。
- 即使Provider每页只返回50条，也允许200次请求达到10000。
- 收集、输出校验、工具描述与部署消费者保持一致。

**Non-Goals:**

- 不提高旧关键词搜索、自定义选项查询或其他工具上限，不新增配置或模型分页参数。
- 不改变90秒、8MiB、HTTP/Job/Sandbox限制、授权、审计和失败关闭，不连接其他环境或真实ONES。

## Decisions

- 将原“测试资产大集合”集合/预算名称改为能涵盖标准工作项查询的名称，沿用已有两档策略；仅加入一个工具，不新建策略框架或配置层。
- 标准查询输出schema引用同一共享上限，避免服务已返回10000但Runtime仍只接受1000。输入schema/hash不变。
- 页数档位随同一代码集合选择：扩展集合200次、其他50次，单页最多200；不把每页大小设置为10000，也不恢复模型cursor。
- 基于现有合成HTTP测试扩展两类固定查询路径和50/200条页，检查4715及10000边界、剩余工具不变、沙盒只读/终态清理和安全预算；不把合成通过视为真实环境验收。

## Risks / Trade-offs

- [大结果可能触及90秒或8MiB] → 保留失败关闭；10000是条数上限，不保证任何数据量/网络条件下都能取满。
- [其他环境保留旧镜像仍停在1000] → 明确需要部署同版本ONES和Runtime共享schema，本轮不修改远端。
- [运行中服务仍是旧镜像] → 只读核对容器合同并记录部署差异；本次不重启现有ONES服务，不随代码修改扩大到部署或无关迁移。

## Migration Plan

运行本地定向回归、合成查询与文件物化、静态/规范检查；只读核对当前容器合同，不在本次代码修改中重启服务。后续部署需重建同版本ONES、API、Worker和Runtime；输入hash不变，不额外修改发布快照；回滚需所有相关消费者一起恢复旧版本。当前运行实例及其他环境需单独部署并以新Job验收。
