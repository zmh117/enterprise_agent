## Context

用户已确认发布表示知识库可用，不要求一轮采集同时生效。当前 `CandidateVectorRepository.index_code` 绑定 run，`configuration_values` 绑定全库内容，`ManagedSyncActivation` 自动发布，造成整代复制和反复全量扫描。工作区已有补采、批量 SQL 和分块复用修改，必须保留。

## Goals / Non-Goals

**Goals:** 固定 collection；文档级增量分块/向量写入/清理；独立进度和可重复恢复；发布配置与内容解耦；安全有界检索。

**Non-Goals:** 不增加消息队列，不实现批次快照或跨存储事务，不改变创建日采集合同，不自动部署或读取真实业务内容。

## Decisions

1. 在现有索引上显式登记增量模式；物理 index_id、collection、profile 稳定，点身份继续使用 index_id 与不可变 chunk_id。现有离线构建用于初始化或模型变更，不作为小时同步的第二条分支。
2. 新发布配置只包含 KB、来源、物理索引和连接/模型/分块配置；来源摘要、成员、数量、updated_at 不参与配置一致性。同步不调用 publish，查询仍复核当前权限和启用状态。
3. 在线采集只暂存观察到的事项及变化，保留日分页检查点；不冻结全库。来源缩减检查仅查询本轮创建日范围。按文档记录准备、写向量、应用当前版本、清理完成等步骤，单来源串行处理，失败保留步骤并继续其他文档。
4. 新向量先隐藏，完成有限逐点核验后提交该文档当前版本，再开放新向量并删除旧块。允许单篇短暂缺失；候选必须通过当前文档版本和当前 ONES 个人权限校验。稳定点 ID 与逐项检查支持写入成功但记账失败的重放。
5. 增量同步不调用全库 snapshot/assert_current/manifest；只验证改变的文档和向量。批次完成情况与发布状态分离。全库维护检查是显式命令。
6. 旧代清理不得删除增量 collection。外部内容库保持只读；受管写仍限定同平台数据库和固定 Qdrant。内容更新不受资源发布/停用/草稿状态驱动，但配置变更必须拒绝继续使用漂移的目标。

## Risks / Trade-offs

- Qdrant 写入与数据库事务不原子 → 持久步骤、稳定 ID、隐藏候选、只读核验及重试；不先删除当前旧向量。
- 混合检索的 IDF 随集合内容变化 → 不承诺排序快照；只保留当前可读文档，及时清理旧块。
- 旧部署仍使用内容快照合同 → 显式维护转换索引和资源配置，失败可重复恢复；不在 schema migration 中执行网络 IO。
- 未确认来源删除 → 不将缺项当作删除。

## Migration Plan

新增前向 schema migration，部署匹配代码后停止旧同步写者；显式维护命令验证并转换现有当前索引和发布配置，保留原文和已验证向量，再恢复同一绑定。处理未完成旧 run 时必须显式完成或取消后迁移，不混用两个合同。维护记录输出安全 ID/计数/错误码，真实环境执行单独验收。
