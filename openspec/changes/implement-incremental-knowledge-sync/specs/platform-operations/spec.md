## MODIFIED Requirements

### Requirement: ONES受管同步必须保持创建日窗口和文档级增量更新
系统 SHALL 通过显式配置和启用的绑定执行首次历史全量、后续每 3600 秒最近七个北京时间创建日及明确日期补采。受管同步 MUST 使用每知识库固定的向量集合，按新增/变更文档独立完成分块、向量核验、当前版本更新及旧块清理；MUST NOT 因日常内容变化重建整个集合或重新发布资源。单来源写者互斥，处理步骤持久可恢复，失败不得撤回其他已完成文档。发布只控制知识库可用性，采集开关独立；内容及 Qdrant 写入仍限定受管同平台目标，不从来源缺项推断删除。

#### Scenario: 少量新增
- **WHEN** 三个知识库中只有缺陷库新增三篇
- **THEN** 只处理三篇对应块，旧块不搬运，三个 collection 和资源发布修订保持不变

#### Scenario: 较早创建的事项最近更新
- **WHEN** 工作项创建日在最近七日之外但最近发生更新
- **THEN** 常规同步不声称覆盖该更新，明确补采按创建日范围执行

#### Scenario: 文档处理后进程中断
- **WHEN** Qdrant 写入、文档应用或清理后响应丢失
- **THEN** 重启复用已完成结果，只补做未完成步骤，不重新处理成功文档

#### Scenario: 单篇失败
- **WHEN** 一篇文档处理失败而其他文档完成
- **THEN** 其他文档可检索，失败项持久保留并报告部分失败，不报告整轮成功


#### Scenario: 同时间戳内容变化
- **WHEN** 受管增量在线采集获得与当前来源观察时间戳相同、语义内容或类型不同的单据
- **THEN** 直接以本次内容创建本地修订，保留原始来源时间戳及旧修订；该文档派生完成后独立生效，不额外请求详情复核，不因这一差异中断整轮采集
- **AND** 来源时间戳更旧仍不得覆盖当前版本；同一内容重放不重复创建修订或写向量；离线导入保留既有版本冲突规则

#### Scenario: 采集元数据变化
- **WHEN** 只有归一化版本、来源采集快照或完整性标记变化，标题、正文、类型、业务属性、显示名称与关联相同
- **THEN** 不创建内容修订；语义摘要只规范化明确无序的集合，不忽略业务内容数组的顺序

#### Scenario: 同时间戳修订日志
- **WHEN** 同时间戳内容修订提交候选或完成文档派生
- **THEN** CLI 输出结构化事件，包含运行及单据 ID、旧新来源时间戳、旧新语义 hash、修订 ID、处理阶段和固定原因码，明确区分候选已提交与内容已生效
- **AND** 事件不得包含标题、正文、业务字段值、异常原文或认证材料；重放事件带相同事件 ID 供去重

#### Scenario: 配置变化
- **WHEN** 来源、模型、连接或分块配置变化
- **THEN** 原处理任务拒绝在漂移配置下继续；单纯资源停用或内容增加不触发重新发布

#### Scenario: 外部内容连接
- **WHEN** 在线知识资源使用独立内容 PostgreSQL
- **THEN** 其读取可按当前合同验证，受管同步不得自动向该外部库写入

## ADDED Requirements

### Requirement: 增量知识派生处理必须有界
系统 MUST 仅对本轮观察及改变的文档建立处理记录；小时同步和在线检索 MUST NOT 为配置校验复制或扫描全部成员及全部向量。全库核验 SHALL 作为显式维护操作。新增点在完成前不得占用检索候选，旧块清理 SHALL 按确定的点 ID 执行，不得误删固定集合。

#### Scenario: 无变化同步
- **WHEN** 本轮只有内容相同的来源观察
- **THEN** 不执行分块和向量编码/写入，不复制全库候选或创建新集合

#### Scenario: 查询时有并行补采
- **WHEN** 新文档仍在准备且用户检索已有内容
- **THEN** 未完成块不进入候选，检查仅覆盖当前配置和有界命中文档
