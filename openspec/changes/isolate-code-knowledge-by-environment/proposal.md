## Why

当前代码知识库可关联多个业务环境，但关联仅用于模型选库提示；代码检索、答案身份和问答历史均没有环境隔离。相同知识库和 SVN 版本下，不同环境的答案可能被混用。用户已明确要求代码问答必须提供环境，并贯穿选库、持久化和复用。

## What Changes

- **BREAKING**：代码知识检索和源码分析必须携带用户明确提供的环境，缺失、停用或不属于当前发布知识库配置的环境均拒绝，不猜默认环境。
- 知识目录支持按环境筛选代码知识库；存在多个候选时继续明确知识库，不自动选第一项。
- 将稳定环境身份绑定到搜索凭证、源码分析、版本化答案、索引和最终问答历史，后续读取再次核对环境。
- 旧无环境的代码答案与历史不推断环境，不参与新代码检索；ONES 知识和环境自身的数据授权规则保持原有合同。
- 更新模型说明、工具合同、迁移和跨环境拒绝测试。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `builtin-tool-resource`：代码目录、检索、全文答案及源码工具必须绑定明确环境。
- `platform-operations`：代码答案、检索凭证、分析与问答历史按环境持久化及隔离，旧无环境数据不可复用。

## Impact

影响 Knowledge MCP schema、代码分析控制面与 Runtime 桥、PostgreSQL/SQLite 迁移、答案索引及问答记录。复用现有表、环境拓扑和知识库发布关联，不新建每环境数据库、代码检出或服务。部署须更新控制面、Knowledge MCP、Worker 和 Runtime，并发布采用新工具合同的配置；本地测试不代表真实多环境验收。
