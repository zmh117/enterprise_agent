## Context

当前 `code_resource_environment` 已保存发布配置与多个环境的关联。目录向模型显示关联，但 `knowledge_search` 没有环境参数，`code_answer` 身份仅包含来源、SVN 版本和问题/条件/路径，`code_qa_record` 也没有环境。继续依赖自然语言条件无法阻止串用。

## Goals / Non-Goals

**Goals:** 每次代码问题明确一个环境；按环境选库、核对用户声明、绑定搜索和源码分析、持久化答案和问答历史，并在读取时强制隔离。

**Non-Goals:** 不为每环境复制检出、不增加独立数据库或服务、不改变 ONES 合同、不把环境关联当成额外知识库授权、不隐式升级旧答案。

## Decisions

1. 外部工具使用精确 `environment` 编码，服务端解析启用的 `platform_environment.id`。代码库必须在当前发布配置中关联该环境。环境 ID 进入分析、答案与历史；编码改名不制造新的答案身份。
2. `knowledge_list_bases` 增加 `source_kind`（默认 ONES）；代码目录必须指定 `source_kind=code` 和环境，仅列出该环境当前授权且发布可用的代码 KB。多个候选仍需用户选择。分页绑定筛选条件。
3. 代码搜索和代码工具必须带环境。控制面在私有输入读取边界核对用户明确的环境声明，支持“环境：编码/名称”和“编码/名称环境”；缺失或多环境歧义要求补充，不根据应用默认、checkout 或模型猜测选择。显示名重名时必须使用编码。源码工具还核对分析/凭证的环境，无法切换。
4. 代码答案身份加入稳定环境 ID；PG 查询先按 KB、来源、环境、SVN 版本、路径和就绪状态过滤，再向量召回和重排。向量候选仍经 PG 复核，全文读取和较高版本线索同样隔离。
5. 问答历史按任务、知识库、环境记录，引用必须属于同环境；没有环境的追问不写成可复用业务答案。旧无环境行保持不可查询，不回填默认值，不回退无环境内容。新写入在应用与数据库边界拒绝空环境。
6. 新迁移扩展现有表，历史字段允许 NULL 仅为保留不可复用记录；新写入约束拒绝 NULL。不建立环境层级、隐式继承或跨环境共享规则。

## Risks / Trade-offs

- 旧无环境答案失去复用能力 → 明确重新提问/分析，禁止推断归属。
- 新合同使旧工具快照失配 → 通过正式 Agent/Application 发布和新 Job 使用，部署同时更新相关服务。
- 一个问题含多个环境 → 明确要求拆分或选择一个环境，避免把多环境最终回答复制到各环境历史。
- 本地测试与现场不同 → 使用合成的双环境、同源码同版本与多知识库用例验证；真实 SVN/模型验收单独记录。
