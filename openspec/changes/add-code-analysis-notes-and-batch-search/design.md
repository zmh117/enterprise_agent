## Context

当前代码只派生 Read/Glob/Grep，Grep 仅支持单文件名命中；已有随机执行沙盒、固定文本写入规则、原子预算和恢复清理可复用。

## Goals / Non-Goals

实现当前执行笔记与有界目录搜索，减少逐文件调用。保持 SVN 源码只读、按版本核验及证据 ID。不开通 Shell，不增加服务、长期源码副本、数据库表或独立提取 Agent。

## Decisions

1. 纯代码 Job 派生 Write，目标仅 `work/notes/**/*.md` 或 TXT；不能 Edit、写 outputs 或其他分区。混合文件 Job 保留独立授权。笔记保存 SVN 版本、路径行号、证据 ID、已查范围与未知项，不应整段抄录源码。
2. 原生 Grep 仍由 SDK 执行；Runtime 先在 grant 内从 SVN metadata 枚举候选，验证受管状态、版本、内容和敏感限制，再将规范化 UTF-8 文本放到代码生成的只读临时目录。原生 Grep 只看该目录，完全不扫描检出中的未跟踪文件、外部链接或 `.svn`。
3. 每次最多 64 个候选文件、32 MiB 正文、200 行输出、前后各最多 5 行上下文；目录枚举上限 10000 个受管候选。支持 glob 收窄，超限明确失败，绝不返回虚假的完整零命中。敏感或不可解码候选只返回跳过计数与不完整标记，不泄露其路径和正文；版本或内容变化整次失败。
4. 缓存共享现有 sandbox 原子容量/文件数预算。搜索并发序列化，防止多个批次突破工作区配额。完成、失败、取消后清理本次搜索副本；SDK 完全停止后清理整个 Job Sandbox，异常退出复用残留扫描。
5. 返回命中还原原源码路径、行号；搜索仅为定位，不生成证据 ID，必须 Read 原源码核验。笔记、搜索副本和原始输出不得进入普通审计正文，只有工具次数与安全元数据。
6. 工具派生策略更新为 code-source-v3，提示词统一升级；控制面、Worker 与 Runtime 同步部署，现有执行先排空，不改写已冻结 Job。

## Risks / Trade-offs

- 首次批量核验和转码有 IO 成本，但节约模型逐文件往返；未通过真实模型对比前不承诺时延提升。
- 64 文件批次受现有 80 个 work/output 配额约束；已有文件占用时明确预算失败，模型可缩小 glob。不为缓存扩张沙盒配额。
- SDK 输出结构可能变化：通过真实 SDK/CLI 合成 Provider 测试验证；未知结构失败阻断，不能泄露内部缓存路径或未经核验正文。

## Migration Plan

无需数据库迁移。测试后构建并在无活动执行时更新控制面、Worker、Runtime；被动核对提示词、工具合同与容器代码摘要。不启动真实模型任务。
