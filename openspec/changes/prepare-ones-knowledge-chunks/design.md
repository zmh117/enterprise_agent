## Context

现有 knowledge 仅包含七张存储表及离线导入。2026-09-16 恢复原 PostgreSQL 卷后核验 head=132、5,000 个缺陷、5,000 个版本/收录、2,407 条关联。正文长度中位数 91、P99 为 1,051、最大 25,886 字符；4,955 条不超过 1,200 字符。解决方案为 3,110 个字符串，其余缺失或 null。没有现成分块、Embedding 或索引代码。

## Goals / Non-Goals

**Goals:** 保留短文完整性、长文有界拆分、解决方案独立证据、上下文模板、精确来源定位、版本化派生结果、可恢复幂等运行和真实全量验收。

**Non-Goals:** 采集、附件/OCR、模型调用、语义摘要、向量索引、召回评估、MCP/Web、授权修改、通用插件式流水线、消息队列或定时调度。

## Decisions

1. **派生结果不覆盖原版本。** 新增 `document_chunk_set` 和 `document_chunk` 两表。前者是单个 document_revision 与固定配置摘要对应的一组完整结果，保存规范化字段、来源内容摘要、版本配置、质量统计和输出摘要；后者保存有序片段。每文档一个事务，成功集合与全部块同时提交，失败不留半组。没有新增全局任务编排表：重跑扫描当前文档并复用已校验结果即可恢复。
2. **纯规则且只处理已批准的来源文本。** v1 仅支持现有 ones-offline-text/v1、defect、active、included、storage_only 数据。正文使用 body_text；方案使用 attributes.solution_text；不重复引入富文本快照，不拼入关联工作项正文。只做换行、控制字符及边缘空白行清理，保留代码缩进、错误码、数字、表格和内部换行；不做 Unicode 兼容折叠、不重复 HTML 解码、不猜测删除业务内容。
3. **来源坐标明确。** chunk 的字段名和字符起止位置指向 chunk_set.normalized_fields 中对应的完整规范化字段，区间是 Unicode 字符的左闭右开，不宣称是源 HTML、原文件字节或原 body_text 偏移；通过集合的 document_revision_id 回溯原版本。验收逐块检查 evidence_text 等于精确切片，并检查规范化正文非空白字符无遗漏。
4. **短文优先。** 规范化正文不超过 1,200 字符时一个问题块；超过时优先在段落、步骤标题、行及句末边界切分，软目标 900、硬上限 1,200，重叠至多 120 字符。围栏代码块可容纳时不切；超长代码/日志按行续块，极端超长单行才硬切并标记。禁止截掉尾部，禁止强行把短文切成多个固定块。
5. **方案不过度提纯。** 非空、非明确状态占位的方案独立生成 solution 块；若与正文完全相同则不重复生成。保留跳过原因与质量标记，不把分类字段或“已处理/已修复”生成为因果解释。
6. **证据与模型输入分开。** evidence_text 仅是规范化字段切片。embedding_text 使用固定模板添加标题、产品/模块/环境/版本等有限上下文；方案块额外带短问题上下文。上下文最多 550 字符，可裁剪但必须标记；证据不裁剪，完整输入不超过 1,800 字符。规则版本、模板版本、配置摘要及文本摘要一并保存。此限制是字符预算，不是假装已选择 Embedding 模型的 token 预算；后续接模型须独立核验 token 上限。
7. **稳定身份与安全复用。** 集合以 revision_id + profile_hash 唯一，块以集合 + ordinal 唯一，输出确定性摘要校验完整内容。来源锁与导入共用；写入前锁定并复查当前来源版本及收录状态。新来源版本或新配置产生新集合，历史集合不覆盖；“当前块”只在当前版本、有效文档、有效收录下解释，不能拿历史集合或来源 readable 标记当授权。
8. **有界批处理。** 使用主键游标分页，每次最多 100 个文档，逐文档生成/提交。CLI 默认只读 dry-run，可用 head=132 预检；显式 --commit 只接受新 head。只输出计数、直方图、固定错误码和内部结果标识；内置 demo 只使用合成数据，不打印真实标题、正文、人员、URL 或凭据。
9. **迁移复用已有治理。** 下一个版本暂定 133；写入前复核目录与 active change。PostgreSQL 使用 knowledge 限定名，SQLite 使用引号点表名。新表带中文注释、外键与唯一约束并纳入事实源清单。抽出导入/分块两个现有调用者共用的表名、稳定 ID、SQL 插入和来源锁函数，不建扩展框架。

## Risks / Trade-offs

- 规则不等于最优召回 → 本轮只验收内容保存和分块质量，不声称提升召回率；后续用评测集校准。
- 仅图片表达的细节缺失 → 保留图片/讨论未采集质量标记，不生成图片语义。
- 上下文裁剪和状态占位筛选可能降低信息量 → 原版本与完整规范化字段保留，记录标记，可版本化重跑。
- DB 中已有敏感内容清洗不等于数据出境批准 → 不调用外部模型，不开放检索授权；后续数据出境仍需明确决策。
- 新 head 与旧镜像不兼容 → 本轮开始时全应用栈已停止，仅恢复 PostgreSQL。完成后准备相关镜像供后续启动，不擅自启动整栈；若期间业务服务恢复运行，先确认安全更新窗口。

## Migration Plan

先合成测试与隔离 PostgreSQL 验证，再通过 one-shot Migrator 追加 133，运行实际库 dry-run/commit/replay。源七表内容摘要与计数前后必须一致。失败保留成功集合并重跑恢复，不 drop schema、修改历史 migration 或回退账本。保持原先停止的无关服务不启动。

## Open Questions

Embedding 模型、token 上限、Qdrant 索引和 MCP 授权属于后续阶段，不影响本轮生成有界、可追溯的文本块。
