# Docling CPU benchmark

Executed at 2026-08-21 against the locally running pinned image:

```text
quay.io/docling-project/docling-serve:v1.30.0
sha256:0244089785d5ccb7570dfaa593cdc81ec64a1aadc63ffa9dce065064b0a6a807
linux/arm64, Docker VM: 10 CPUs / 16,748,032,000 bytes
Docling limit: 4 CPUs / 8 GiB, local engine workers: 1
file-processing-worker limit: 1 CPU / 512 MiB, concurrency: 1
```

The inputs were generated by `scripts/generate_docling_synthetic_samples.py` and
contain deterministic synthetic text only. The benchmark client
`scripts/benchmark_docling_cpu.py` uses the production `DoclingServeProvider`, the
fixed `docling-text-v1` profile and the internal multipart submit/poll/fetch API. It
does not print Markdown, Docling JSON, task IDs, credentials or source grants.

## Results

| Input | Bytes | Pages | Wall time | Processor time | Files/min | Markdown | Docling JSON |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| PDF, 10 pages | 3,145 | 10 | 10.025 s | 8,074 ms | 5.985 | 279 B | 5,044 B |
| DOCX | 42,699 | 0 reported | 2.014 s | 76 ms | 29.796 | 192 B | 36,308 B |
| PPTX, 3 slides | 36,047 | 3 | 2.011 s | 96 ms | 29.836 | 139 B | 98,210 B |
| XLSX, 100 rows | 6,660 | 1 | 2.019 s | 15 ms | 29.721 | 3,773 B | 141,948 B |
| PNG with text | 11,993 | 1 | 4.014 s | 2,311 ms | 14.946 | 87 B | 2,027 B |
| JPEG with text | 40,055 | 1 | 4.013 s | 2,337 ms | 14.950 | 87 B | 2,028 B |
| WebP with text | 5,524 | 1 | 4.020 s | 2,369 ms | 14.925 | 88 B | 2,031 B |
| PDF boundary: 300 pages, 25 MiB - 1 KiB | 26,213,376 | 300 | 246.518 s | 246,110 ms | 0.243 | 8,932 B | 138,408 B |

All eight conversions returned non-partial success and non-empty Markdown plus
Docling JSON. Before submitting the boundary PDF, the platform source validator also
confirmed its exact byte size and 300-page count.

The Docling cgroup `memory.peak` increased from 3,308,146,688 to 3,514,445,824 bytes;
the latter is a conservative container-lifetime peak of approximately 3.27 GiB and
includes model residency. Post-run steady memory was approximately 2.42 GiB by
`docker stats`. The long boundary-file latency leaves insufficient safe CPU and tail
latency margin for concurrency 2, so phase 1 remains fixed at concurrency 1. No
processing queue, retry queue or DLQ messages remained after the benchmark.

The 600-second worker/provider timeout and Docling server timeout therefore remain
executable for the accepted 25 MiB/300-page boundary on this reference host. This is
a capacity baseline, not a production SLO; other architectures and scanned PDFs must
be load-tested before raising concurrency.
