## Context

本机已有完整 MES 工程，主平台具备知识管理权限、PostgreSQL、knowledge-sync 和固定 SVN 版本采集器。现有采集器是知识准入流程，不承担完整工程工作副本的创建。用户要求本地 SVN 服务、完整导入和网页多选检出，模型提取保持关闭。

## Goals / Non-Goals

**Goals:** 本地 HTTPS SVN 仓库；完整导入三套工程；管理页输入已登记地址、多选目录、固定版本检出；持久进度、权限和目录隔离；真实源码字节核验。

**Non-Goals:** 局域网共享、网页上传本机文件、网页管理 SVN 用户或写入 SVN、自动覆盖/合并工作副本、模型调用或知识发布。

## Decisions

1. 独立可选 Compose 服务 `code-svn` 使用 Apache/mod_dav_svn 提供 HTTPS，只映射 `127.0.0.1:18443`，同时加入当前项目的 knowledge-managed 网络和专用 code-svn-local bridge（使 Docker Desktop 的回环端口映射可达）。服务只允许网络读取；初始化和首次导入通过显式部署命令在仓库卷上执行。证书在本机生成，客户端信任明确的证书文件，不忽略 TLS 校验。这样可直接复用现有 HTTPS SVN 合同，无需允许通用不安全协议。
2. 仓库持久化在 `.local/code-svn/state`；完整工作副本根目录为 `.local/code-svn/checkout`，在 knowledge-sync 内映射到 `/var/lib/code-svn/checkout`。每个任务写入其中独立的相对子目录。导入按原字节、目录和链接保存，不读取正文到日志，不应用知识准入过滤。SVN 无法保存的特殊文件或保留元数据导致导入失败，不能静默跳过。
3. 在现有知识管理页增加 SVN 检出区。管理员输入部署登记的公开地址；服务器使用登记中的内部地址、UUID 和认证目录。未知地址、URL 中的凭据及任意宿主机路径不接受。初始登记只有本机仓库；接真实生产 SVN 时由部署者登记其只读连接。
4. 增加一个专用 `knowledge.code_checkout_job` 表保存浏览和检出任务、操作者、幂等键、配置摘要、状态和安全结果。复用 knowledge-sync 的可选线程模式与现有数据库；API 不执行 SVN、不挂 Docker socket、不持有完整源码卷。后台执行前重新检查当前管理员权限。任务受全局 advisory lock 串行执行；重启发现未完成任务标记中断，不冒充成功。
5. 浏览固定一个 revision 并返回有界目录树。检出引用已成功浏览的任务，选择只能来自该树，因此浏览后 HEAD 更新不改变本次文件版本。使用 SVN 稀疏工作副本和 `--ignore-externals`；第一版发现仓库分支存在 externals 声明即明确拒绝检出，不能声称工程完整。普通版本控制文件不按扩展名过滤。完成后核验选中目录的 UUID 和实际 revision，避免 svn update 跳过路径却返回成功。
6. 检出先写任务专属临时目录，完成后原子重命名到目标目录。目标存在、符号链接、路径穿越、父子重复选择均拒绝；失败只清理本任务临时目录。原工程、其他工作副本和知识快照保持原样。
7. 知识提取仍使用现有 `CodeSourceRegistry`、`SvnSourceAdmission` 和固定源码快照。完整 SVN 导入不取消模型读取的准入边界，本次不启动模型提取或自动切换历史知识身份。
8. API 和 knowledge-sync 的登记、证书、检出卷接线放在主 Compose，开关 `CODE_CHECKOUT_ENABLED` 默认关闭；本机显式开启。可选覆盖文件只管理 SVN 服务与导入容器，避免正常重建或知识服务“应用版本”时丢失检出接线。主 Compose 的宿主目录优先使用显式变量，否则基于 `KNOWLEDGE_DEPLOY_ROOT` 解析，兼容现有运维控制器的 Docker daemon 路径约定。

## Risks / Trade-offs

- 完整工程可能包含用户希望保留的配置和依赖 → 按用户明确选择原样导入，仅本机可读，不在日志或响应中返回文件内容。
- 本机 HTTPS 证书不是公共 CA → 只为这一个登记使用生成的可信证书，不修改系统信任或关闭证书核验。
- SVN 网络超时或进程中断 → 有界执行、停止信号终止子进程、持久失败/中断状态；已有目录不覆盖。
- 新表增加 schema head → 同步迁移事实源及必要测试，通过后更新依赖 schema head 的本地容器。

## Migration Plan

先验证独立服务和合成检出，再导入真实三套工程并核对目录/文件摘要；添加登记和目录挂载，运行迁移，更新受影响服务。只启用完整工程检出线程，保持代码采集和模型提取开关关闭。停用时停止本地 SVN 与检出线程，保留仓库、工作副本和任务记录。

## Open Questions

无。目录多选已确认用于 SVN 检出；默认首次导入三个已选工程。

## 检出文件预览补充

浏览结果在现有有界 SVN 清单内同时返回 directories 和 files，前端按父路径分组、展开后渲染，文件使用独立图标且可单独勾选，与目录混合提交。任务摘要轮询排除两类完整清单，仅浏览详情返回它们；不新增文件内容读取接口。检出前记录所选节点类型，文件按路径 update，目录使用无限深度 update；完成时核验对应类型和版本。
