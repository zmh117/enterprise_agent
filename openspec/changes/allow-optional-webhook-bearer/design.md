## Context

当前代码的配置 schema v2 已将 Webhook 绑定到业务角色，Agent、触发和投递由应用发布管理。canonical 的强制 Bearer 要求需要明确修改；本次只调整鉴权要求与调用帮助，不扩展其他关联配置。

## Goals / Non-Goals

目标：允许不填写凭据发布并调用；保留带凭据入口的严格鉴权；在页面提供准确的 HTTP 示例。

范围外：不添加更多认证协议，不更改应用或角色授权，不自动触发真实任务或发送消息。

## Decisions

- 在现有 authentication 对象中增加 `type: none`，引用为空时规范化到该模式。显式 `none` 携带非空引用属于矛盾配置，应拒绝；已有 `bearer_v1` 加有效引用原样保留。缺失/未知认证模式不得在接收端降级为免鉴权。
- 保存时去除引用两侧空白；非空引用仍执行格式校验。发布阶段仅在 Bearer 模式解析、检查强度和唯一性。运行时只有冻结的显式 `none` 可免 Authorization；Bearer 解析失败仍拒绝。
- 配置页只提供一个可选凭据字段，空值和非空值分别生成对应模式。示例使用固定合成报文和当前 public ID；按通用 JSON/Grafana 类型展示，Bearer 值始终为占位符。示例说明它依据当前编辑配置，修改需发布才生效。
- 示例采用用户请求的 `http://localhost:8000` 后端直连地址，并明确远程调用需替换地址。当前管理端没有 `/webhooks/` 转发，不推断管理端 origin 为接收地址。

## Risks / Trade-offs

- 免鉴权入口允许持有有效接收地址者触发应用，这是用户明确选择的行为；页面直述“留空时无需 Authorization 请求头”。角色、应用路由和事件边界继续校验。
- 草稿修改与当前运行版本可能不同；在示例附近注明保存、发布、启用和应用激活要求。

## Migration Plan

无需数据库迁移。部署 API 与前端；既有发布不重写。启用或取消 Bearer 均通过新草稿发布生效。回滚代码会拒绝 `none` 发布，不会把受保护入口降级。

## Open Questions

无。用户已确认“允许免 Bearer 调用，凭据改为可选”。
