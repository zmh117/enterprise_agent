## Context

现有采集按七个创建日，候选代际仍复制完整知识库；向量复用每 32 块关联检索，清单及检查点逐块 SQL，激活对默认同一目标重复校验。范围由 run manifest 冻结但 CLI 无日期入口，sync_run 时间未随派生阶段更新。保留当前不可变集合、单写者和原子激活，不改真实环境任务。

## Goals / Non-Goals

目标是可恢复的显式日期补采、减少数据库往返和重复工作、可诊断停采。非目标是真正物理增量向量、MQ、通知机器人、自动扩大七日范围、删除校验或自动修改错误配置。

## Decisions

1. `sync --mode once --from-date YYYY-MM-DD --through-date YYYY-MM-DD` 两个参数同时提供，按北京时间闭区间创建日扫描，不能早于绑定 first_date、不能晚于当天。无历史激活仍要求先做初始全量；常规 daemon 不接受自定义日期。范围以 `backfill` 模式和实际日期冻结到 manifest；恢复原 run 时拒绝不同范围或拿常规 daemon 接续未完成 backfill，不新建第二写者。
2. 新增前向迁移，仅为已 INDEXED 的向量清单增加 `(index_id, embedding_text_hash)` 检索索引，查询先用清单 hash 过滤再关联块。清单以最多 32 项多行 INSERT 后单次批查，检查点以批量 UPDATE 处理，保留冲突和数量验证。Qdrant 字节/批次上限不随意扩大。
3. 对指定文档 revision/profile 读取已存在块集，验证稳定 ID、profile、输出摘要、逐块 hash、数量和序号后复用，不重新运行文本清洗切分；损坏时失败而非重写。保留当前正文与块 hash 合同。
4. 构建完成和激活仍分别做完整独立校验；激活内同一候选及同一 Qdrant 配置只校验一次，其他存储/凭据引用必须独立校验。校验结果仅在本次进程/调用内复用，不持久缓存、不把 READY 状态当充分证据。资源、连接、配置、授权和事务 CAS 复核不变。
5. 在既有 checkpoint_json 记录节流的安全派生进度和更新时间，采集日断点不被覆盖。状态/health 显示最近成功/失败、活动阶段和陈旧原因。容器健康检查执行只读状态诊断，不加载主密钥或访问 ONES。无成功激活超过两周期、活动进度超过两周期未更新或最新运行失败时报安全告警/非零 health，禁用不报警，首次部署给两周期宽限。失败仍区分瞬时和永久错误，不通过无限重启掩盖配置错误。

## Risks / Trade-offs

- 整代复制仍是 O(全库)；本轮不承诺分钟数，以 SQL 次数及相同语料分段基准验收。
- 索引增加需统一迁移，使用新的空闲版本号；并行 Webhook 迁移不改写，不自动在业务库执行。
- 健康检查不是外部通知渠道，部署监控需订阅 unhealthy/结构化事件；不自动创建外部消息。
- 本机没有目标环境运行状态；真实 SQL 执行计划、BGE-M3 吞吐及补采结果保持未验收。
