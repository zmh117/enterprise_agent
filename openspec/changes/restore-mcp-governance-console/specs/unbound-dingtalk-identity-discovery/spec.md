## MODIFIED Requirements

### Requirement: 未绑定钉钉消息形成安全发现候选
系统 SHALL 只为通过渠道认证和规范化、已持久化且明确因钉钉身份从未绑定、身份已停用或解绑、或所属用户已停用而被拒绝的新消息创建发现候选，并 MUST NOT 因此创建 Agent Job、发布 Job 消息、调用模型或调用任何 MCP Tool。

#### Scenario: 从未绑定用户发送私聊消息
- **WHEN** 部署本功能后，一个没有历史钉钉身份的用户向已启用机器人发送私聊消息
- **THEN** 系统返回现有未授权提示、创建或更新该用户的发现候选，且不得创建 Agent Job

#### Scenario: 从未绑定用户发送群聊消息
- **WHEN** 部署本功能后，一个没有历史钉钉身份的用户在群聊中向已启用机器人发送消息
- **THEN** 系统创建或更新同一身份候选并记录安全群会话标识，且不得触发 Agent 或 MCP 执行

#### Scenario: 不符合身份发现条件的入口失败
- **WHEN** 钉钉事件因 Connector 认证失败、格式错误、缺少 `senderStaffId` 或非身份授权原因被拒绝
- **THEN** 系统 MUST NOT 创建身份发现候选，且不得泄露事件是否对应现有人员

## ADDED Requirements

### Requirement: 未绑定钉钉页面接入完整治理 Shell
系统 SHALL 在“身份治理”导航域提供未绑定钉钉候选列表、徽标、筛选、详情、选择现有人员、新建人员继续绑定和历史身份恢复入口，并 MUST 使用现有受信候选 API 与真实数据。

#### Scenario: 管理员从候选绑定并分配初始角色
- **WHEN** 有权限管理员选择当前候选、启用自然人用户和自己可分配的零个或多个角色
- **THEN** 系统按现有事务规则完成身份绑定和角色成员关系，页面刷新人员详情、有效权限摘要和候选徽标

#### Scenario: 候选绑定中途冲突
- **WHEN** 候选、用户或角色 revision 在提交前已经变化
- **THEN** 系统原子拒绝操作、保留候选并要求页面刷新，不把客户端身份字段作为可信事实
