## Context

业务应用当前只解析钉钉私聊、群聊及 Webhook。Webhook 固定执行用户并按事件隔离会话。Agent 编辑器已有入口及投递 Connector 选择器，应用已有按触发器冻结投递绑定的机制。关键入口是 `business_application/domain/{models,delivery_routing,runtime}.py` 和 `channel/application/channel_ingress_service.py`，后者的来源判定和回复路由都有钉钉专用分支。

Python Runtime 1.5 已定义带序号的 `assistant_text{text}`。当前 `claude_client.py` 汇总 SDK 文本，`invocations.py` 在执行结束后发出最终回答。Worker 的 `runtime_http_client.py` 校验并消费内部事件，普通事件审计对文本只投影字符数。管理端完整 invocation 审计另有专门的权限和读取接口。

插件的 `extension/ui/control.ts` 能预览已保存的请求，`extension/export/package.ts` 可生成包含回放、原始值和采集缺口的 ZIP。其 `shared/redaction.ts` 主要保护密码。本方案的联调对象是这个现有控制台。

## Goals / Non-Goals

用户可在控制台纯文字提问，或选中一段已结束录制，预览并确认共享其接口与操作诊断数据，在同一应用内持续查询。插件在生成期间展示回答，支持同会话追问与重新打开。首版范围限定为用户主动发送、文本回复；录制进行中的实时上传、上传 ZIP、文件交付和插件内外部写操作确认留待独立需求。依赖原渠道确认的能力须继续按其现有前置条件处理。

## Decisions

### 1. 发布时绑定渠道，运行时按当前用户授权

登记代码支持的 `browser_extension` Connector，在 Agent 入口/投递目录中提供同一个受管连接。业务应用触发器使用 `browser_extension`、`CURRENT_SENDER`，路由键由服务端使用稳定应用标识生成，例如 `application:<id>`。绑定 `reply_original` 及相同 Connector，实际投递路线指向本次原插件会话。客户端只能从本人可用的活动应用选择；服务端重新解析部署、应用、Connector、项目、授权和 Publication。纯文本输出走会话结果读取，无公网回调、钉钉发送器或通用 HTTP 目标。复用既有 Agent 发布上限和每入口投递规则，可支持同一应用同时接收钉钉与插件问题。

### 2. 平台登录，插件只持有短期业务凭据

本期部署使用内网 HTTP。插件保存平台的完整 Origin（协议、主机、有效端口），例如 `http://agent.intra:8080`。HTTP 支持内网 IP 或域名。登录、授权码兑换、应用列表、录制上传、提问、历史和 SSE 均使用所选平台 Origin。扩展按该协议及主机申请 Chrome 主机权限，并在每次请求时核对端口。携带业务凭据的 fetch 禁止跨 Origin 重定向；连接失败按原协议报错或重连，切换平台需重新授权。[Chrome 扩展网络请求](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)

首次连接由用户发起 `chrome.identity.launchWebAuthFlow`。登录和授权页面位于所选平台，完成后跳至 Chrome 为该插件生成的固定回调，该回调由浏览器截获。发行包 manifest 使用固定公钥，服务端内置对应的公开客户端标识和固定回调。服务端从 HTTP 请求的 Host（含非默认端口）及 ASGI 的协议识别平台 Origin，按该 Origin 隔离授权、凭据、回执和 HTTP 授权专用父会话。首次登录使用系统的现有自然人账号。服务端校验精确插件标识和回调，原子兑换绑定平台 Origin、回调和 PKCE S256 的一次性授权码；插件校验 state。PKCE 在扩展受信上下文计算。授权码最长 60 秒，业务凭据最长 15 分钟且不超过父 Session 剩余期限；服务端仅保存凭据哈希及归属。插件以内存保存业务凭据，通过 Authorization 头调用接口。[Chrome 扩展身份 API](https://developer.chrome.com/docs/extensions/reference/api/identity)

内网 HTTP 部署复用同一账号校验、限流、过期和撤销逻辑，在平台登录页建立仅用于插件授权的父 Session。HTTP 授权 Cookie 使用独立名称、Host-only、HttpOnly、SameSite=Lax 和授权路径。服务端校验会话用途、本站 Origin 与 CSRF；现有管理 API 拒绝该会话。现有 `WEB_COOKIE_SECURE` 是全站配置，插件接入无需关闭管理 Session 的 Secure。业务 API 在提交和读取（含已有数据流继续发出）时复核当前授权。HTTP 承载的登录信息、业务凭据、问题与答案均缺少传输加密，适用于组织接受该条件的内网部署。

#### 活动期间自动续期

首次授权时，平台记录用户在该登录会话中向该插件授予的范围。每次兑换返回业务凭据、实际剩余有效秒数和服务端确认的账号归属。发送问题、调度分片或保持回答订阅期间，插件依据有效期提前换证。若浏览器休眠或回到插件时凭据已经到期，下次操作前也可换证。并发提问、分片和订阅共用同一次进行中的换证。没有待办操作时不定时续期，续期不能越过父 Session 的闲置或绝对期限。

插件以 `launchWebAuthFlow({interactive: false})` 访问原平台授权页，每次生成新的 state 和 PKCE 校验材料。平台用浏览器在该站的父 Session 验证同一内部用户、原有插件授权、来源、发行版回调及范围，并在签发和兑换时检查有效性。涉及 Cookie 的授权写入仍通过同源请求校验 CSRF。非交互续期沿用该 HTTP Origin 的插件专用父 Session。新凭据仅存内存；过期凭据不能单独用于换证，插件无需保存长期刷新令牌。[Chrome 非交互授权流程](https://developer.chrome.com/docs/extensions/reference/api/identity#type-WebAuthFlowDetails)

| 服务端或浏览器状态 | 插件行为 |
| --- | --- |
| 仅业务凭据到期，父 Session 和授权仍有效 | 主动换证，或在请求收到凭据到期的 401 后换证。用新凭据恢复该次请求一次。若其他操作已完成换证，迟到的旧 401 复用新凭据。若此次换证未延后截止时间，则在下次实际到期时复核，避免连续换取相同截止时间的凭据。 |
| 父 Session 已退出、到达闲置或绝对期限，或已被撤销 | 暂停并显示「重新登录以继续」，由用户打开登录页。重新登录为原账号且业务范围仍有效才恢复原工作。若父 Session 有效但需要首次或重新同意授权，只提示用户确认授权。 |
| 账号停用、插件禁用或应用权限撤销 | 停止相应操作并提示不可用。换证或重复登录不能恢复该权限。切换账号或平台时隔离待发问题、上传进度和答复草稿，禁止自动发给另一身份。 |
| 暂时离线、超时或无法完成静默交互 | 网络故障保留进度，联网后有限重试；浏览器要求交互时提供用户点击的「继续授权」入口。恢复前复核身份和权限。 |

业务请求只在收到 `401 credential_expired` 时自动换证一次。`login_required` 提示重新登录，`consent_required` 提示用户确认，`access_denied` 或对当前业务的 403 停止对应操作。授权回调在匹配 state 后才采纳这些结果。无回调的断网、超时或关闭窗口保留进度，不据此认定用户退出。插件只采纳当前连接发起的授权结果，并核对发起时的 Origin 和预期账号（首次登录除外）。若用户已退出、换号或切换平台，迟到的成功兑换及失败通知均丢弃。按认证响应中的租户与内部用户匹配原工作，最终仍由平台复核资源权限。

#### 凭据过期后的业务恢复

| 中断位置 | 在原用户和授权范围内继续 |
| --- | --- |
| 连续提问 | 保留当前待发问题及其原始 `client_message_id`、会话和录制绑定指令。尚未发送就继续提交；提交结果不明就用原 ID 和完全相同的输入重试。已拿到回执则直接跟踪原 Job，不重复排队。 |
| 大录制上传 | 暂停发新片。若收片期间到期，服务端在确认分片或发布前复核凭据。进度以服务端已提交的分片为准，即使确认响应丢失也算已收。恢复时带原版本键和清单查询服务端回执，只发缺片。已发布则直接复用 `recording_id`。暂存已过保留期时提示用户重新发起上传。 |
| 流式回答 | 原凭据到期后服务端停止发送并关闭旧流，已受理的 Job 继续运行。换证或重新登录后，插件用新认证头订阅原 Job，并以最后已渲染的 `Last-Event-ID` 续读。旧流迟到事件不得覆盖新流。无可用草稿或游标时读取快照，已终结则读取持久结果。 |

### 3. 双方 HTTP 契约

以下路径以 `/api/browser-extension` 为前缀。前端使用带认证头的 fetch 读取 SSE，可在重连时带游标。用户 ID、发布 ID、执行用工具和输出目的地均由服务端确定。

| 请求 | 输入与结果 |
| --- | --- |
| `GET /auth/authorize` | 在所选平台打开授权页，校验并绑定发行版的 `client_id`、`redirect_uri`、`state`、`code_challenge` 与 `code_challenge_method=S256`。静默请求携 `prompt=none`。成功或可判定的拒绝均经固定回调返回原 state 以及 code 或 error。 |
| `POST /auth/token` | 受信插件用同一 client_id、redirect_uri、code 和 `code_verifier` 兑换。成功返回 `access_token`、`expires_in`（秒）、`tenant_id` 和不可变 `user_id`；后续业务请求使用 Bearer 认证。 |
| `GET /applications` | 返回此人可用的活动应用 ID、显示名及创建录制和提交问题时需回传的 scope_ref。 |
| `POST /applications/{id}/recordings` | 用户确认后，以 upload_attempt_id、稳定的本地录制版本键、投影版本和清单（两类行数、ID 集摘要、各分片序号/大小/摘要及采集缺口）初始化或恢复上传。返回服务端不可变版本引用 `recording_id`、状态及缺片序号。已就绪版本直接复用。 |
| `PUT /recordings/{id}/parts/{n}` | 仅发送缺片，版本化 UTF-8 NDJSON，支持 gzip 传输。校验解压后的确定性字节摘要、契约与容量后确认该片。同片同内容幂等，同键异内容冲突。 |
| `POST /recordings/{id}/complete` | 复核清单、索引与明细，成功才原子发布为可查询；重复完成返回同一回执。缺片返回所缺序号，重新打开可用原初始化请求查询进度。 |
| `POST /applications/{id}/messages` | 输入稳定 `client_message_id`、可选 `conversation_id`、`question`。首次绑定或切换时带已就绪的 `recording_id`；省略沿用本会话绑定，显式 null 解除。首问无绑定可纯文字。受理后返回 202、实际会话、Session、Job 和本轮绑定引用。 |
| `GET /applications/{id}/messages/{client_message_id}` | 在当前授权归属内只读查询已提交的原 202 回执，含实际会话、Job 与绑定。未找到可见回执返回 404，不创建 Job。 |
| `GET /conversations/{id}` | 返回本人在该应用当前可访问的有序问答（有界分页）、当前录制引用和可用状态、在途 Job 及已提交的结果。插件可在本机仅记录按账号、平台和应用区分的非敏感引用以恢复。 |
| `GET /jobs/{id}` | 返回经授权的回答快照及其 through_cursor，或持久终态。快照可直接用于重开或补读事件。 |
| `GET /jobs/{id}/events` | 返回 SSE。每条有数据的事件带递增的 Job 内游标。接受 `Last-Event-ID`。终态或历史增量已清理时从持久结果恢复。 |

授权路由也使用该前缀。授权页凭父 Session 工作，兑换使用 PKCE，两者不要求先有业务凭据。所有业务读写与回执查询独立复核当前授权。

发送前按账号与应用保存非敏感的 client_message_id 及原会话和绑定指令，不持久化问题正文。单个控制台按用户提交顺序等待上一条受理回执后再发送下一条，不等上一轮回答结束；多窗口以服务端受理事务的顺序为准。原文仍在内存时可按原请求幂等重试。首问回执丢失且控制台已重开时，用消息 ID 查询回执，即使没有 conversation_id 也能找到原 Job。查询暂未命中可能是原请求仍在途，允许有限重查；没有可恢复正文时提示用户确认输入，以原键再次提交。同键异内容返回冲突，禁止自动换键重发。

初始化录制与提交消息均在 `X-Application-Scope` 头回传用户选择应用时取得的 scope_ref。服务端先校验当前身份和资源访问；未受理的旧请求遇到范围变化返回 `409 scope_changed`，不在新发布下自动创建任务。已受理请求只可在仍有读取权时返回原回执。用户重新选择当前范围后提交的新问题按既有规则分配会话。

会话、消息和 Job 写入沿用现有创建事务与 dispatch Outbox。以租户、应用、内部用户、插件入口与 `client_message_id` 唯一识别一次提交，保存对原请求语义的摘要（区分首次省略会话的请求）。并发重发复用既有结果；同键不同输入返回冲突。先按原提交语义识别重放（包括省略、null、显式绑定），返回原 Job 及绑定，不重新读取会话当前选择。服务端验证传入会话的用户与应用归属。Publication、执行范围改变或请求新会话时按已有隔离规则创建新的 Session，响应告知实际会话；跨边界不拼接历史。仅在该边界允许连续会话，沿用 Session 串行及有界上下文。

### 4. 录制的准备、上传和查询

| 责任方 | 改动位置与交付 |
| --- | --- |
| 浏览器插件仓库 | 在 `extension/ui/control.ts` 及控制台界面增加共享预览、进度、恢复、当前录制和切换/解除；在 `extension/storage/database.ts` 增加按录制分页读取及上传回执。受信扩展页面负责投影与 HTTP 传输。沿用当前采集和本地 ZIP 导出入口。 |
| Enterprise Agent 渠道与存储 | Channel 实现上表的上传、对账及消息事务。PostgreSQL 记录录制归属、清单、分片回执、请求/操作索引、会话与 Job 的绑定；File Service 管理较大诊断明细的读写、配额与清理。 |
| Enterprise Agent 工具与执行 | 在现有固定的 `tool-mcp` 注册两个只读工具，沿用发布、角色授权、Job 工具快照与审计。Worker 传递本轮受信引用，Runtime 在需要证据时取命中项；回答沿用下文的 SSE 通道。 |

#### 插件从 IndexedDB 生成诊断数据

用户选定已封存的录制，插件按录制索引分页遍历 network 和 chunks 中的 ui.action，按需读取关联 blob。用户确认共享后，已采集的接口请求、响应和操作中的业务字段按实际名称、嵌套层级、类型和值传递。新增业务字段和首次出现的接口自动纳入，无需管理员登记路径模板或维护字段清单。发送前显示投影样例、请求数、操作数、采集缺口和预计上传字节。上传流程绕开 bundle()。整段视觉回放和截图属于独立的本地回放数据。

源端按请求、操作分别核对「已保存总数 = 可共享唯一行数 + 平台自身流量排除数」。每个可共享请求和操作各占一条索引。录制投影版本 2 将固定索引与开放的业务明细分开。请求、响应和操作的明细分别使用 `request_details`、`response_details` 和 `details`，`value` 保留业务结构，`omissions` 逐项说明省略位置和原因。路径模板为空时仍可保留该条记录的业务明细。时间邻近和实际观测的关联分别标识。两端独立核对唯一 ID 数、排序后的 ID 集摘要和源端计数。

插件在生成分片前处理凭据、原始业务消息和平台自身流量。密码、Cookie、访问令牌、模型密钥和数据库凭据的值不得出现在分片、日志或 Agent 输入中。无法安全拆分的原文标记为省略并保留请求或操作索引。服务端在持久化前独立复核，拒绝违规分片且不回显原值。

#### HTTP 传输、入库和恢复

用户只选应用。当前插件入口的执行范围是平台路由决定的项目，录制不按本地填写的 MES 环境名分区。共享范围由平台来源、当前内部用户、应用、活动部署与发布、插件连接和该项目共同确定。录制读取不会授予查询实际 MES 环境的权限，实际业务工具仍执行系统原有的环境授权检查。

一次上传指同一授权边界内同一本地录制、封存检查点和投影版本对应一个已提交的服务端版本。服务端由身份与路由确定租户、用户、应用、发布、Connector 及执行范围，按该边界和版本键去重。初始化重试不重建录制；同键清单摘要冲突时拒绝覆盖。插件按平台 Origin、账号和该范围保存非敏感回执与稳定键，重开后对照服务端已收分片。同一轮消息的 64 KiB 上限仅适用于提问信封，问题最多 4,000 字符。分片上传有独立的压缩字节、展开字节、行数、单录制及累计暂存配额，读取时实施限制。初始化清单也限制分片数量与字节数。达到配额明确报错；传输字节与 ZIP、解压体积分别统计。

平台校验固定索引的 schema、业务明细结构和内容安全边界，普通日志只记状态和计数。分片以序号、摘要幂等暂存，索引按录制版本与证据类型、ID 唯一；较大的业务明细按有界分片交 File Service 写 MinIO，索引只存内部明细引用。核验所有已确认分片、索引和对象后，持久事务才置为就绪。中断可在原版本续传或重试完成；部分写入对查询不可见。File Service 的幂等写和过期暂存回收覆盖对象成功、数据库提交失败的窗口。就绪时按平台内容保留策略固定到期时间；到期立即停止新读取，后台可重试地清除索引和明细。Job 沙箱回收与录制保留分别计时。

确认共享时保存非敏感清单、版本键、应用返回的 `scope_ref` 和一次上传的随机 `upload_attempt_id`，再发初始化。scope_ref 是服务端对租户、用户、应用发布、Connector 和执行范围的比对值，只作前置条件，当前权限另行复核。原清单恢复时若范围改变，返回 `409 scope_changed` 并要求重新选择和确认，避免旧录制被自动送入新范围。投影版本固定排序、NDJSON 编码、分片边界和分片摘要算法（SHA-256 作用于未压缩 UTF-8 字节），清单中的分片大小也以展开字节计。插件重开后照原清单生成缺片，核对摘要再发送；本地数据缺失或升级后无法复现时停止并提示原因。完成请求返回 `409 parts_missing` 时按缺片序号恢复；`409 manifest_conflict` 或摘要不符时停止，不能将同键异内容当作缺片。

初始化重复使用同一 attempt 查回当前进度。对已过期的未发布暂存返回 `410 upload_expired`，保留可识别旧尝试的最小回执。只有用户重新确认才可生成新的 upload_attempt_id；同版本仍在上传时返回同一有效上传，已就绪时返回原 recording_id。重新开始未发布暂存分配新 recording_id，迟到的旧 PUT 或 complete 不能写入新尝试。首次回执丢失、两个窗口和并发完成均受同一授权范围与封存版本唯一约束。已发布内容到期后的读取报告不可用，不能触发自动重传。

#### 连续提问和受权查询

消息受理时在同一事务内串行更新会话选择、分配消息顺序、固定 Job 的 `recording_id`（或空）与 dispatch Outbox。选择必须属于当前授权边界且已就绪；发布或执行范围变化产生新会话，不继承旧绑定。未就绪、已过期、无权绑定或缺少任一录制工具授权时，带录制的请求返回明确的安全状态，用户可解除绑定后纯文字提问。界面恢复时呈现当前录制。每条历史证据引用保留所属录制，切换后旧引用只能用于解释既有回答，不能作为新录制的观测结果。

普通追问走消息接口，跳过录制初始化、上传和完成接口。纯文字输入或引用录制时均沿用现有会话的有界历史与摘要。绑定的 Job 只获得本轮引用、覆盖概况及已授权工具说明；派发消息只携带现有标识。录制不进入任务附件清单，不自动物化为 Runtime 文件，不整段注入提示词。两个工具从受信 RUNNING Job 解析唯一录制并逐次复核用户、应用、授权范围、工具合同和版本可用性；模型不能指定其他录制或对象地址。工具返回的网页派生字段标为不可信证据，不能改变指令、权限或投递目标。

| 工具 | 输入与返回 |
| --- | --- |
| `search_recording` | 按请求/操作类型、相对时间窗、路径模板、方法、HTTP 状态、业务结果、操作类型或关联证据定位。PostgreSQL 按相对时间与稳定 ID 分页，返回有限索引行、证据 ID、关联依据、缺口和续页状态。游标绑定本轮范围、版本及筛选条件。 |
| `get_recording_evidence` | 按带录制归属的证据 ID 取一条操作或请求的业务明细和省略原因；需要较大明细时，经 File Service 读取命中分片并截取该条。返回字段级缺失/截断原因和关联引用。两工具均限制响应条数及字节，截断或未查全时显式标记。 |

例如首轮问「点保存为什么失败」，Agent 先查保存操作及邻近的请求，引用命中的请求 ID。追问「那条请求的业务码是什么」时只读该 ID 的明细。追问「把刚才结论写成一句话」可直接使用前序回答。服务端缺片时，插件可从本地已封存录制补传对应分片。源端未采到的内容标记缺失，必要时由用户重新录制并显式绑定新版本。平台到期或拒绝访问时不会自动从浏览器恢复内容。

### 5. 复用内部文本事件，向用户提供独立的回答流

仅对发布为插件原会话回复的 Job 启用 SDK partial messages。Runtime 按所属对话和内容块类型，依次提取主对话助手 text 块的 `text_delta`。工具前的说明及工具后的结论都是用户可见的 Markdown 正文，沿用同一次 Agent 执行。思考、工具参数与原始结果、子任务、系统和审计块均排除，来源不明时只发平台状态。[Agent SDK 流式输出](https://code.claude.com/docs/en/agent-sdk/streaming-output)

同一 attempt 的预览和成功消息使用同一份正文。保留原始换行和 Markdown 标记，独立助手消息间以空行分隔。以主对话的完整助手消息核对该消息的增量并构成持久全文，即使预览因预算提前结束，终态也保留先前说明及后续结论。只有 SDK 成功结果可用时才以该正文兜底。按消息和块的位置识别重复交付，不按文字相同与否删段。插件按游标拼接原文后渲染 Markdown，重开会话时用相同方式展示持久全文。

Runtime 小批合并增量，为工具、审计块和唯一终态预留现有协议的事件数与字节预算，预算紧张时停止预览并保留正式结果，不扩大协议上限。Worker 在现有 claim、digest、事件序号和工具合同校验后，将合格增量写入仅供原用户读取的短期 Job 回答记录，与 Worker 事件推进幂等提交。可用现有关系库按 Job 顺序读取，无须引入常驻推送服务。普通运行时间线继续省略文本内容。

| SSE 事件 | 插件行为 |
| --- | --- |
| `status` | 显示排队、分析中或重试中；无模型增量时如实显示等待状态。 |
| `answer_delta` | 对当前 attempt 追加新文本，仅应用未消费游标。 |
| `reset` | 新 attempt 开始时废弃旧预览，重新积累当前回答。 |
| `completed` | 在 Job 和助手消息成功提交后，使用权威最终正文整体替换草稿。 |
| `failed` | 对取消、超时或重试耗尽展示安全终态，清除未完成草稿，停止订阅。 |

短期记录以 Job、invocation 和源 sequence 去重，面向插件的游标在 Job 各 attempt 之间单调增加。重放相同 invocation 不产生新片；旧 Worker 失去所有权后不能继续写。客户端以最后实际渲染的游标恢复；丢失本地草稿或游标过期时读取该 Job 的快照或持久终态。断开订阅不取消 Job。终态后清理短期记录（默认 1 小时），删除与 Job 生命周期联动，持久历史只保留已提交消息。HTTP 代理对 SSE 路由关闭缓冲，设置心跳并在发数据前校验授权。

同一草稿与其游标一起推进。无匹配草稿、游标不可用或收到开流前的 `409 cursor_invalid` 时，经 `GET /jobs/{id}` 获取同一已提交位置的快照。快照包含 `job_id`、`state`、`attempt_id`、`through_cursor` 及对应的公开草稿（尚无文本时为空）；终态返回持久最终回答或安全失败。先整体替换本地状态，再从 through_cursor 严格向后重放并接上实时事件，覆盖读取快照与建立订阅之间的增量、reset 或终态。每个事件的 id 只在该 Job 内有效；使用十进制非负整数游标，0 表示尚未消费事件。切换 Job 时不得复用游标。终态后不再订阅。

SSE 响应头已发出后，到期或撤权通过停止数据并关闭连接生效。没有收到终态的 EOF 仅表示需要恢复；以当前身份读取 Job 快照或重新订阅，根据新 HTTP 响应处理认证、撤权、终态或网络重试。旧连接及旧尝试的迟到事件不得改变新草稿。

## Risks / Trade-offs

- **模型或网关聚合了增量。** 用目标部署验证长回答在模型仍生成后续片段时，插件已显示首段。仅收到终态时仍可展示最终结果，但该组合的流式验收保持未通过。
- **浏览器原始证据可能包含敏感值。** 本地预览与远程发送分别构造；用合成样例验证新增嵌套字段可读取、凭据省略和原始业务消息隔离。目标环境验收只记录时间、计数、状态和非敏感关联标识。
- **SDK 完整消息、断流或重试造成文本重复。** 完整消息用于核对最终结果；Worker 重放按源序号去重；浏览器始终用最终消息校正。
- **插件页面与 MES 共用浏览器。** 认证和联网限定在扩展受信上下文，内容脚本和网页消息不能自行发起诊断、指定平台或取得凭据；排除平台认证和 Agent API 自身流量。

## Migration Plan

先发布兼容现有渠道的录制表与索引、File Service 明细接口、录制工具合同、身份及流式接口，再开放配置并激活一个试点应用，最后在插件仓库接入该平台版本。回退时停用插件入口并终止其用户流，禁用新上传及绑定，已保存录制、Job 与消息按各自生命周期回收；在途执行按现有 Job 策略收敛。独立回归钉钉、Webhook 和旧 Runtime 协议。

## Open Questions

目标平台接入新业务字段无需配置字段映射。系统地址由用户首次选定，发行插件身份在构建时确定。目标部署的录制配额与分片大小通过大录制联调确定并公布。实际 SDK、代理和目标模型能否在工具调用后及时产生可展示的首段，须以真实链路验收。

## File Service 的录制授权

插件仍使用系统登录取得的业务凭据。平台复核当前用户、活动应用、录制及清单后，为单次分片写入签发短期授权。工具查询时先从运行中的 Job 及冻结工具解析可读证据，授权绑定 Job、录制版本和证据 ID。File Service 独立验证签名、角色、精确用途和资源摘要，在读写时复核状态；明细只返回命中的一行。录制使用独立对象前缀，用户端、模型和 Runtime 均看不到内部授权或对象位置。到期回收复用 File Service 的维护入口。
