## Why

MES 用户已经能在插件里复现问题并查看操作和请求，但要使用平台上的诊断 Agent，还需要离开现场、手工整理证据。同一问题往往需要连续核对某次操作、它附近的接口和返回结果。每轮 Job 结束会清理 Runtime 沙箱，因此录制需要独立于 Job 保存，让用户选一次录制就能持续追问。

## What Changes

- 在 Agent 渠道配置和业务应用编辑器中提供「浏览器插件」入口和「回复原插件会话」结果去向。一个应用可同时使用插件及现有渠道。
- 插件用户使用自己的平台身份，选择有权使用的活动业务应用。支持纯文字提问，也可主动选择一段已结束录制并绑定到会话，连续追问或重新打开时复用同一版本。
- 插件用户首次粘贴系统网址，用自己的系统账号登录，然后从本人获准使用且已启用插件入口的活动应用中选择。平台内置发行插件身份，自动识别请求来源。本期支持并验收现有内网 HTTP 平台。登录、共享录制、连续提问和回答续读均使用用户选择的 HTTP 地址。
- 插件在提问、上传或接收回答期间，凭仍有效的平台登录会话自动换取新的短期业务凭据。用户无需每 15 分钟输入密码。登录会话失效时提示重新登录，恢复后按原消息、已确认分片或回答游标继续。账号停用或业务权限已撤销时停止相应操作。
- 插件保留共享范围内每个请求、响应和操作的全部业务字段，新字段无需登记，核对平台自身流量的排除计数，预览覆盖范围，经用户确认后分片上传。同一授权范围内的同一录制版本只导入、建索引一次，断点续传只补缺片。原始 ZIP、回放和报文留在本机。
- 平台用 PostgreSQL 保存可查询索引，经 File Service 将较大的业务明细保存到 MinIO。每轮 Job 固定录制引用，Agent 可调用内置只读工具搜索接口或操作，再凭证据 ID 查看少量明细。插件追问只发送问题和会话引用，Runtime 无需反复接收整段录制。
- Runtime 将主对话的助手正文按生成顺序经 Worker 和 SSE 送回原会话，包括调用工具前后的文字。插件按 Markdown 展示，成功后从同一条持久助手消息恢复全文。
- 在插件现有控制台接入提问、预览、流式展示及重连。本提案负责平台实现与双方接口契约，插件客户端由浏览器插件仓库实施，端到端验收需要双方版本。

## Capabilities

### New Capabilities

无新增主规格领域。

### Modified Capabilities

- `identity-access` — 插件登录授权、短期凭据静默续期、重新登录及撤权。
- `agent-model` — 在 Agent 发布时校验并固定允许使用的插件连接。
- `business-application` — 插件触发器、原会话输出、发布校验和活动应用路由。
- `channel-conversation` — 录制上传、完整性对账、会话绑定与消息幂等。
- `builtin-tool-resource` — 录制搜索与按 ID 取证的授权、查询范围和有界返回。
- `task-file-workspace` — 录制明细的 File Service 存取、独立保留与到期清理。
- `execution-delivery` — 按 Job 固定录制引用、有界输入、回答增量与断线恢复。

## Impact

- 平台涉及 Agent 与应用配置界面、身份服务、Channel、Job、Python Runtime、Worker 和用户结果读取接口。沿用已发布 Agent、应用授权、Job 调度与既有模型接入。
- 当前应用的触发器枚举只包含钉钉和 Webhook；Runtime 协议已有 `assistant_text`，当前执行链在成功终态才发出最终答案。插件当前预览和导出本地证据，默认脱敏主要保护密码，远程提交必须另行排除凭据和原始业务消息。
- 外部依赖是 MES 证据采集插件的客户端接入和目标部署上的真实流式模型联调。首版不包含录制时持续上传、远程控制网页或在插件中确认外部写操作。
