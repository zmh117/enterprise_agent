## MODIFIED Requirements

### Requirement: Channel 在创建 Job 前解析活动业务应用
钉钉 Stream、受管 Webhook 和浏览器插件 SHALL 在 Job 创建前，以当前代码支持的 `local` deployment、Trigger 类型、Connector 和受信 routing key 解析活动业务应用。部署路由与用户业务 Environment/Base/Workshop 不是同一维度。命中后 MUST 使用不可变 Application Publication 的 Agent、Session、执行、文件和 Delivery 策略；与已固定事件 Agent 冲突或无活动匹配时失败关闭，不回退默认 Agent。

#### Scenario: 业务 Environment 与部署环境不同
- **WHEN** 消息 routing context 指向业务环境而控制面运行当前 local deployment 路由
- **THEN** 两者分别用于应用解析和受管数据范围校验，payload 不得更改 deployment

#### Scenario: 受理时固定的应用 Agent 与当前活动应用不一致
- **WHEN** Event 在受理时固定的 Application/Agent Publication 与分发时命中的活动应用不同
- **THEN** 阻止 Job 创建并记录配置冲突，不选择其中一个静默继续

#### Scenario: 未匹配或应用阻塞
- **WHEN** Resolver 返回 not_matched 或 blocked
- **THEN** 不创建 Job 或发布 Job 消息，通过已注册原渠道通知能力发送安全错误；通知失败独立记录，不回退运行 Agent

#### Scenario: 插件提问命中已停用或无权使用的入口
- **WHEN** 插件请求创建业务 Job，但服务端复核时入口已停用、应用未激活或当前用户无权使用
- **THEN** 返回安全错误，不创建 Job 或复用任意默认 Agent

## ADDED Requirements

### Requirement: 插件以幂等消息进入隔离的 Agent 会话

系统 SHALL 提供纯文字和文字引用已就绪录制两种输入。持久受理 MUST 原子建立本人所属的消息、Session、Job 和唯一 dispatch Outbox，返回实际会话和 Job 引用。客户端指定的用户、Agent、Publication、部署、工具或回调不能更改路由。系统 MUST 复用已有 Session 隔离、连续会话开关、上下文预算及输入顺序。同人、应用、连接及客户端消息 ID 的重放不得产生第二次执行。

#### Scenario: 第一次提问超时后并发重发
- **WHEN** 客户端没有拿到首次回执，以原 ID 和相同内容重提，原请求未带会话 ID
- **THEN** 重发得到同一会话和 Job；同键不同问题、录制绑定指令或目标会话返回冲突，不增建消息

#### Scenario: 追问在提交前或返回回执前凭据过期
- **WHEN** 原用户完成静默换证或重新登录，且原业务边界仍有效
- **THEN** 待提交或受理结果未知的问题 MUST 使用原 client_message_id、问题文本、会话与录制绑定指令提交。已受理则只返回原回执；已有回执直接恢复原 Job，不再发起一次提问

#### Scenario: 首问无回执就关闭控制台
- **WHEN** 首问已使用 client_message_id 发送，重开后既无正文也无 conversation_id，随后用户还要继续追问
- **THEN** 客户端 MUST 先按原账号、应用和消息 ID 查受理回执，命中便恢复原会话及 Job；暂未命中时不自动创建新消息。连续提问按受理回执确定顺序，无需等待前一 Job 完成

#### Scenario: 追问和发布切换
- **WHEN** 同一人向原插件会话追问且应用允许连续会话
- **THEN** 同一发布与执行范围内复用 Session 并按序运行；发布或范围变化时返回新的隔离会话，旧历史不带入。关闭连续会话时按单次上下文处理

#### Scenario: 身份来源
- **WHEN** 已通过插件授权的用户提交问题
- **THEN** 服务端以认证得到的内部用户作为请求人，无需创建虚构钉钉外部身份；该用户的工具身份和数据范围另按既有策略解析

### Requirement: 插件按已封存录制共享可核对的请求与操作索引

插件 SHALL 仅在用户预览并确认共享封存录制后发送。用户确认共享后，已采集的接口请求、响应和操作中的业务字段按实际名称、嵌套层级、类型和值传递。新增业务字段和首次出现的接口自动纳入，无需管理员登记路径模板或维护字段清单。插件 MUST 对排除平台自身流量后的每个已落库唯一 requestKey 和 ui.action 的 eventId 保留一行，核对源计数、可共享数、排除数和 ID 集摘要。插件在生成分片前处理凭据、原始业务消息和平台自身流量。密码、Cookie、访问令牌、模型密钥和数据库凭据的值不得出现在分片、日志或 Agent 输入中。无法安全拆分的原文标记为省略并保留请求或操作索引。服务端在持久化前独立复核，拒绝违规分片且不回显原值。录制字段 MUST 作为不可信数据处理，不得改变指令、授权或工具调用范围。

#### Scenario: 大量正常请求中存在业务失败与未知路径
- **WHEN** 同一录制含重复调用、HTTP 200 的业务失败、无响应正文或未登记路径的请求
- **THEN** 各次请求均可凭各自的 requestKey 查到，业务结果与 HTTP 状态分开，未登记接口中的新增业务字段按原结构可查，未采集、受保护或截断的值带原因；相邻操作只标为时间线索

#### Scenario: 敏感字段或超额上传
- **WHEN** 分片含未定义的协议信封字段、凭据、原始报文、非法编码，或超过压缩、解压、行数或存储配额
- **THEN** 服务端在确认分片或发布前拒绝，返回安全错误且不回显或记录原值；有效的小分片不能绕过整段录制及暂存配额

#### Scenario: 未选择录制
- **WHEN** 用户新开会话直接输入问题
- **THEN** 平台接受纯文字；插件不读取其他录制或自动传输数据

### Requirement: 同一授权范围内同一录制版本仅上传并发布一次

平台 MUST 为同一授权归属、本地封存版本及投影版本最多发布一个有效的就绪版本。发布前过期的暂存可在用户确认后重新开始。同键但清单内容变化 MUST 拒绝。插件 MUST 对保存的录制分批读取、稳定分片并支持断点续传。服务端 MUST 以序号和内容摘要确认分片，对照源端可共享唯一 ID 集摘要、请求和操作数量及可用明细进行核验；只有核验成功的版本可绑定和查询，已就绪版本不得覆盖。

#### Scenario: 回执丢失或两个窗口同时提交
- **WHEN** 同一分片或发布请求并发或重发，或插件重开后以原清单恢复
- **THEN** 已确认内容复用、只传缺片；已发布版本返回同一 recording_id，不重复建可见索引；同序号异内容拒绝

#### Scenario: 大录制在分片或完成请求途中凭据过期
- **WHEN** 传输跨过凭据有效期、回执未送达，或需要等待原用户重新登录
- **THEN** 插件暂停调度，服务端 MUST 在确认分片或发布版本前复核当前凭据。恢复后按原版本键和清单读取已提交进度，仅发送缺片，已发布则复用原版本。暂存已清理时明确提示重新上传，不报告续传成功

#### Scenario: 续传时范围变化或旧暂存已过期
- **WHEN** 插件用原 scope_ref、upload_attempt_id 与清单恢复，或重新开始后旧分片仍在途
- **THEN** 平台 MUST 在创建任何暂存前复核原范围，范围改变返回 scope_changed。已过期的暂存返回 upload_expired；须经用户确认才能以新 attempt 开始，旧 recording_id 的迟到写入被拒。已就绪的有效版本始终复用

#### Scenario: 分片或索引行缺失
- **WHEN** 完成时存在缺片、重复 ID、数量相同但 ID 集不符或所需明细未持久化
- **THEN** 版本保持不可查询，返回缺片序号或安全核对错误供重试；原采集报告的缺口可在传输完整时按原状态发布

### Requirement: 原插件会话按提交顺序绑定不可变录制版本

消息受理 MUST 在同一事务中校验归属和就绪状态、应用绑定指令并将解析出的唯一版本或空值固定到 Job。首次可显式选择录制，后续省略沿用会话当前版本，显式 null 解除。同一请求重放 MUST 先复核当前读取权再返回原绑定与回执；授权或发布边界产生的新 Session 不继承录制。绑定录制的 Job 必须具备本次诊断所需的两个已授权工具。

#### Scenario: 排队后切换录制并重试首轮提交
- **WHEN** 问题一在录制 A 下受理，问题二切换到 B，问题一的请求因回执丢失被重发
- **THEN** 两个 Job 分别固定 A 和 B，重放返回问题一的原回执；随后未指定录制的追问复用 B，旧证据引用保留来源

#### Scenario: 显式解除或超出保留期
- **WHEN** 用户解除录制后继续提问，或本轮试图继承已过期的录制
- **THEN** 解除后的 Job 可纯文字运行；继承失效时给出不可用状态，不静默切换版本或重传录制

### Requirement: 插件通过内网 HTTP 完成问答和断点恢复

插件和平台 SHALL 支持内网 HTTP 平台地址，包括 IP、域名和显式端口。应用选择、上传与恢复、消息提交、会话读取、SSE 订阅和断点续读 MUST 使用选定的协议和 Origin。

#### Scenario: 内网 HTTP 采集诊断与流式恢复
- **WHEN** 用户通过仅提供 HTTP 的局域网地址登录，上传所选录制、提交首问并在同一会话追问，在收到首段回答后断开并重连
- **THEN** 插件通过该 HTTP 地址按游标接收后续增量和最终答案，仍归属同一个 Job
