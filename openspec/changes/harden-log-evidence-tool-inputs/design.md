## Context

扫描器使用不区分大小写的字面匹配，但入参规范化遇到大小写重复词会整体拒绝。File bridge 仅返回通用中文文本及具体码；SDK 安全摘要保留了码，却没有写入事件顶层，后续 `normalize_tool_events` 因此使用 `runtime_tool_failed` 和瞬时失败分类。

## Goals / Non-Goals

目标：合理的重复词不再导致扫描失败；非法路径仍被拒绝但可纠正；扫描错误在普通运行记录可定位且不泄露输入。保留工具失败后 Agent 使用现有只读工具完成任务的能力。

非目标：自动补全或搜索文件路径，扩大扫描格式/授权/容量，给所有工具更换错误协议，修改 Job 成败定义，自动重跑现场任务或部署。

## Decisions

1. 保留原始数组最多 32 项、每项最多 128 字符、合计 4096 UTF-8 字节的校验，随后按 `casefold()` 去重并保留首次拼写及顺序。Schema 去掉词项的 `uniqueItems` 限制，补充参数说明；路径数组仍禁止重复。这样不会因容错扩大预算。
2. 不新增路径自动修复和复杂路径正则。工具及参数说明明确 POSIX `inputs/` 路径、LOG 扩展名及取自物化结果；后端仍以现有路径/精确物化身份检查为准，避免两套校验漂移。
3. 扫描错误的已知码使用代码拥有的固定中文安全提示和重试分类。File bridge、SDK 事件与终态工具投影复用该映射；只有已知扫描码能进入普通事件顶层。未知码保持通用安全回退，不透传动态异常文本。其他工具行为不变。
4. 参数、路径、身份/完整性及容量等确定性错误为 `NEVER`；只对明确读写 I/O 等瞬时错误保留 `TRANSIENT`。这不自动触发重试，也不强制让有失败工具的 Job 变成失败。
5. 规范化策略变化使用新 scanner version，派生 Schema hash 由当前声明自动计算。系统 Prompt 不变，不额外升级 Prompt 或 Runtime 协议。真实调用受当前冻结的物化权限约束，历史 Job/审计不回写。

## Risks / Trade-offs

- 错误信息泄露 → 固定码映射，不复制原始关键词、路径、日志或异常堆栈；加入恶意伪造错误码和消息的回归。
- 词项去重隐藏超限 → 原始数量和字节仍参与预算；超过上限仍失败。
- SDK 层提前校验导致提示不同 → 通过真实 SDK 内存 MCP 连接覆盖正常调用、大小写/完全重复词与非法路径。
- 本地测试不等于 Windows 现场恢复 → 记录合成验证与远端新 Job 验收边界，不宣称已部署。

## Migration Plan

无数据库迁移、不改变远端 File MCP 工具清单。部署时使用一致构建更新相关 Runtime/Worker 镜像并通过现有构建身份检查，以新 Job 验收；回滚使用上一完整构建，不修改旧审计或放宽契约校验。本轮仅完成代码和本地验证。
