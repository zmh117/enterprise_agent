# Design

## Context

`live-recorder.ts` 对所有文本和输入使用返回空串的 rrweb 遮蔽函数，额外排除了 iframe。它只发送节点增删，原地修改的文本会丢失。`shared/live-page.ts` 在内容脚本和后台分别重建只含结构的树，操作只保留动作、元素类型和节点编号。平台 `live_query.py` 可分页读回事件字节，但当前时间线摘要也只认识这几个动作字段。

## Goals / Non-Goals

本次交付以授权业务页的操作时间线和可读页面状态为准。像素级回放、截图、扩大站点权限及解密 MES 流量均超出本次范围。旧录制仍按其实际证据回答。

## Decisions

1. 在采集工单列表、表单、弹窗等可见区域时，保留有界文本与结构关系，沿用基线引用和节点编号。覆盖初始状态、纯文本变化、增删节点、可见性与控件状态变化；滚动区域中已渲染的业务行也在范围内。对未渲染的虚拟列表项、无法观察的子页面或超限材料记录覆盖边界。重用已有基线及增量通路，避免每次点击都复制整页。
2. 从实际事件路径定位最近的业务控件，从可见文字、原生 label 或 ARIA 命名关系提取名称；对表格或网格，使用当前行可见的业务标识和表头。输入和选择保留策略允许的实际确认值。区分“点击保存”和“保存成功”，旧值或结果只有在确有观测时才出现。对已有录制保留实际发生时间、页签及文档绑定。
3. 录制启动时把文本遮蔽、敏感选择器和输入字段策略传给持续录制器，后台按固定字段集合验证。凭据、密码、Cookie、验证码和原始消息区域须在读取值、汇总父元素文字和发送 rrweb 内容等入口统一排除。敏感子树不能经父元素、ARIA 引用、行摘要或属性绕过遮蔽。离线模式的 `redaction.ts` 只识别部分密码字段，不能直接作为上传端的唯一防线。对已运行的旧版录制缺少有效策略时保持原有保护，更新后新开录制使用明确策略。
4. 操作概览提供短小的页面和目标信息；已有详情接口分页返回同一事件及对应基线。查询沿用现有授权和大小预算，记录缺失、脱敏或截断原因。Agent 将采集内容当作页面数据，引用观测事件；只有轮询或时段覆盖不完整时说明实际看到的记录。

## Risks / Trade-offs

- 表格虚拟化、嵌套图标、自定义下拉、隐藏转显示及 SPA 复用节点会导致误认。用两个同名按钮、动态表格和变化的页面标题验证事件发生时记录的上下文。
- 可见业务内容会增加基线体积。遵循现有预算、队列和分片规则，受限时显式标记不完整；使用合成页面验证容量边界。
- 可见字符串可能同时含业务信息和敏感信息。采集策略在入队前生效，对无法安全分离的敏感区域整体省略。开发测试使用虚构数据，现场验收保留结论与覆盖状态。
