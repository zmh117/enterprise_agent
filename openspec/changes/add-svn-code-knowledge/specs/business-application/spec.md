## ADDED Requirements

### Requirement: 应用必须按来源工具族装配代码知识能力
系统 SHALL 将代码知识目录与当前查询作为成套依赖，时间轴工具依赖前两者且可额外选配；ONES 目录/检索继续依赖 ONES 详情工具。Agent 和 Application Publication MUST 冻结精确工具 identifier/schema hash，Job MUST 使用既有工具交集与当前角色知识库授权。系统 MUST 按具体工具族和来源类型校验，不因使用同一个 `knowledge-mcp` Server 而强制代码知识用户具备 ONES 身份，也不得取消实际 ONES 调用的个人可读性校验。

#### Scenario: 发布纯代码知识应用
- **WHEN** 应用选择代码知识目录、当前查询及可选时间轴工具
- **THEN** 不要求装配 ONES 详情或用户 ONES 身份，但必须满足代码知识资源、角色范围和固定工具合同

#### Scenario: 工具组合不完整
- **WHEN** 只选择代码当前查询而没有目录，或只选择时间轴而缺少其依赖
- **THEN** 保存/发布校验返回明确组合错误，不把不完整组合交给 Runtime

#### Scenario: 同一应用同时提供两类知识
- **WHEN** 应用同时装配 ONES 与代码知识工具
- **THEN** 分别校验两套依赖和来源，代码查询不触发无关 ONES 身份要求，ONES 调用仍执行本人可读性检查

#### Scenario: 新工具发布后旧 Job 重试
- **WHEN** 平台新增代码知识 Tool 或其 schema 改变后旧 Job 重试
- **THEN** 旧 Job 继续受原冻结合同约束，不能自动获得新 Tool 或新知识库范围

### Requirement: 代码知识内容更新不得改变应用授权或混淆运行事实
已启用来源的自动同步 SHALL 只更新其绑定范围内的当前内容，不要求每次提交重新发布 Agent/Application，也不得修改工具合同或角色权限。应用的代码知识使用说明 SHALL 要求每个新的当前事实问题执行新鲜度检查，并区分主干代码行为、代码结构和真实运行状态；更新失败时不得从旧对话或旧工具结果推断最新行为。

#### Scenario: 正常提交完成知识更新
- **WHEN** 后台在既有来源绑定内完成一个提交的内容激活
- **THEN** 下一次有权查询使用新鲜度合同读取新内容，无需重新发布应用且权限集合保持原值

#### Scenario: 用户询问实际工单状态
- **WHEN** 用户的问题需要具体业务对象当前数据，而应用只有代码知识工具
- **THEN** 应用仅解释规则及数据缺口，不把代码知识当成对象当前状态；读取实际数据仍需已有业务工具的独立授权
