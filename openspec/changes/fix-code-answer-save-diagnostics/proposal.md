## Why

拆批问答已取得源码读取证据，但保存工具失败后只留下 runtime_tool_failed，最终仅生成未核验问答记录，代码答案与向量集合仍为空。需要使失败原因可诊断、可纠正，并验证受控保存到增量索引的完整链路。

## What Changes

- 保留知识工具失败的白名单错误码、固定安全说明和重试分类，覆盖 Runtime 本地校验、源码授权结束及 MCP 返回失败；不记录业务正文、凭据或任意异常字符串。
- 修复长时间源码分析期间知识 Principal 过期，复用现有受控续期链保持原 Job 会话有效，不延长任务截止或放宽身份有效期。
- 对保存参数错误提供有界、无值的参数提示，修复复现出的保存阻断；证据不足仍不进入确定答案索引。
- 更新代码查询 Skill，按具体错误进行有界纠正，明确保存成功与索引就绪的区别。
- 测试通过后更新本机服务与 assist03，使用原拆批问题核验正式答案、索引任务与 Qdrant 数量。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `execution-delivery`: 知识工具安全失败分类不得在 SDK 事件归一化和审计中丢失。
- `builtin-tool-resource`: 代码答案保存失败须给出可处理的安全原因，参数纠正不放宽授权和证据准入。

## Impact

影响知识 MCP Runtime 桥、工具事件安全摘要、代码答案保存流程及 Skill。复用现有 PostgreSQL、Qdrant 和索引 Worker，不新增服务，不把普通聊天记录直接转换为确定答案，不追补历史未知错误码。
