## Context

历史任务已获得 9 条有效 Read 证据，knowledge_save_code_answer 在 Runtime 中失败，MCP 服务没有该调用记录；普通工具事件仅保留 available 和通用错误。原始参数与业务正文按安全策略不落审计，不能从历史记录猜具体失败原因。

继续核对身份审计确认直接原因：knowledge-mcp 凭证于 10:44:24 签发、10:49:24 到期，10:49:35 的校验拒绝为 principal_token_expired。原实现只在知识 MCP 调用在途时续期，长时间原生源码读取期间没有续期。

新模型复测另确认：源码分析把已经完成的搜索 receipt 的 360 秒请求截止误作后续多调用分析截止。Job 仍有效时，分析授权提前失效，源码授权客户端又把具体失效原因折叠为 CODE_SOURCE_GRANT_DENIED。

## Goals / Non-Goals

**Goals:** 复现失败，保留安全可处理错误，完成经证据验证的保存及索引验证。

**Non-Goals:** 不放开原始正文审计，不自动将 unverified/partial 升级，不直接补写答案或向量，不复活已结束任务的源码授权。

## Decisions

- 在知识工具边界维护固定错误分类；SDK 文本/结构化响应只提取代码白名单和固定参数位置，不透传服务返回的任意 message/details。事件归一化和模型收到的安全说明使用相同分类。
- Runtime 在已连接的知识 MCP 会话内每 30 秒发送固定 ping，复用在途 Principal 续期和 continuation 响应头；服务复核当前 RUNNING Job、原身份、授权、冻结合同和原截止。与业务调用共用串行锁，长业务调用仍由在途续期负责。ping 不读取业务资料、不生成工具调用次数、不延长 Job 截止；关闭或取消后停止并回收。续期失败关闭后续知识调用，不凭过期票据恢复授权，不延长 JWT 有效期。
- 保存前完成结构校验，对缺字段/错误类型给出受控 schema 路径，避免为无效请求停止源码读取。模型只能据实际证据纠正，不自动改写问题、关键未知项或证据 ID。
- 搜索 receipt 只证明前置检索的身份与版本，后续源码分析绑定原 Runtime invocation 的 execution_deadline_at；继续逐次验证当前任务、租约、授权和资源配置，不延长原任务预算。源码授权端点和客户端仅保留允许公开的固定失败代码，不传异常正文。
- 原保存合同仍校验同 Job、同环境、SVN、读取占用、实际 Read 证据及幂等键。成功提交 PG 后才形成增量索引工作；失败必须在普通工具时间线保留原因，但不伪造服务已执行的 MCP 审计。
- 用真实新 Job 复现（提示要求安全错误码），同时以合成边界测试固定诊断行为。根据复现结果补充具体保存修复及测试；不能用通用错误推断根因。
- 通过相关检查后更新服务及 assist03 发布；重新问同一拆批问题，检查保存、问答引用、索引任务及 Qdrant 点数。旧失败记录保持原事实。

## Risks / Trade-offs

- 错误对象含用户内容 → 只允许固定代码/说明和 schema 拥有的字段名，未知错误安全降级。
- 保存时源码读取已停但请求失败 → 保留原分析和幂等语义，不允许新读或盲目重跑。
- 真实分析存在关键未知 → 允许 partial，不能为了向量数达标绕过质量准入；另记实际验收边界。
