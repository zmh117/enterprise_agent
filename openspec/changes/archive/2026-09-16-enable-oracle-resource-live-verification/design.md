## Context

Oracle 验证器默认返回 BLOCKED；API 负责管理权限和验证证据入库，tool-mcp 才具有 19c Thick 客户端。现有服务共享受保护数据库与平台主密钥。用户已批准接通真实验证并细分失败，未批准放宽版本、只读账号、字符集或镜像隔离规则。

## Goals / Non-Goals

目标：Web 技术测试实际访问指定 Oracle 草稿；可发布结果与当前草稿一致；失败能定位类别且不泄露秘密。

非目标：新增 Agent 工具、自动发布、自动改配置、安装或下载授权客户端、迁移数据、放宽到其他 Oracle 版本、在 API 安装客户端。

## Decisions

1. API 使用独立 Oracle 验证委派接口，不改变通用本地 Provider 探针签名。API 保留管理员授权、草稿快照及验证结果入库责任。
2. tool-mcp 增加固定私有 POST 入口，不加入 MCP manifest。请求为短时签名票据，绑定资源编码/ID、草稿 ID/版本/hash、操作人及 Provider 契约；仅传标识，不传密码、Secret reference、连接内容或任意 SQL。服务重新检查管理员权限、身份状态及草稿一致性，自行解析凭据。
3. 从现有主密钥按独立用途派生签名密钥，请求/响应使用不同 audience，结果签名并绑定同一请求摘要。验证票据有效期、禁止重定向、限制管理目标主机、请求体/响应体大小；请求 nonce 进程内消费一次并有容量上限。共享密钥只存在现有受信服务内，不下发 Agent。
4. 每进程限制并发探针数量；连接使用受控 CONNECT_TIMEOUT、TRANSPORT_CONNECT_TIMEOUT 和 RETRY_COUNT=0，查询沿用 call_timeout。HTTP 超时或任何协议异常均失败关闭，不自动重试连接。
5. 探针失败仅返回固定中文说明、安全代码与有界检查字段。客户端/服务不可用为 BLOCKED；网络、认证、服务名/SID、数据库版本、字符集、只读权限问题为 FAILED，未知异常不输出原文。通过结果必须具有真实连接、Thick、11.2.0.4 及只读会话等检查事实。
6. 不修改其他 Provider，也不在构造函数增加一个用户可用的“跳过验收”开关。当前草稿发布仍必须具备匹配的 PASSED 验证事实。

## Risks / Trade-offs

- 另一环境仍可能缺少客户端或数据库授权 → 返回真实类别，附部署检查步骤；不把本地测试当作真实验收。
- 主密钥不同或网络错误 → 委派拒绝或 BLOCKED，数据库密码不跨服务传输。
- 进程重启/多副本无法共享 nonce 消费记录 → 票据短时且只执行固定只读探针，草稿一致性、管理权限与容量限制每次重验；不将该机制用于 mutation。
- 验证期间草稿变化或资源停用 → API 入库前重新检查身份和草稿；拒绝旧结果。

## Migration Plan

无数据库迁移。构建 tool-mcp 时由操作者按许可放入匹配架构的 Instant Client 19c；重建 tool-mcp 与 api-server 后在 Web 重新技术测试。回滚仅恢复旧镜像，已有资源和审计保留。

## Open Questions

实施无阻塞决策。另一环境的真实 Oracle 验收需要用户部署并再次执行技术测试。
