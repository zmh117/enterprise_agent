## Context

钉钉 Stream 消息进入系统后，会先规范化并持久化渠道事件，再解析 `provider + tenant_code + external_subject_id` 对应的内部用户。未知身份、已停用或已解绑身份、所属用户已停用时，入口按 fail-closed 规则返回“你的钉钉账号尚未获得授权，请联系管理员”，不创建 Agent Job。现有人员管理可以创建用户并管理钉钉身份，但管理员必须事先知道 `senderStaffId`，无法从真实消息入口发现待绑定人员。

钉钉实际事件可提供 `senderStaffId`、`senderNick`、`conversationType`、`conversationId`、`robotCode` 和 `createAt`。群名称并不可靠，因此界面必须以 `conversationId` 作为群标识。原始渠道事件还可能包含正文、附件访问材料、`sessionWebhook` 或其它不应向管理端传播的字段，不能直接作为列表查询模型。

本变更跨越渠道入口、身份解析、数据库投影、管理 API、人员管理和前端导航。它必须继续满足以下约束：

- 未绑定身份不能创建 Agent Job、发布 Job 消息、调用模型或 API Capability；
- 当前 Agent 及其工具仍保持只读诊断边界；
- 管理端用户可见文案和错误使用简体中文；
- 不新增容器，不改变一个固定 `dingtalk-runtime` 管理多个 Stream 连接的运行架构；
- 不在日志、审计、API 或页面暴露 Secret、Token、模型 API Key、原始事件或附件下载材料；
- 现有外部身份唯一归属和软解绑语义保持有效。

## Goals / Non-Goals

**Goals:**

- 发现部署后新收到的未绑定钉钉私聊和群聊用户，并按企业租户与用户 ID 聚合。
- 为管理员提供可搜索、可筛选、可轮询的安全列表和最近消息上下文。
- 将候选人可靠地衔接到现有人员创建、人员详情和钉钉身份绑定/恢复流程。
- 保证候选绑定只使用服务端重新解析的可信身份字段，绑定或恢复后立即从列表消失。
- 对候选消息实施数量、长度、类型和保留期上限，同时保持原始渠道审计数据独立。
- 通过幂等投影、并发版本检查、RBAC、CSRF 和审计保证真实运行链路安全。

**Non-Goals:**

- 不允许管理员从管理端向钉钉用户或群发送消息。
- 不自动创建系统用户，不按昵称、手机号、邮箱或相似度自动匹配人员。
- 不回填部署前的历史渠道事件，不回放绑定前被拒绝的消息。
- 不提供忽略、人工删除、批量绑定、跨用户强制转移或身份冲突治理中心。
- 不预览、下载、解析图片、文件、音频、视频、DOCX、XLSX、PPTX 或 Markdown。
- 不新增 WebSocket/SSE、权限项、功能开关、运行容器、Agent 工具或 API Capability。

## Decisions

### 1. 在身份拒绝分支生成独立的安全投影

只有已通过来源认证、规范化和渠道事件持久化，并明确被身份解析归类为“从未绑定”“身份停用/已解绑”或“所属用户停用”的钉钉消息，才能生成发现记录。格式错误、连接器认证失败、非钉钉事件、无 `senderStaffId` 的事件和其它授权失败不得进入发现列表。

发现投影与入口拒绝结果在同一个数据库工作单元内提交；随后才向 Runtime 返回既有的未授权结果。重复投递或在提交边界重试时，系统以来源 `channel_ingress_event` ID 幂等补齐/返回投影，不得增加第二条候选消息，也不得创建 Job 或 Outbox Job 消息。投影失败时入口保持 fail-closed，并返回可重试的安全错误分类，避免出现已确认但永远不可发现的消息。

选择独立投影而不是管理 API 读取 `normalized_event_json`，是为了在写入边界完成字段白名单、截断、附件降级和幂等控制，并让查询不接触原始 payload。

### 2. 使用候选聚合表和有界消息表

新增两个投影表：

```text
dingtalk_identity_candidate
  id
  tenant_code
  external_subject_id
  display_name
  first_seen_at
  last_seen_at
  observation_count
  revision
  created_at
  updated_at
  UNIQUE (tenant_code, external_subject_id)

dingtalk_identity_candidate_message
  id
  candidate_id
  source_ingress_event_id
  connector_id
  robot_code
  conversation_type
  conversation_id
  message_kind
  safe_text
  text_truncated
  attachment_type
  attachment_name
  attachment_size
  occurred_at
  received_at
  created_at
  UNIQUE (source_ingress_event_id)
```

候选键不包含 connector、机器人或会话，因此同一企业内同一 `senderStaffId` 经多个机器人、私聊和群聊发来的消息合并为一个候选人。不同租户的相同用户 ID 保持隔离。

每次幂等写入后只保留该候选最近 20 条消息，按服务端 `received_at` 和稳定 ID 决定保留顺序。`observation_count` 可累计真实幂等观察次数，不因消息裁剪回退。列表中的群 ID、机器人和会话类型从保留消息中去重汇总，避免无界数组字段。

### 3. 区分可信接收时间和钉钉展示时间

消息界面优先展示经过格式校验的钉钉 `createAt`，缺失或无效时使用服务端 `received_at`。候选排序、30 天活动窗口和清理依据服务端 `received_at`，避免外部时间戳过旧、过新或乱序导致候选被错误隐藏、永久保留或置顶。

列表使用 `(last_seen_at, id)` 的稳定降序游标分页。名称、用户 ID、群 ID、机器人搜索以及“全部/私聊/群聊/两者”筛选均由服务端执行，徽标和列表复用同一“当前可见候选”条件。

### 4. 在写入时把消息降级为安全、有限的展示模型

文本和 Markdown 消息只保存纯文本摘要，最多 1,000 个 Unicode 字符；超出后保存截断标志，由界面显示明确的“内容已截断”。前端不得将其作为 HTML 或可执行 Markdown 渲染。

图片、文件、音频、视频只保存经过白名单和长度/数值上限校验的消息类型、附件名称和大小；不保存或返回下载码、下载 URL、临时 URL、二进制内容、`sessionWebhook` 或原始嵌套对象。不支持的消息只保存安全类型说明。

日志和审计不得记录 `safe_text` 或原始消息正文。审计仅记录操作者、候选 ID、目标用户 ID、动作、结果和稳定安全错误码。

### 5. 查询时实时核对外部身份和用户状态

候选投影不作为身份真相来源。每次列表、详情和计数查询都以 `tenant_code + external_subject_id` 关联当前 `user_external_identity` 和 `app_user`：

- 没有历史身份记录：状态为“待绑定”，允许选择已启用自然人用户或新建人员后绑定；
- 存在停用、已解绑身份或停用用户：状态为“需恢复”，显示原人员和具体状态，只允许前往原人员详情处理；
- 身份和所属用户均已启用：不返回该候选。

该实时关联保证绑定或恢复事务提交后，候选无需等待投影消费或轮询清理即可从下一次查询和徽标计数消失。恢复操作不由发现模块自动启用用户或身份，管理员必须在原人员详情中显式完成适用的启用动作。

### 6. 使用候选 ID 驱动可信绑定，不接受客户端身份声明

新增管理接口：

```text
GET  /api/admin/dingtalk-identity-candidates
GET  /api/admin/dingtalk-identity-candidates/count
GET  /api/admin/dingtalk-identity-candidates/{candidateId}
POST /api/admin/dingtalk-identity-candidates/{candidateId}/bind
```

绑定请求只允许提交候选 ID、目标用户 ID、候选和目标用户的期望版本。服务端锁定候选、重新读取其租户与用户 ID、解析当前可信 Connector，并再次检查候选仍未绑定、目标是已启用自然人账号且版本未过期，然后复用现有外部身份应用服务完成绑定。客户端、URL、路由状态或隐藏字段中的 tenant、connector、`senderStaffId`、昵称都不能覆盖服务端值。

如果同一租户可由多个 Connector 接收消息，绑定使用候选最近一次有效消息关联的当前启用 Connector；若该 Connector 已停用或归属不一致，服务端返回中文可操作错误，要求管理员刷新或修复渠道配置，不猜测替代 Connector。

“新建人员并继续绑定”先调用现有创建人员接口，再调用候选绑定接口。这是两个独立、受审计的操作：若第二步失败，已创建人员保留，界面停留在绑定上下文并允许重试，不秘密删除或回滚人员。

### 7. 前端复用人员管理，不建设第二套用户编辑器

导航结构调整为：

```text
用户与外部身份
├── 人员管理        -> /users
└── 未绑定钉钉用户  -> /users/dingtalk-discovery
```

发现页面统一展示私聊和群聊候选，支持筛选、搜索、分页、展开最近消息、手动刷新和“去绑定”。“去绑定”只携带内部候选 ID 进入 `/users` 选择上下文；选择人员或新建人员后进入其详情，并自动打开现有钉钉绑定面板。面板显示服务端加载的企业、Connector、用户 ID 和昵称，只读不可编辑。

绑定成功后返回发现列表，显示中文成功提示并刷新列表与徽标；失败时保留选中的人员和候选上下文，显示映射后的中文错误。历史身份候选只显示“前往原人员恢复”，不出现人员选择器。

### 8. 使用有界轮询和数据库清理，不新增实时基础设施

发现页在浏览器前台每 15 秒刷新，侧边徽标每 30 秒刷新；页面不可见时暂停定时请求，恢复可见时立即刷新。绑定/恢复成功后主动使列表、详情和计数 Query 失效。徽标显示不同候选人数，超过 99 显示 `99+`。

后台通过现有服务内调度/worker 周期性删除 `last_seen_at` 早于 30 天的候选投影及其投影消息，不新增容器。删除只作用于发现投影，不删除 `channel_ingress_event`、审计、Agent Job 或投递记录。第一版 30 天为集中策略常量并预留平台配置接入点，不新增管理页面配置。

选择轮询而不是 WebSocket/SSE，是因为该页面不是实时聊天工具，15/30 秒延迟可接受，也能避免为一个低频管理列表引入新的连接和鉴权生命周期。

### 9. 复用统一管理安全边界

候选列表、详情、计数和绑定均要求已认证管理 Session 与 `identity:manage`；写请求额外要求 CSRF、乐观并发和现有审计。没有权限的请求不得通过计数、搜索结果或错误差异泄露候选是否存在。

API 响应使用专用 DTO 白名单，不复用渠道事件 ORM 序列化。所有用户可见错误映射为中文；内部日志保留稳定英文 `error_code` 和追踪 ID，但不记录消息正文或任何凭据。

## Risks / Trade-offs

- [另一个已完成 change 的用户/身份规格尚未归档] → 本 change 用独立新能力描述发现及可信绑定衔接，不复制或重定义完整人员管理能力；实施前保持依赖代码和接口兼容。
- [入口投影写入增加消息处理事务成本] → 仅在明确的钉钉身份拒绝分支执行，使用唯一索引、批量裁剪和必要索引；性能测试覆盖突发未知用户与重复投递。
- [同一候选来自多个 Connector] → 聚合身份仍按租户和用户 ID，消息保留 Connector/机器人来源；绑定时重新验证最近有效 Connector，失效时拒绝而非猜测。
- [昵称和消息内容由外部用户控制] → 限长、纯文本渲染、禁止 HTML/Markdown 执行，并在日志与审计中排除正文。
- [两步“创建人员再绑定”可能留下未绑定人员] → 保留人员以保证审计和数据安全，界面明确提示绑定失败并提供重试，不执行隐式删除。
- [轮询期间短暂显示过期数据] → 所有查询实时过滤 30 天窗口与当前身份状态；绑定成功主动刷新缓存。
- [清理任务中断导致投影增长] → 查询仍按 30 天过滤，清理具备幂等批次、指标和安全日志，恢复后可继续执行。
- [历史身份恢复规则可能让管理员误以为可以转绑] → API 返回明确的“原人员/需恢复”状态，界面不提供目标人员选择，服务端也拒绝候选绑定。

## Migration Plan

1. 新增投影表、唯一约束、查询索引和回滚安全的数据库迁移；迁移不读取或转换历史渠道事件。
2. 实现后端领域/应用服务、入口幂等投影和只读查询 API，保持前端菜单隐藏；完成单元、集成、权限、并发、幂等、敏感信息和保留期测试。
3. 实现候选可信绑定接口和历史身份分类，验证创建人员后绑定失败的保留语义，以及绑定/恢复后查询立即消失。
4. 实现前端导航、列表、筛选、消息展开、徽标、轮询和人员管理衔接，完成前端测试和真实浏览器链路验证。
5. 重建受影响容器，在 local 环境分别发送新的钉钉私聊与群聊消息，逐段验证 Runtime → Inbox → 渠道事件 → 身份拒绝 → 候选投影 → 管理页面 → 绑定/恢复 → 后续新消息创建 Job → Worker → Delivery；确认旧消息未回放。
6. 检查 API、数据库投影、应用日志、审计和浏览器状态，确认没有 Secret、Token、模型 API Key、原始 payload、`sessionWebhook`、附件下载材料或未截断正文。

回滚时先隐藏新菜单并停止候选查询/绑定接口，再回滚入口投影钩子。投影表可保留为不可访问数据或在确认无需恢复后通过单独迁移删除；不得删除原始渠道事件、审计、现有外部身份或已创建人员。因为没有历史回填和消息回放，回滚不影响既有 Agent 链路。

## Open Questions

无。第一版固定采用“仅部署后新消息、30 天候选窗口、每人 20 条消息、文本 1,000 字、附件仅元数据、无回复/忽略/删除、15/30 秒轮询、复用 `identity:manage`”的范围。
