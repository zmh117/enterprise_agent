## Why

钉钉私聊或群聊消息来自尚未绑定的用户时，系统会按安全边界拒绝创建 Agent Job，但管理员目前无法在管理端看到是谁、从哪个机器人和会话发来了什么消息，只能依赖用户主动提供 `senderStaffId` 后再手工绑定。需要把这类已被系统安全接收但未获授权的消息转成受控、短期、可操作的身份发现列表，让管理员在现有“用户与外部身份”工作区完成绑定，同时继续保持未知用户不能触发 Agent、不能自动创建系统用户。

## What Changes

- 将侧边导航调整为“用户与外部身份”分组，保留 `/users` 作为“人员管理”，新增“未绑定钉钉用户”页面 `/users/dingtalk-discovery`。
- 在钉钉消息因身份未绑定或历史身份不可用而被拒绝时，写入独立、安全、有界的发现投影；不扫描部署前历史事件，不创建 Agent Job，不调用模型或 API Capability。
- 按“钉钉企业租户 + `senderStaffId`”聚合候选人，展示最近消息、时间、钉钉用户名、用户 ID、群 ID、所属机器人，并支持私聊/群聊类型、名称、用户 ID、群 ID、机器人筛选。
- 每个候选人仅保留最近 20 条发现消息；消息文本最多 1,000 字并明确标记截断，附件仅保存安全的类型、名称、大小摘要，不提供预览、下载或内容提取。
- 候选人以最近消息时间计算 30 天展示期；页面每 15 秒轮询，侧边菜单徽标每 30 秒轮询并按候选人数显示至 `99+`，同时提供手动刷新。
- 从发现列表“去绑定”时仅传递内部候选 ID；服务端重新解析受信任的租户、连接器和钉钉用户标识，并复用现有人员管理和外部身份绑定能力，不信任 URL 或客户端提交的钉钉身份字段。
- 从未绑定过的候选人可选择已启用自然人账号或新建人员后继续绑定；历史上已停用或解绑的身份只能返回原人员恢复，不允许转绑其他人员。
- 绑定或恢复成功后候选人立即从列表消失，仅后续新消息进入现有 Agent 链路，不回放发现期间的消息；失败时保留当前操作上下文并显示中文错误。
- 读取发现列表和执行绑定继续使用现有 `identity:manage` 权限、Session、CSRF、乐观并发与安全审计，不新增权限模型、回复入口、忽略按钮或人工删除功能。

## Capabilities

### New Capabilities

- `unbound-dingtalk-identity-discovery`: 定义未绑定钉钉私聊/群聊身份的安全发现投影、聚合列表、筛选与轮询、人员管理衔接、可信绑定/恢复、即时消失、保留期和敏感信息边界。

### Modified Capabilities

- `channel-ingress-contract`: 扩展渠道入口拒绝处理，使钉钉事件在明确因身份未绑定或历史身份不可用而拒绝时形成幂等的安全发现记录，同时仍不得创建 Agent Job 或发布 RabbitMQ Job 消息。

## Impact

- 数据库：新增钉钉身份候选聚合和候选消息投影表，使用来源渠道事件唯一键保证幂等；不改动原始渠道事件、Agent Job 和审计数据的保留规则。
- 后端：扩展钉钉入口拒绝分支、发现投影应用服务、清理任务和 `/api/admin` 查询/计数/可信绑定接口；查询时实时关联现有外部身份状态，保证绑定或恢复后立即隐藏。
- 前端：调整“用户与外部身份”导航层级，新增发现列表、详情展开、筛选、轮询和“去绑定”衔接；复用现有人员创建、用户详情和钉钉绑定界面。
- 安全：发现 API 不返回原始事件、`sessionWebhook`、下载凭据、临时 URL、Secret、Token 或完整附件内容；前端仅以纯文本展示安全摘要。
- 运行时：继续使用现有 `api-server`、`dingtalk-runtime`、`agent-worker`、`channel-dispatch-worker`、PostgreSQL 和 RabbitMQ，不新增容器、不开放写操作型 Agent 能力。
