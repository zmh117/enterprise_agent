## Why

同一业务目标下存在云、边等多个数据库时，需要可配置的资源角色参与唯一定位。现有 placement 仅允许 cloud/edge，且管理页面没有完整配置入口，资源名称无法消除解析歧义。

## What Changes

- 管理端数据库和 Redis 资源增加“资源角色”：初始为空，可输入新值并复用历史值；Loki 保持不支持该维度。
- 扩展现有 placement 字段语义为资源角色，保留字段名与旧 cloud/edge 值兼容，不并存另一套选择字段，不增加 RBAC 授权维度。
- 角色纳入 Draft / Revision 与内容哈希，修改后重新验证发布才影响解析；旧资源可从发布版本建草稿补齐。
- 目录、工具参数、精确解析、审计和提示同步支持角色，多候选不得自动猜测。
- 新增数据库迁移；保留旧发布的角色事实与哈希，旧草稿需保存及重新验证后发布。工具输入契约更新后需重新发布 Agent / 应用，不修改旧 Job 快照。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `builtin-tool-resource`：资源角色参与调用唯一定位，支持自定义值及旧 placement 兼容。
- `platform-operations`：管理端角色输入、历史值复用及角色的草稿验证发布生命周期。

## Impact

涉及工具资源 UI/API、资源存储、迁移、MCP 工具契约与解析、提示及测试。不自动修改现场数据库、资源、授权或发布应用；不覆盖工作区既有知识导入改动。
