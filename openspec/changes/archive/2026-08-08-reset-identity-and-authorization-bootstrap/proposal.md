## Why

新的“角色与授权”模型落地后，系统仍保留旧人员、外部身份、服务账号、角色成员和兼容授权事实；继续混用会让授权来源难以解释，也会使严格模式无法成为唯一判定口径。需要一个独立、可审计且可恢复的初始化变更，在明确的维护窗口内清空旧身份与授权状态，创建唯一的新平台管理员，并把系统切换到严格角色授权。

## What Changes

- **BREAKING**：在显式确认、备份验证和维护锁保护下，删除全部旧人员账号、服务账号、外部身份绑定、登录会话、角色成员关系、旧角色与直接授权事实；业务应用、Agent Profile/Publication、渠道、Connector、运行记录、投递记录和审计历史不随之删除。
- 对引用被删除服务账号或用户的触发器、投递绑定等运行配置进行依赖扫描；无法继续安全运行的配置必须原子停用并生成中文重配清单，不允许留下悬空主体或隐式匿名回退。
- 重新创建且仅创建一个启用的人员账号 `platform-admin`，为其绑定受保护系统角色 `platform-admin`；该角色拥有全部 Web 管理能力，但不自动获得任何业务应用、工具或数据访问权限。
- 生成高强度一次性初始凭据，通过受限权限的本地凭据文件安全交付；明文不得进入数据库、命令参数、标准输出、日志、审计、API 响应、OpenSpec 产物或代码，首次登录必须修改密码，并使一次性凭据失效。
- 提供“预检/演练—准备—执行—验证”的受控运维流程：统计影响范围、验证可恢复备份、校验外键和依赖、申请全局维护锁、事务化重置、撤销全部旧会话、验证唯一管理员与权限不变量，并记录不可篡改的安全审计摘要。
- 重置成功后关闭旧授权兼容读取并切换到严格应用角色授权；未重新配置业务角色的用户、服务账号和入口不得创建 Agent Job，用户可见拒绝信息使用中文。
- 支持失败事务回滚、重复执行保护和经过验证的数据库恢复手册；不得通过重新启用旧兼容授权来掩盖不完整重置。

## Capabilities

### New Capabilities

- `identity-authorization-bootstrap-reset`: 定义身份与授权重置的作用域、预检与备份、维护锁、事务边界、唯一平台管理员初始化、一次性凭据安全交付、依赖停用、验证、审计和恢复要求。

### Modified Capabilities

- `agent-audit-permission`: 在重置完成后取消旧身份和旧授权兼容来源，要求所有 Channel、Webhook 和管理入口只接受新角色授权事实，并审计重置造成的拒绝和主体失效。

## Impact

- 后端身份、认证、会话、角色授权、外部身份、Trigger/Delivery Binding、配置覆盖和审计模块。
- PostgreSQL 表关系、迁移/运维命令、数据库备份恢复流程及重置操作台账。
- `api-server`、`agent-worker`、`channel-dispatch-worker`、`dingtalk-runtime` 的维护窗口、重启和严格模式读取。
- 管理端登录、首次改密、中文错误提示，以及重置后的人员与角色重新配置流程。
- 部署验收需要容器重建，并验证登录、授权拒绝、钉钉/WEBHOOK 入站到 Job 创建边界和投递边界；当前只读诊断 Agent 的工具边界保持不变。
