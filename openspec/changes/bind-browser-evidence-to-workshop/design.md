# Design

## Context

插件的 `float-sites.ts` 按 origin 检查站点访问许可，`agent-panel.ts` 把同一账号多个应用的环境选项合并，采集会话在 `rootEnvironments` 按 origin 保存环境。事件、网络记录已有 `recordingId`、`tabInstanceId`、文档或请求标识，可以分别定位同域多页。平台浏览器渠道向 Job 传入的 `RoutingContext` 目前只有项目，省略 `recording_id` 时还可能继承会话原有录制。现有浏览器工具读取已就绪的录制包。

平台授权目录已有环境、基地、车间的上下级关系，Loki Resource 已有环境或基地级固定 selector。部署同时调整平台运维和文件存储的权限边界。

## Goals / Non-Goals

用户为 URL 选择业务应用和授权范围后，可以在该页操作完直接提问。个人操作可按当前页、同场同范围或同范围历史检索。插件用网址确定车间，无需解析 MES 下拉框；跨用户协作检索、改写 MES 表单及通用日志权限模型不在本次范围内。

## Decisions

### 1. 把浏览器访问许可与 URL 的业务归属分别保存

浏览器继续按站点申请权限。平台在当前来源、用户和应用下保存 URL 与一组稳定目录 ID 的绑定，插件缓存供匹配，设置页可手动输入 URL 或选取标签页。每条规则选一次业务应用，按该应用授权选择环境、可选基地和可选车间。平台表 `browser_workshop_binding` 保存归属与显示开关。Chrome 本地缓存按账号及平台隔离，主机访问权限由浏览器单独管理。复用已有目录和授权判定，单条角色应用授权须覆盖实际组合和所需能力。服务端校验层级、可用状态和当前授权，为保存的绑定返回身份及版本。

页面匹配使用顶层 URL 的协议、主机和有效端口。绑定路径按完整路径段覆盖自身及子页面，支持 hash 路由。在同一来源内，先取最具体的路径，再取最具体的 hash 路由。站点根目录可显式绑定默认车间。更具体的规则限定了业务定位键时，只有选定键唯一且值匹配才进入相应车间。缺少授权、规则已撤销或归属不明确时停止匹配。保存时显示规则所用的路径和显式选定的非敏感业务定位键，拒绝同一匹配键的冲突。同文档内的同车间导航保留采集与登记，跨车间或离开授权路径后暂停至刷新或重新打开。

### 2. 把归属固定到来源页，把账号和应用固定到服务端录制登记

用户开始录制时，在受认证入口登记录制所有者、应用和每个已选标签页命中的绑定版本。允许多个车间共用一次录制。跨文档导航、单页路由变化、重新绑定时结束该页旧范围，下一条有明确来源的事件使用新版本；采集处理和持久化队列保存事件产生时的归属。后台以登记范围和当前有效授权校验每批数据，服务端生成所有者和租户条件，忽略或拒绝客户端覆盖。跨账号、撤权或页面未匹配时停止相应车间投递，明确标明原因。

操作和 rrweb 片段沿用发出它们的页面范围。网络记录在请求开始时以 `requestKey` 固定来源，响应晚到或落入另一个上传段仍用同一范围。页面共用的 API 域名不足以确定车间。录制级心跳、无法定位到标签页的事件只用于报告覆盖情况。同文档导航跨车间时立即暂停此标签页的页面采集，废止旧页面票据，并提示用户刷新或重新打开。即使地址切回原车间，同一文档仍保持暂停；其他标签页照常采集。刷新或重新打开产生新顶层文档、核对绑定并收到首份已脱敏基线后，才恢复该页。待完成请求保留发起时归属，暂停期间不把来源未确认的新请求标给新车间。

### 3. 让录制中的证据可观察

录制开始时明确选择离线或持续模式，一场录制的模式固定。原有离线模式保留本地回放和手动共享行为。持续模式对可解析的 MES 接口 JSON 保留工单号、批次、数量和业务明细等字段的原值，支持同一用户跨页按原值核对。页面按已确认的源头脱敏策略处理。持续模式在来源端过滤凭据、Cookie、原始业务消息和无法安全拆分的正文或 DOM 字段，先脱敏再写入 IndexedDB。队列只接收持续模式生成的材料，不导入旧离线记录。插件将持续模式的已脱敏观察和证据先存入扩展的独立持续采集 IndexedDB。旧离线库使用原名称和版本，旧插件回退后仍可打开。持续材料写入本地后，再由可恢复的后台队列分批发往平台采集入口。入口校验身份、录制与范围后，将受控标签及事件转给 Alloy，Loki 压缩并使用 MinIO 对象存储。控制库只保存录制登记、范围和核对所需元数据，操作、rrweb 和正文通过 Loki 读回。证据数据集仅供受控入口读取，部署使用专用内部网络与双向 TLS。只有平台 API 和 Alloy 持有客户端证书；普通业务日志资源和共享 Grafana 凭据不能调用证据的读写入口。

- 轻量 `activity` 先送达，原始事件、rrweb、正文按引用补读。Loki 索引只使用取值受控的应用、环境、站点、类别、格式；基地、车间、所有者、录制和标签页放在可过滤的记录字段。由受控入口写入归属，服务端固定查询条件，并校验返回条目与所有后续引用。
- 保留观察时间与接收时间，小批次滚动封段，记录稳定事件 ID、源序号和段清单。重试按稳定身份去重；同一身份内容冲突须报告。分片按对象长度、片序和摘要核对。断网、Worker 重启或磁盘耗尽时显示积压或缺口。收到上传 ACK 仅推进发送状态；核对通过并满足本地保留策略后才回收相应原文。
- 当前单正文默认 1 MiB，可配置上限 4 MiB。拟先提供可调至 **32 MiB** 的采集档位，保留较低默认值；上线前用大响应验证页面负载、解码内存、并发和本地队列承载力。分开约束单正文、队列、序列化日志行、上传批次和工具回复。初始采用每行至多 64 KiB、每批 512 KiB、单次观察回复 256 KiB；先按编码后的真实字节切片，重组后核对已脱敏逻辑正文。超出采集预算留下原因与已知长度。
- 正常路径观测从页面操作到受控 HTTP 查询首次可见的时延，以 p95 五秒为初始验收目标，记录条件和实测值。该目标不包含模型生成时间。

### 4. 在用户点击发送时冻结页面和查询起点

浮窗经现有消息票据识别真实发送页。发送时保存页面匹配规则与版本、车间、录制及标签页实例、文档和提问时间；重试沿用同一份输入和消息幂等键。平台检查应用与录制归属，由平台目录生成 Job 的 environment、base、workshop 路由，同一消息键若更换范围则返回冲突。页面未开始录制时仍可发起车间问题，工具明确返回本页无录制。

复用会话前检查来源、账号、应用和车间一致性。进入其他车间后使用独立会话，可从历史回看原会话；本轮带页面上下文时显式指定录制或无录制，不触发旧会话的隐式继承。通用聊天及用户主动打开的旧录制继续通过现有鉴权入口工作。

### 5. 让 Agent 通过有界接口取证

沿用浏览器工具的 Job 身份和调用鉴权，扩展现有 `search_recording`、`get_recording_evidence` 的契约，复用受控 HTTP 读逻辑。当前录制通过观察接口按 tab 增量读取；同车间多场检索通过本人和应用范围内的录制登记先筛选候选，再在有界窗口内读取 Loki。摘要和详情分别返回覆盖状态、可用引用和后续读取位置。平台把允许访问的范围固定为本轮环境、基地和车间三项的精确组合，空值仅匹配空值，检索默认值取发送页，只有问题明确要求其他页或历史时才选择更大范围。

| 用户问题 | 浏览器检索条件 |
|---|---|
| 在 C 问“刚才保存为什么失败” | 本人、本应用、本场、C、发送时车间，以提问时刻为最近窗口的终点 |
| “我在 A 选了工单，C 为什么没更新” | 本人、本场、同车间，按工单或请求证据关联 A、C |
| “今天这个车间有过同样错误吗” | 本人、本应用、同一完整车间组合、用户当地自然日，支持多场录制 |

游标绑定已验证的调用范围、过滤条件和时间窗。按接收窗口交叠读取并按稳定 ID 去重，对后到封口段按清单补读。超预算、过期、缺片、未录制、鉴权失败和查询不可用均与空结果区分。rrweb 基线、原始正文和分片定位符每次独立验权。此分页属于浏览器证据接口，无需开放任意 LogQL 或调整通用日志工具的分页规则。

关联后端时先使用请求或追踪标识，通过获授权的已发布日志资源在固定环境或基地选择条件内查证；同名车间标签不代表后台日志隔离。已有代码工具可在授权范围内核对相应版本。没找到运行版本、匹配记录或完整链路时，在答复中说明证据边界。

## Risks / Trade-offs

- URL 规则配置错误可能把个人操作标到错误车间。设置页展示实际匹配地址，浮窗显示当前三级范围，规则冲突阻止写入。
- 大正文可能阻塞轻量事件。分别调度观察和正文，测量多标签页内存与积压，用有界重试、公平调度和明示缺口处理压力。
- 读到几条匹配行不能证明所有材料均已送达。保留实时与核对完成两种状态，跨场查询也报告超预算与缺口。
- 通用日志选择条件可能覆盖整个基地。以受控证据接口实施所有者隔离，用请求标识核对后台记录，避免把共享接口或相近时间认作同一个操作。

## Migration Plan

先部署向后兼容的目录、范围登记、读写协议和受控 Alloy/Loki/MinIO 配置，再发布支持三级绑定的插件。旧配置可预填已知环境，用户补全后才启用该 URL 的车间信息流；历史记录不会按新规则回填。按单一授权车间试用，再验证多车间和双账号。回退时先停用新增录制写入和新入口，保留本地待传队列、已接收数据及旧录制读取能力。试用和回退都保留积压或缺口状态。

### 主 Compose 与共享 MinIO

主 Compose 的 `browser-evidence` profile 启动 Alloy、Loki 和一次性证据桶初始化。Loki 使用本机 `grafana/loki:latest`，部署记录本地镜像 ID。文件与证据使用同一 MinIO 的不同私有桶和不同受限访问密钥。证据桶独立设置容量和七天保留期。旧环境先轮换文件服务的受治理凭据，再启用采集。已有独立试用卷保留原位，切换不回填旧数据。
