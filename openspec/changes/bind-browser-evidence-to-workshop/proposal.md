# Proposal

## Why

用户在 MES 某个车间操作后，希望直接在同一个标签页问“刚才为什么保存失败”。当前插件按站点保存环境，提问入口只向 Job 传项目，录制工具依赖已上传并就绪的录制；同域不同车间、同一车间多个标签页和多人同时操作时，Agent 都缺少可靠的定位依据。

## What Changes

- 用户输入页面 URL 或选择标签页，为每条规则选择一次应用和已授权环境，可继续选基地、车间。每个匹配的 URL 唯一对应一个业务范围，悬浮助手显示当前范围。用户仍主动选择录制目标并开始采集。
- 对已纳入录制的标签页，按操作发生时的车间和来源页标记操作、页面变化、接口及其证据引用；同一场录制可覆盖多个车间。录制过程中即可查询已经送达的证据。
- 从悬浮助手发送问题时冻结发送页的业务范围，默认定位本人当前标签页。明确询问其他标签页或某日同车间历史时，可在完全相同的授权范围与时间窗内跨标签页、跨录制检索。
- 通过 Enterprise Agent 的受控接口向 Agent 提供增量观察和证据详情，结合获授权的服务端日志、代码版本辅助解释。浏览器信息流沿采集入口、Alloy、Loki、MinIO 链路写入和读取；大正文分片，读取结果标明积压、缺片和过期。
- 既有通用聊天和显式选取的已就绪录制继续按原入口使用。旧浏览器本地环境设置缺少平台规则授权，用户可按实际授权保存到相应层级，历史材料保留原归属。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `channel-conversation` — 插件 URL 绑定、操作来源和提问范围、录制期间的证据写入与可见状态。
- `builtin-tool-resource` — Agent 读取本人、指定车间和时间范围内的浏览器证据，定位详情并关联已有日志资源。
- `platform-operations`、`task-file-workspace` — 主 Compose 共享 MinIO，隔离任务文件和浏览器证据的身份、容量和生命周期。

## Impact

插件涉及站点设置、悬浮聊天、采集会话、网络正文预算和本地待传队列。平台涉及浏览器渠道应用目录、消息与 Job 路由、证据读写接口和工具授权。协议落在 `contracts/browser-extension/`，沿用平台已有的环境、基地、车间目录及角色应用授权。部署需提供受保护的证据写入入口和 Loki 对象存储配置；已有业务日志的 Published Resource 仍按原固定选择条件访问。
