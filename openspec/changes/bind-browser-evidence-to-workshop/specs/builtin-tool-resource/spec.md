# 按车间检索浏览器证据

## ADDED Requirements

### Requirement: 浏览器信息流按本人及本轮授权范围检索

浏览器证据读取 SHALL 以受信 Job 或经同等鉴权的渠道请求为依据，在相同平台来源、应用、本人、环境及有界时间窗内查询。基地与车间 MUST 逐项精确匹配，未选值只匹配同层级的未选值。默认范围为发送时的录制及标签页。用户明确要求同场其他页或同范围历史时，工具才可在相应范围内检索。各入口 MUST 在读取前复核当前授权和证据归属。

#### Scenario: 两人同车间同时保存

- **WHEN** 张三和李四在同一车间访问同一个 URL，同时完成各自的保存操作，张三从 C 提问
- **THEN** 默认结果只包含张三本场 C 页的证据；即使显式要求同车间历史，也不含李四的行、正文、计数或引用

#### Scenario: 跨页和跨录制的边界

- **WHEN** 用户在 C 明确询问同场 A 页对 C 的影响，或询问“今天这个车间是否发生过同类错误”
- **THEN** 前者可读取同场同车间的 A、C，后者可读取本人同车间当天多场录制；两者均排除同场其他车间

#### Scenario: 换用引用或撤销授权

- **WHEN** 传入另一车间的请求或 rrweb 引用、其他用户的录制 ID、与筛选不符的游标，或权限已被收回
- **THEN** 服务端在返回内容之前拒绝，响应不披露越界对象的内容或存在性

### Requirement: 增量观察和证据详情可按来源核对

工具 SHALL 先提供有界的操作时间线、观察时间、覆盖状态及稳定的证据引用，并支持按需读取相关接口或页面证据。增量读取 MUST 处理同时间戳、重新投递和迟到补传，显式标记未读完、过期和缺失。大正文的响应预算与单次允许采集的正文大小分别约束。

#### Scenario: 大响应与迟到数据

- **WHEN** 同一标签页的多个事件时间相同，个别事件在查询后补传，一份大响应需多次读取
- **THEN** 消费者可用相同筛选继续读取、去重并重组预算内已采集的响应且核对长度与摘要；无法核对时明确给出不完整状态

### Requirement: 关联服务端日志和代码时保留各自的证据范围

Agent SHALL 通过现有授权工具和已发布资源关联后台日志或代码。车间归属只描述浏览器来源。答复 MUST 区分已观测的点击、接口结果、后台关联事实，以及仍需确认的原因。

#### Scenario: 多个标签页共用接口

- **WHEN** C 的失败响应带有可匹配的请求或追踪标识，同时同一时段其他页也调用该接口
- **THEN** 服务日志查询沿用获授权环境或基地的固定选择条件，通过关联标识核对结果；仅时间接近的请求不能认定为 C 的请求
- **AND** 找不到可匹配日志或无法确认运行代码版本时，答复指明缺失的依据，不将候选原因写成现场事实
