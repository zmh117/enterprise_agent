## Context

Knowledge MCP 允许四个在途调用，重排只有一个执行槽与三个等待位置。排队消耗检索预算，现有失败审计只有错误码。Runtime 已使用进程内 MCP bridge 转发受控工具，固定知识工具仍直接交由 SDK 发 HTTP 请求。

## Goals / Non-Goals

目标：同一 Job 的知识请求在 Runtime 排队，进入 MCP 后保持独立单次预算；为成功、失败和取消留下不含业务正文的计时证据。

不增加通用调度平台，不改变模型、候选量、访问模式、Job 重试或权限；不通过延长 360 秒和 JWT 寿命解决排队。

## Decisions

- 新增专用于两个固定知识工具的 Runtime bridge，复用现有 SDK 内嵌 MCP 注册方式。按冻结名称/schema 验证远端目录，以一个 FIFO 异步锁串行派发；等待和传输统一服从本次 Runtime 的原截止和取消。仅修改提示词不能强制串行，服务端等待又会消耗已经开始的检索预算，均不采用。
- bridge 在取得派发槽后才发送请求；发送 Runtime 截止和安全的派发等待毫秒数，Knowledge MCP 仍取本地 360 秒、上游、持久化 Job 预算最小值。请求失败不自动重试，取消等待项不得发出 HTTP。
- 通过内部 HTTP 响应头接续 Knowledge MCP 请求内已经续期的 Principal；只在 bridge 内存保存，不进入 MCP payload、SDK 工具结果、日志或审计。后续请求仍验证票据和当前授权。没有有效续期材料时失败关闭，不接受已过期旧票据。
- 请求范围计时对象只接受固定阶段/数字，记录有效截止来源和各段耗时。重排响应携带内部计时并输出带随机请求关联标识的安全事件；客户端未收到响应时将细分耗时保留为未知，不伪造为零，可按关联标识核对服务事件。
- 统一工具审计在成功和异常路径都写计时快照；保留已有错误码和业务结果 schema。阶段含授权、资源解析、查询向量、向量检索、重排、ONES 可读性及结果组装。

## Risks / Trade-offs

- 串行会增加多库总等待，但避免同 Job 争抢单路重排；跨 Job 容量上限仍由现有服务控制，不能据此承诺真实环境时延。
- 原短期 Principal 可能在长调用期间续期；必须消费安全传输头并测试超过单张票据生命周期的连续派发，不能把凭证写入结果。
- 服务超时后模型线程可能仍退出中；计时区分部分与完成，现有槽位保持到真实线程退出。

## Migration Plan

无需新数据库迁移。同步部署 Runtime、Knowledge MCP 与重排镜像；工具输入输出 schema 不变。以前的四小时同步迁移属于另一个变更。发布前执行串行/取消/授权/预算及真实本地 MCP 协议回归；目标环境部署和业务容量另行验收。
