# 本地验证记录

日期：2026-11-05。证据仅针对本地实现、合成数据和实际 SDK/MCP 协议；未连接真实 ONES、业务模型或目标环境，未部署服务、应用数据库迁移或提交代码。

## 已验证行为

- 用安装的 Claude Agent SDK、MCP `InMemoryTransport` 和合成 HTTP 服务并发提交三次检索：实际派发峰值为 1，按到达顺序执行。每次计算 120ms、单次预算 200ms，三次总耗时超过 200ms 仍全部成功，证明等待位于单次远端预算之前。
- 排队项取消、Job 取消、截止或 bridge 关闭后不发出请求；前一请求失败后后续项正常执行，无自动重试。408/503 响应中安全错误码、有效续期头分别处理，私有错误正文不透传。
- 实际 Knowledge MCP ASGI 入口、Runtime bridge 和 SDK 进程内 MCP 连通，三次调用的审计包含安全阶段耗时、派发等待及有效截止来源。
- online/offline 回归保留现有权限边界。模拟超过旧 300 秒票据生命周期，服务端仍执行真实签发/核验逻辑；新票据可用于下一请求，过期旧票据仍被拒绝，工具内容、日志和审计不含票据。
- 重排服务区分排队、执行和部分计时；客户端未收到计时时保留 null。成功/失败审计都有固定阶段及预算信息，异常远端字段不进入审计。
- Runtime 实际装配保留版本一致性与冻结 schema 检查，知识 SDK bridge 超时覆盖 Job 等待；其他 MCP 路由保持其原有策略。关闭会清理异步任务、HTTP 客户端及内存凭证。

## bundled CLI 注册验证

使用隔离临时配置目录、固定本机不可达模型地址和合成 Key，只连接安装的 `ClaudeSDKClient` 并查询 `get_mcp_status()`，不发起模型请求。等待注册后，`knowledge_mcp` 状态为 `connected`，可见工具恰为 `knowledge_list_bases`、`knowledge_search`；CLI 接受 1800000ms 的本地 bridge 超时配置。客户端和临时目录在测试后关闭、清理。

这证明真实 bundled CLI 注册与配置兼容，不是模型发起并行调用或持续 360 秒调用的现场验收。

## 检查范围

最终回归 **554 passed in 82.36s**，覆盖知识 MCP、Principal 续期、重排、推理队列、预算、搜索、访问模式、授权、Runtime、固定合同、架构和测试分层治理。修改的 30 个 Python 文件通过 Ruff 检查和格式检查，17 个源文件通过 mypy；变更及两个相关 canonical spec 通过 OpenSpec strict，`git diff --check` 通过。

## 交付边界

- 需协调更新 Python Runtime、Knowledge MCP 和 Reranker 镜像。工具输入输出 schema、访问模式、候选量和 360 秒硬上限未改变；四小时同步及其迁移属于单独变更。
- 本地验证不能确认其他环境之前两次失败的慢阶段，也不能承诺现场成功率或 P95。应使用新审计比较同步空闲/繁忙、单 Job/多 Job；串行仅协调同一 Job，不消除跨 Job 或同步任务的资源竞争。
- 凭证接续要求实际收到有效内部响应头；连接中断丢失响应时仍失败关闭，不允许接受过期票据或在后台绕过授权续期。
