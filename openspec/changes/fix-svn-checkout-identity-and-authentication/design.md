## Context

当前 `physical_key=sha256(st_dev, st_ino)` 被 knowledge-sync 和两个 Runtime 长期共享，虚拟文件系统重挂载后不稳定。实际工作副本已核验 r2、UUID 和完整范围正常。SVN 管理入口目前仅支持部署 JSON 登记和挂载的 SVN auth 目录；页面无法登记真实地址和账号。原生工具审计丢弃安全拒绝码，异步操作的传输成功被展示成完成。

## Goals / Non-Goals

实现跨正常重挂载的身份验证、真实 SVN 页面连接、安全认证和可行动的失败提示。保持原有共享只读、单写者、固定 SVN revision、知识先行的流程。此次不做 Graphify、不重放旧业务 Job、不执行业务预提取，不改变 ONES 内容。

## Decisions

1. 在受管工作副本 `.svn` 中保存版本化随机身份标记，`physical_key` 保存对应持久键。新检出在独占期间初始化；Runtime 只能读取标记。每个本地 Reader/WorkingCopy 实例还固定自身观察的设备号/inode，检测执行中替换，不跨容器比较该本地值。校验标记为普通文件、无链接，校验路径规范与已有唯一/重叠登记约束。
2. 旧哈希登记只能由维护命令在持有目录行锁、没有未释放读占用、没有未结束 SVN 操作的情况下完整核验后升级。缺失/不匹配的新标记不能自动重建。标记与数据库写入中断可在同样独占核验下恢复。保留工作副本、既有答案和业务版本；代次变化使旧授权失效。
3. 新增资源归属的 SVN 连接表，仅保存 SVN 服务地址（http/https/svn）、Secret 引用、识别出的 UUID/分支和创建审计元数据。连接配置不可原地覆盖：改地址或账号产生新连接，旧发布继续引用旧连接，重新浏览再绑定/发布新配置。部署登记仍为本地启动来源，统一解析，但页面连接不得跨资源引用。
4. 页面一次提交地址、用户名、密码，控制面要求知识管理和凭据创建权限，在同一事务中调用既有加密 Secret Provider 保存账号密码 JSON。只返回连接 ID、地址和已配置状态；后续操作只传 ID。knowledge-sync 解析凭据并通过 SVN `--password-from-stdin` 传密码，使用 `--no-auth-cache` 和临时空配置目录；不把密码放 argv/env、工作副本、普通审计或 Runtime。TLS 校验保持开启，企业 CA 由部署信任链配置，不提供跳过证书选项。
5. 首次浏览通过 `svn info --xml` 识别 UUID/分支并固定；后续浏览、检出、info/update/log/diff 均复核连接身份。失败只返回固定认证、证书、连接或一般 SVN 错误码，不透传 stderr。外部引用和任意命令保持关闭。
6. 普通工具摘要增加有界 `operation_state`、操作种类和错误码。保留 MCP 调用成功这一事实，另显示后台排队/执行/失败；源码 Hook 把固定拒绝原因按 tool use ID 留在内存，合并至标准化事件，标记 DENIED/NEVER，不保存路径、搜索词或源码。确定性目录错误明确提示停止重复申请。
7. 页面连接的临时 SVN 配置只增加部署提供的 CA 信任：从既有只读 `CODE_SVN_AUTH_ROOT/trusted-ca/*.crt` 读取公开 PEM 证书，在任务临时目录合并后配置 `ssl-authority-files`。目录可缺省，系统默认 CA 仍生效；已配置但损坏、超限或链接证书拒绝执行，不忽略证书或主机名校验。本地 SVN 初始化复制公开证书到该目录，不复制私钥或账号，不按 URL 借用旧认证目录。企业部署可在同一目录添加公开 CA。
8. 源码绑定删除访问登记选项及请求字段。复用 `code_svn_operation` 中唯一成功 checkout 的不可变请求，取得原始 registration 和摘要；确认连接当前仍可由该资源使用、摘要及 UUID/分支一致后，由后端填入既有配置的 `svn_access_ref`。不按 URL、列表首项或最近浏览猜测连接，不新增表。列表返回安全连接摘要，前端只读展示实际连接地址和认证类别。缺少、冲突、变更的来源或其他资源的账号连接不得新绑定；只经维护登记且没有成功检出记录的目录需要从当前页面重新检出，不能伪造历史。已发布配置保持固定引用，不因新增连接记录改变。

## Risks / Trade-offs

浏览表单仅有一个 URL 和“无需认证 / 配置用户名密码”两种模式，无已保存连接下拉框。无需认证时按输入地址直连，不自动替换本机或远端 URL，不套用部署登记的路由或认证配置；创建资源所属匿名连接，以空 secret_ref 表示无凭据，使用隔离空 SVN 配置，不解析 Secret。账号模式保持选择不变，密码保存后清空，表单在地址、账号未变化且没有新密码时复用已保存 ID；编辑后失效。匿名与账号连接均固定首次核实的仓库身份。连接目录 kind 扩展为 deployment/account/anonymous，仅用于来源绑定元数据。

代码知识库与现有环境采用多对多关联，绑定配置修订；页面多选启用环境，知识目录返回环境编码和名称，Agent 据此选库。环境归属不代替知识库 grant，也不自动扩张数据库权限；共用代码的环境在同 KB/来源/修订下复用代码规则，涉及现场差异的结论仍须说明条件并独立核验。

- 持久标记本身不是源码内容证明：继续逐次核验 SVN 来源、干净状态和 revision，读取证据继续核验文件 hash。
- 本机无法替用户验证尚未提供的真实企业 SVN：用隔离的需认证 SVN 夹具和当前本地真实工程验证，明确区别现场验收。
- 页面允许管理员配置本机或远端 http/https/svn 服务地址：限现有管理权限，拒绝 URL 内凭据、file/SSH 隧道协议、参数注入；不能开放给模型提交任意 URL。
- 旧容器不理解新身份：更新知识执行器和两个 Runtime 后才维护升级现有登记；先排空占用，不能混跑旧代码读取新标记。

## Migration Plan

新增迁移连接表并完成 SQLite/PostgreSQL 同构校验；运行定向后端/前端/权限/并发测试；构建更新相关容器；在无活跃读写时升级当前登记，核验两个 Runtime 只读视图和同版本读取、重建容器后身份稳定。回退需要保留维护窗口并回退登记协议，不能直接让旧 Runtime 接新持久键。
