# PostgreSQL 重启恢复实施证据

日期：2026-10-09。用户确认单次采集、单次同步和常驻同步均支持自动恢复。

## 实现

- 知识 CLI 专用恢复入口，仅处理 PostgreSQL 连接类/重启错误及已知 libpq 瞬时传输故障。池超时另做一次 5 秒直连鉴别；认证、权限、库名、TLS、schema、配置和业务拒绝不进入数据库恢复循环。
- 失败尝试退出并关闭旧连接和客户端；以 5/10/20/40/60 秒封顶退避、无总次数上限重试，SIGINT/SIGTERM 可中止等待。非写入的 status/configure/enable/disable/cancel 不增加无限重试。
- 每次重新读取 schema、绑定身份和启用状态，再获取 worker/source 会话锁。进程内固定 run；原日/阶段恢复、staged UUID 幂等、原索引代际复用不变。已激活响应丢失会读取原 ACTIVATED 成功事实，daemon 即使尚未到下个 tick 也先完成读回。
- 采集、分块、向量、内容访问和凭据解析的安全包装保留原始 cause；故障记账、解锁或关闭失败不覆盖原始故障。输出仍为固定事件/错误码、计数、等待秒数；不输出连接串、原始异常或业务正文。
- 恢复 COLLECTING 时也补记幂等调度 tick，避免首次 begin 已提交、调度记账失败时漏记。永久错误在 daemon 中停止，原 Provider/Embedding/Qdrant 瞬时故障仍走既有有界间隔重试。
- 不新增 schema、配置变量、授权或发布逻辑。不改默认停用、七个创建日、3600 秒周期、容量和双权限边界。部署需要重建并重新创建 knowledge-sync，命令已写入运行手册。

## 隔离 PostgreSQL 真实重启：2 passed

仅使用带测试所有权标签的独立 PostgreSQL 18 容器、固定本机测试端口和任务专属数据卷；测试先核对容器标签、DSN 主机/数据库/端口。仅迁移测试库，Provider/凭据替身及记录均为合成数据，不连接真实 ONES、不加载业务凭据。

1. 页候选提交后、日检查点前重启 PostgreSQL 容器：旧会话失效，发生一次安全重试；原 run 恢复为 STAGED，只有一个 run/候选，已 staged 详情仅拉取一次，日游标完整后前进，当前正式成员仍为空，新连接实际重新拿到 source 锁。
2. 启动前停止测试数据库：连接池超时经直连判定为瞬时故障，数据库启动后同一进程继续并完成 STAGED，不需人工重跑。

第一次试验使用随机发布端口和 tmpfs，容器重启导致测试端口变化/数据不保留，因此中止，不能作为恢复验收。改为固定端口、任务专属持久卷后，上述两项通过；修正一个只存在于测试断言的表字段引用后再次运行 2 passed，增加目标归属核对后最终重跑仍为 2 passed。

测试容器及其专属合成数据卷已移除，不含业务数据。没有重启本机业务数据库、启动真实采集、修改部署/凭据/权限/发布或提交推送。真实 ONES、完整外部模型/Qdrant 重启联调及历史 8–10 节待验收项仍未完成，不补勾。
