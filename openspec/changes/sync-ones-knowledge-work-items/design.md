## Context

用户已确认三个独立知识库、每 3600 秒采集一次但默认停用，以及完整校验后自动切换同一知识库的检索版本、失败保留当前可用版本。当前本机没有可用真实 ONES，开发、离线导入和本地向量化可先完成，真实采集在未来具备连接条件的环境显式启用。

本轮只读核对的代码事实：

- PostgreSQL 已有 `defect/ticket/requirement/article` 分类，document ID 由 source、`ones_work_item` 和 UUID 生成，不包含 KB 或分类；`document_revision` 保存不可变内容版本，关系独立保留来源证据。
- 导入仓储、清洗用例、向量仓储均硬编码 defect；来源/KB 默认名称也固定缺陷。不能仅换目录参数直接导入工单或 Story。
- 现有向量索引绑定 corpus/profile、索引 ID 和独立 collection，point ID 由索引 ID 和 chunk ID 生成；只支持同一索引断点重放，尚无跨索引向量复用。
- `KnowledgeResourceReader` 的配置摘要使用整个 source 的当前文档；新增同源另一 KB 会影响原 KB 的摘要。候选读取也依赖 `document.current_revision_id`；先更新此指针再编码，会让旧发布失效。
- 指定导出目录的只读统计：工单详情/list 各 4820 行、Story 各 17388 行，均无重复 UUID，详情/list 集合相同。详情文件约 46 MB/161 MB。12627 条 Story 的描述字段没有非空字符串，但列表具有标题；其余富文本仍需正式规范化预检，不能把字符串存在等同于有可用正文。
- 指定导出器含创建时间分片、详情抓取和已完成 UUID 缓存，也检测到字面量认证头和关闭 TLS 校验；没有已验收的更新水位合同。只做无字面量值的结构检查，未运行脚本、读取配置凭据、显示业务正文或调用 ONES。

以上是实现依据，不是已经完成新类型入库/自动同步。canonical 仍只描述离线存储；本次 delta 增加同步和知识版本行为，不改 Database/Redis/Loki 的发布语义，不覆盖其他 active change 的验收记录。

## Decisions

### 1. 统一身份、类型化收录、来源明确而不重键

| 数据 | document_kind | KB code | 首批范围 |
| --- | --- | --- | --- |
| 缺陷 | defect | 保留 `ones-defects-offline` | 保留已有数据；后续受管采集更新 |
| 工单 | ticket | `ones-tickets-offline` | `全部工单` 的完整详情/list |
| Story、Sub-task、演示子任务 | requirement | `ones-stories-offline` | `全部story` 的完整详情/list |

名称允许为“ONES 工单知识库”“ONES 需求知识库”，不把工作项显示类型当稳定 ID。保留可取得的真实来源类型 UUID、显示值、source timestamp、内容 hash；在线采集配置的类型 UUID 到三种分类为显式映射，未知类型拒绝，不按标题关键词猜测。离线输入由显式 `--document-kind` 声明粗粒度分类，验证每条来源类型都属于该分类已批准的集合；默认 defect 的旧入口保持兼容。

2026-09-21 实施预检后用户确认：需求库收录全部 17388 条，包括 Story 4244、Sub-task 13056、演示子任务 88。当前可读导出只有类型显示值，因此明确使用本批映射（缺陷→defect、MES工单→ticket、上述三类→requirement），保留实际来源类型并标记类型 UUID 未采集，不反推 UUID。Embedding 上下文显示真实类型，子任务不改称 Story。此批准映射不自动推广到其他 ONES 实例或任意未知名称。

三个指定导出属于用户指定同一离线数据集，复用既有离线 source 命名空间，不因此宣称已验证 ONES 实例/Team。未来采集绑定必须明确该 source、Provider 目标、类型/项目集合及配置 revision；切换目标或范围不能继承旧水位。连接信息属于采集配置，不重新引入知识资源 Web 的 ONES 地址/Team 确认表单。

跨类型链接只保存真实 UUID 与观察方向；目标导入后补解析，不从关联摘要生成正文。同一工作项类型迁移时 ID 不变，以更高来源版本更新类型并在同一激活事务调整两个 KB 的收录。相同 timestamp 但内容/类型冲突停止批次，不靠执行顺序覆盖。旧文件重放不使已迁出的成员重新收录。

取舍：不按类型分 source 或复制正文，避免跨库关联断裂；不新增 `story` 枚举与既有 requirement 重复。

### 2. 保留实际文本，给稀疏记录明确质量标记

预检流式读取并保持现有文件/行/记录上限，校验唯一 UUID、详情/list 集合、字段形状、来源时间单位、类型和输入 hash。批次失败无静默跳过；数量不是靠文件夹名称推断。本轮两个数据集初始期望 4820/17388，实施时重新确认文件未变化。错误只报行号、类别及安全统计。

标题仍必需。工单/Story 正文为空时允许标题和实际业务字段构成可检索文本，标记 `description_missing` 或 `title_only`；只有图片且无文本也不触发下载/OCR。标题也缺失则隔离为批次错误，不能声称全部已入库。富文本解析继续移除 URL、认证材料、Base64 和控制字符，正文不改写为模型总结。

沿用现有保守切段、重叠、证据 offset/hash 和 1200/1800 字符边界，另以明确版本提供工单/Story 的上下文模板。工单优先描述、实际处理/解决内容，Story 优先描述、已有需求/验收字段；没有的字段不补造。模板为“类型、项目/模块、标题 + 本块实际内容”，不拼接其他工作项正文，不把全部未映射字段无界塞入 Embedding。保留未映射字段的安全原始值与来源映射，用于追溯；是否进入 Embedding 按固定白名单。

既有 defect normalizer/profile 不因新增类型而全局升级；新类型派生版本有明确标识，避免已有 5000 条缺陷重分块/重编码。标题-only 生成一块，不能伪造“解决方案”；边界测试覆盖纯图片、HTML 空壳、长代码、超长字段和提示注入。

取舍：不因缺少描述丢掉大多数 Story，也不以臆造正文提高表面召回率；是否有效仍需人工效果评测。

### 3. 将导出器逻辑收敛为受管采集适配器

指定目录是来源参考，不成为运行时可执行插件。提取分页/分片、详情解析和必要字段映射，放入 knowledge infrastructure；复用现有固定 ONES HTTP/解析边界可用部分，不复制账号登录体系。临时探针、图片下载、硬编码认证头、任意路径加载和 `verify=False` 不进入部署镜像。

采集使用独立受管只读 ONES 凭据和固定配置的 Provider/Team/项目/类型集合；认证材料通过受管文件或既有 Secret 引用在受信适配器内部消费，不出现在参数、日志、异常、数据库快照或模型中。启用前核验目标、TLS 与证书、范围和真实分页合同。同步服务的 PostgreSQL 写权限与在线 `knowledge_mcp_reader` 隔离；MCP、Runtime 不获得采集写账号或 ONES 服务账号。

首版可靠模式为可恢复的完整枚举与详情版本核对，复用创建时间分片仅用于覆盖全集，不把它当“更新时间过滤”。每轮重新检查已有 UUID，不能根据历史 done 集合永久跳过。完整页合同、游标无进展、重复页、截断/窗口上限和数量差异都必须检测；最小可分片范围仍截断时返回未完成，不标为成功。

若以后已在目标 ONES 验证可靠 updated-time 筛选和稳定排序，才启用优化模式：固定扫描上界、重叠时间窗、时间戳/UUID 去重、时间戳单位归一、周期全范围对账。该模式不能仅根据本地脚本字段名自动开启；没有验证就保持完整扫描，不承诺每小时全部抓完。两种模式都只为发生真实语义变化的内容生成新版本和新向量。

采集可见性下降、401/403/404、5xx、超时、部分分页不能推断业务删除，不批量撤收录或清向量。首版不自动推断永久删除；权威删除/移出范围证据需要独立已验证合同或显式维护命令。运行时仍以用户当前 ONES 权限挡住不可读项目。

取舍：完整枚举可能更慢，但比未经验证的更新时间筛选或 UUID 跳过可靠；不把采集完整性问题藏成“零更新”。

### 4. 少量持久状态驱动串行同步，不另建 MQ

在 `knowledge` 内新增面向当前用例的同步绑定、运行及候选项目事实，命名在迁移时按仓库惯例确定：

- 绑定：source、三种类型到 KB 映射、配置 revision/hash、启用状态、3600 秒间隔、允许自动换版的资源 ID、采集目标/凭据引用、完整扫描模式、下一触发时间。
- 运行：run ID、binding revision、阶段、冻结扫描范围、完整性事实、进度/安全计数、采集检查点、激活水位、期望旧资源 revision、失败码和时间。
- 候选项：run/source/UUID 唯一键、来源版本、类型、候选 revision 引用、旧 revision/成员期望值、处理结果；复用不可变文档修订和 vector_index_item，不再保存多份正文。

阶段为 `COLLECTING → STAGED → CHUNKING → INDEXING → VERIFIED → ACTIVATED`，失败保留阶段检查点以恢复，配置变化使旧候选不能激活。数据库保证同一 source 只有一个有效写运行；借用现有 advisory lock，短事务保存 checkpoint，外部 HTTP/Embedding/Qdrant 不在事务内。无须通用调度 DSL、任务依赖图或 MQ 消息。

可选 `knowledge/sync.compose.yml` 提供同步 worker/CLI，调度默认停用；停用时不登录 ONES、不写采集游标，未启用环境无额外 Secret 要求。启动任务需 profile 与绑定 enabled 两重显式动作。3600 秒为触发间隔，不是无论上一轮是否完成都启动一轮；运行超过周期只记一次待执行，不堆积小时补跑。重启先恢复未终态运行，只有完整持久化后推进对应采集 checkpoint，激活水位仅成功激活后前移。

全量同内容轮次只刷新同步观察统计，不增加修订、不建新 collection、不调用编码、不重复发布。取消/禁用有界终止在途批次，当前已发布内容不被撤销。

### 5. 候选修订先入库，但不抢占当前可用内容

自动更新不能照搬现有导入后立刻推进 current_revision_id 的行为。新增同步/批量流水线入口将候选修订持久化，但保持已存在 document 的当前指针、类型和收录不变。新 document 使用不可检索的 `pending` 状态，迁移增加该状态，旧查询仍只读取 active；新关系观察绑定候选 revision，不能覆盖当前关系视图。

候选分块和索引读取明确 run 内的“基线成员 + 候选覆盖”，不偷用随时变化的 current 查询；vector_index_item 及不可变 chunk_set 构成冻结成员清单。旧 CLI 在未发布数据集上的行为可保留，但若它会改变已有发布的内容，必须拒绝并要求走受管同步入口，避免维护脚本绕开双缓冲。

本版自动激活仅接受内容与治理均在平台同库的明确绑定。候选向量已在 Qdrant 就绪后，短 PostgreSQL 事务检查 binding/resource revision、停用状态、基线成员、并发内容版本及验证 hash，整体更新对应 current 指针/成员/关系当前视图、新不可变资源修订与 published 指针、激活水位。三种类型间迁移和同批受影响资源一起切换，任一冲突整体回滚。Qdrant 无跨库事务：先写尚未引用的新 collection，后提交 PG 指针；PG 提交前失败留下未引用候选，提交后崩溃可凭运行状态幂等恢复，不对活跃 collection 先删后写。

未发布 KB 的首批数据可以完成内容激活与 READY 索引，不因此创建业务授权；首次资源发布仍走显式管理流程。已有资源首次纳入自动更新需显式绑定 resource ID、当前连接/profile 与允许策略。worker 不创建/覆盖管理员手工草稿，不变更连接、凭据引用或索引模型，不自动启用已停用资源；这些变化必须由管理员重新配置和验证。

取舍：这是一层必要的候选/激活状态，不是多版本通用平台；它避免“先入库再编码失败，旧版本已经不能用”的假回退保证。异库原子切换不是本轮范围，不能用补偿写冒充原子事务。

### 6. KB 范围摘要与旧发布兼容

新增配置版本只基于所选 KB 的冻结成员、对应修订、类型、profile 和索引计算摘要，不把整个 source 的其他 KB 内容纳入。MCP 返回前继续比较本次固定资源版本与当前授权；激活期间旧调用失败并要求重试，不拼接两代结果。

旧配置 hash 不原地改写。首次导入其他同源类型之前，提供显式兼容接续操作：预检所有受影响已发布资源，在已验证旧发布仍可用时，以相同 KB、索引、连接和权限创建新的 KB 范围资源修订，完成独立验证再切换。无需重编码原缺陷点。若发现未纳入维护范围的同源资源、未知配置版本或并发草稿/停用，停止接续和正式导入，不让未批准资源悄悄失效。迁移 DDL 只增加版本/状态字段，不自动发布或把旧验证当新验证。

### 7. 只编码变化内容，向量代际与清理有界

候选索引保持现有稳定 point ID 公式和引用型 payload，为每个确有变化的 KB 构建新 collection。优先从明确已验证的旧索引批量读取可复用向量：相同模型完整 profile、模板/清洗版本、embedding_hash、维度且向量有效才可复制；身份/profile/文本改变则重新编码。跨新 revision 即使 chunk ID 变化，也只凭完整文本/模型键复用向量数值，新 payload 必须绑定候选 document/revision/chunk，不复制旧引用。

无需外部向量缓存或在 PostgreSQL 再存一份完整向量。构建后核对逐点 payload、维度、实际点数及冻结成员摘要，计数相同不能替代逐点检查。新 KB 首次全量编码先抽样基准、报告耗时估算并支持后台断点恢复，不承诺现有 CPU 在一小时完成所有内容。

某类成员经已确认的类型迁移变为零时，允许完整空语料形成零成员、零块、零点的 READY 代际；不调用 Embedding，并验证空 collection 与空成员摘要一致后按相同事务激活。查询返回空命中，不能继续返回旧成员，也不能把采集失败或零页响应当成已确认空库。

派生版本清理仅针对带本同步运行归属且已无发布/候选/在途引用的 collection：保留当前及上一成功版本，失去引用后至少等待 10 分钟；同时复查数据库引用。手工/历史索引、当前或上一成功索引、原始文档/修订不自动删除。失败重试复用同一候选 ID，不每小时重复建失败 collection；超出磁盘预算则暂停构建而不是删除可用版本。清理动作只记录安全数量/ID，与原始数据删除分开。

### 8. DDD、部署与验收边界

domain 负责类型、时间/版本顺序、模板与纯候选规则；application 编排预检、采集、派生和激活，使用具体所需 ports；infrastructure 负责导出适配器、SQL/锁、受管 Secret 和 HTTP；CLI/worker 显式装配。不得在 API、domain 或模型 MCP 中直接实现采集 SQL/网络逻辑，不创建无调用者抽象。

默认本轮交付不连真实 ONES，测试用合成 HTTP Provider 覆盖分页/更新/失败；本地真实文件只交给受限程序预检/入库，输出安全统计。本地真实 BGE-M3/Qdrant 可验证流水线，但不证明 ONES 增量合同、角色本人权限或人工召回质量。MCP 仍按当前业务应用 KB 范围与本人 ONES 可读性返回引用；采集账号可读全部，绝不等于所有用户可读全部。

## Risks / Trade-offs

- [多数 Story 无描述] → 标题-only 和质量标记保留信息，不制造内容，单独报告这部分效果。
- [导出可读字段可能混用 ID 与名称] → UUID 从可靠列表/字段字典获取，显示值独立保存；不能按显示名称重建身份。
- [小时触发但全量扫描/编码耗时较长] → 串行恢复、合并 tick、实测吞吐，不承诺一小时新鲜度；真实优化模式须先验证 Provider。
- [来源哈希牵连其他 KB] → KB 范围配置版本及显式旧发布接续，正式入库前先完成兼容门禁。
- [修改期间向量落后] → 候选修订不抢占 current，激活原子；详情仍由本人实时回源，旧索引不是旧权限缓存。
- [采集凭据过期或权限缩小] → 安全失败、停止水位，不根据缺失推断删除；没有“全部允许”的 Mock 兜底。
- [类型跨 KB 变更或并发人工发布] → 同 source 排他与期望 revision CAS，相关资源同批激活；不自动修改手工草稿。
- [周期生成派生版本占满磁盘] → 无变化不建版、失败恢复同一版、只清理已归属且无引用的过时派生索引，保留当前/上一成功与原始数据。

## Migration Plan

1. 先完成本规格与批准，锁定类型/数据量/默认停用/自动换版范围；不执行原始导出工具，不变更真实部署。
2. 实现类型化预检/分块和合成回归，保留原 defect 重放/ID/profile/hash 合同；新增前向候选与同步状态迁移，按实际最新 catalog 分配版本。
3. 实现采集适配器、串行恢复、向量复用和原子激活，补双引擎、独立 PostgreSQL/Qdrant 与 MCP 合成验收；登记新测试。
4. 正式处理前核对输入摘要、schema/非终态任务/磁盘和现有资源，按批准维护流程执行 Migrator、部署配套版本及旧资源兼容接续。采集定时仍停用。
5. 按完整性预检 → 候选入库 → 分块 → 本地基准 → 断点向量构建 → 核验/内容激活完成两个新库。报告真实 counts/hashes/关联解析和失败记录；首次资源发布及角色授权单独走管理流程，不用旧 Job 验收新增能力。
6. 在能访问真实 ONES 的环境配置受管采集身份，显式单次扫描验收新建、旧项修改、分页截断、401/403/5xx 和重放，再显式开启每小时调度。当前本机不自动开启。
7. 回退首先禁用同步并中止候选激活，保留当前可用资源/索引和数据；需要切回上一成功版本时按正常验证及当前安全状态执行，不回退 DDL、不修改历史修订或复活已撤销权限。

## Open Questions

- 已解决：三个独立 KB、3600 秒周期、默认停用、验证后自动换版、不改业务授权。
- 目标 ONES 的更新时间筛选、排序、分页完整性和权威删除合同目前没有真实证据。首版保持完整扫描及不推断删除，未来启用优化必须单独验收，不阻塞本地离线处理。
- 真实采集环境、受管凭据、项目/类型 UUID 配置与未来正式启用时间由部署时提供；本轮不索取明文密码/Token，也不读取临时脚本的真实认证值。
- 工单/Story 原文含义与召回质量需要人工样例评测；结构预检和向量就绪不作为业务效果达标证据。
