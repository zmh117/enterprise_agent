## Why

用户希望把本地全部工单和 Story 接入既有 PostgreSQL → 清洗分块 → 本地 Embedding → Qdrant → Knowledge MCP 链路，并在可访问 ONES 的环境每小时同步缺陷、工单和 Story。当前导入、分块和索引仍限定 defect，导出工具也不是可靠的增量同步器；直接定时运行会漏掉旧工作项修改，并可能让已发布知识资源失效。

## What Changes

2026-09-23 用户调整：旧格式测试内容无需迁移，改用“最近2000_保留ID”替换三类 KB 当前内容，并验证 BM25＋本地 BGE-M3 混合召回。数量预期为 2000/2000/8654（需求包括 2000 Story 和 6654 子任务）；保留 KB/资源/授权身份，旧内容不混入新索引。下列原输入数量与旧缺陷不重建要求仅记录初始范围，本次按 design 的同日确认节执行。定时采集仍停用，评论和 OCR 不扩围。

- 保留现有缺陷知识库，新增工单、Story 两个独立逻辑知识库，共用 `knowledge` schema 和稳定来源工作项身份，保留跨类型关联。Story 映射现有 `requirement` 分类，保留原始类型身份和显示值，不新增同义类型。
- 用户确认将 `全部story` 中的 Story、Sub-task、演示子任务全部收录需求知识库，粗粒度 document_kind 为 requirement，保留各自真实来源子类型，不把子任务改称 Story。
- 先预检用户指定的两个本地详情/list 导出，再分阶段显式入库、分块、基准测试和构建向量；不下载图片/附件、不做 OCR、不外发 Embedding 文本。当前文件初步统计为工单 4820 条、Story 17388 条，正式执行前重新校验文件摘要及完整性。
- 扩展类型与缺少正文的处理，工单/Story 允许有效标题的短文本记录并标记完整性，不为凑字段伪造问题、解决方案或验收标准；保持既有缺陷身份/profile/hash 兼容。
- 基于指定导出工具的分页、详情和字段映射逻辑实现受管采集适配器；不原样执行含字面量认证头、关闭 TLS 校验、按 UUID 永久跳过的临时脚本。增加可恢复批次、完整性校验、可靠更新发现和幂等阶段处理。
- 新增可选知识同步运行入口，每 3600 秒调度、默认停用；本机只准备和验证能力，不连接真实 ONES、不启用定时任务。运行状态保存在 PostgreSQL，不依赖聊天会话或助手定时器。
- 用户已确认：新内容和索引完整校验通过后自动切换同一知识库的检索版本；失败保留上一可用版本。为此隔离候选修订/索引与当前可用事实，按 KB 计算摘要，原子激活，不原地改写已发布修订或复用失效验证。
- **行为变更**：对显式启用同步的知识库，新增内容更新的受控自动换版，不再要求每小时手工发布；初次资源启用和角色/应用授权仍须显式配置。采集身份不替代查询用户的 ONES 可读权限，不修改业务 Tool Snapshot、角色或应用 Publication。

## Capabilities

### New Capabilities

无新增顶层领域；沿用现有 canonical 领域。

### Modified Capabilities

- `platform-operations`：多类型离线入库、类型化分块、增量向量构建、默认停用的每小时同步、迁移与正式执行验收。
- `builtin-tool-resource`：KB 级内容版本隔离、验证后自动换版、失败保留当前版本、MCP 单调用版本与双权限边界。

## Impact

- 修改 `backend/app/modules/knowledge/` 对应 domain/application/infrastructure 及 CLI，保持现有 DDD 分层；新增当前用例需要的同步状态和候选修订持久化，不引入通用工作流/调度平台。
- 扩展 `knowledge/` 可选部署单元与运维手册，不让其他环境必须部署采集器；现有 MCP 仍只有目录和检索两个只读工具。
- 必要 DDL 通过新的前向 Migrator、双引擎 catalog 和测试交付；不修改历史迁移、重键既有缺陷或清空现有向量。正式数据操作与原始输入均留在本机受控边界。
- 新增测试纳入 `backend/tests/test_suite_tiers.toml`，区分合成/数据库/本地 Embedding 与真实 ONES、模型、人工质量证据。
- 依赖当前代码已实现、尚未全部同步到 canonical 的清洗分块、本地索引和 `enable-governed-knowledge-retrieval` 合同；本提案相对于 canonical 增量表达，不替这些 change 同步/归档或补勾真实验收。实施前核对其接口及迁移头，处理冲突后再动正式数据。
