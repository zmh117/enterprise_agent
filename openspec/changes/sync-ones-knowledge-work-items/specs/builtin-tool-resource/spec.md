## ADDED Requirements

### Requirement: 知识混合召回必须保持相同版本与授权边界
新版索引 SHALL 同时提供 BM25 sparse 和本地 BGE-M3 dense，默认每路最多 100 点并等权 RRF 融合；MUST 在同一已发布 KB/index 范围读取，两路文本处理配置 MUST 版本化且与构建一致。缺少任一路或配置不符 MUST 明确失败，不伪称混合成功。融合后 MUST 验证引用、按工作项聚合并执行当前本人 ONES 可读校验，保持最长 120 秒和现有工具权限。

#### Scenario: 混合候选来自未授权工作项
- **WHEN** 词法或语义通道命中当前用户不可读内容
- **THEN** 不向用户或模型返回该工作项引用、分数或内容，不使用采集身份绕过权限

### Requirement: 知识资源内容摘要必须按所选知识库隔离
知识资源 SHALL 基于所选 KB 的冻结成员、内容修订、分类、profile、连接身份和索引计算版本化配置摘要，MUST NOT 因同 source 其他 KB 的无关内容变化而失效。既有 source 级摘要版本 MUST 保留验证语义，不得原地改写历史 hash 或静默跳过完整性检查。新增同源类型之前，维护流程 MUST 枚举所有受影响旧发布并显式完成兼容接续：保留原 KB/索引/连接/权限，独立验证后创建新的 KB 范围资源修订；未知版本、未授权维护资源或并发冲突 MUST 阻止正式入库。DDL MUST NOT 自动发布资源。

#### Scenario: 工单增加不影响缺陷发布
- **WHEN** 缺陷资源已完成 KB 范围摘要接续，同 source 新增工单或 Story
- **THEN** 缺陷当前配置与索引仍可独立验证，无需重编码缺陷或重新授予访问权限

#### Scenario: 存在未接续的同源旧资源
- **WHEN** 正式多类型导入预检发现另一个仍依赖 source 级摘要的发布，且未在批准维护范围
- **THEN** 停止正式入库并报告受影响资源，不偷偷改变其摘要、发布或可用状态

### Requirement: 自动知识换版必须显式绑定且只更新内容版本
系统 SHALL 允许管理员为指定知识资源启用完整验证后的自动内容换版，绑定 MUST 固定 resource/KB、当前连接、凭据引用、模型/profile 与配置修订。同步 MUST NOT 自动首次发布新资源、授予角色、修改应用/Agent Publication 或 Tool Snapshot，MUST NOT 自动启用停用或归档资源，亦 MUST NOT 覆盖管理员手工草稿。连接、凭据引用或 profile 变化 MUST 经过新的显式配置与验证。

#### Scenario: 新工单知识库完成首批索引
- **WHEN** 工单 KB 已完成内容激活和 READY 向量索引，但未显式发布或授权
- **THEN** 后台报告索引就绪；Agent 不能因此自动发现或读取该 KB，首次资源发布与应用内角色授权仍由管理员执行

#### Scenario: 已授权知识库定时更新
- **WHEN** 同步绑定保持不变且新内容和索引全部验证通过
- **THEN** 系统创建新不可变知识资源修订并切换同一资源的发布指针，不修改其角色/应用范围或模型工具目录

#### Scenario: 管理员并发编辑或停用
- **WHEN** 构建期间管理员创建草稿、停用资源、归档资源或变更连接/profile
- **THEN** 自动激活的期望修订核对失败并保留候选，不覆盖管理员操作、不恢复已撤销权限

### Requirement: 知识候选激活必须保持可用版本原子一致
自动激活 MUST 在候选 Qdrant 代际完成独立校验后，以同平台 PostgreSQL 的短事务同时校验并更新当前内容修订、分类/成员、当前关系视图、新资源修订与发布指针、运行激活水位。事务 MUST 核验来源绑定与资源配置修订、基线内容、启用状态及候选验证摘要；同批类型迁移影响的 KB 和资源 MUST 一起成功或一起回滚。外部向量构建 MUST 发生在事务之外且 MUST NOT 原地覆盖活跃 collection。

任何构建、校验或事务失败 MUST 保留上一个可用内容/索引组合；这不构成对当前停用状态或已撤销权限的回退。成功提交后重复执行 MUST 幂等识别已激活事实，不创建重复发布。完整空代际 SHALL 与非空代际使用相同原子激活边界。

#### Scenario: 向量准备成功但发布事务失败
- **WHEN** Qdrant 候选已完整而 PostgreSQL 激活发生并发冲突或失败
- **THEN** 当前可用内容和资源不变；候选保持未引用且可恢复，不留下半数 KB 已切换的状态

#### Scenario: 激活提交后 worker 崩溃
- **WHEN** 同一运行已提交内容与发布事务但尚未向调用方返回成功
- **THEN** 重启从持久激活事实识别成功，不重新发布、不倒退水位或重编码

#### Scenario: 原知识库成为空库
- **WHEN** 完整校验的空成员代际被激活
- **THEN** 已授权用户查询该 KB 获得空命中而非上代成员，不能以保留上一代为由绕过当前成员关系

### Requirement: 同步后的 Knowledge MCP 必须保持本人授权和单次版本边界
Knowledge MCP SHALL 继续仅提供目录与检索的只读能力，按当前业务应用内角色 KB 范围与当前用户 ONES 可读权限双重核验；采集服务身份 MUST NOT 替代查询用户身份。每次检索 MUST 固定已发布资源修订/索引并在返回前核验当前授权和版本，MUST NOT 混合两代结果、回退未发布候选或将 Provider 失败解释为无缺陷。同步写入与后台编码 MUST NOT 进入在线检索请求，MUST 保持已有最长 120 秒调用预算，不通过本变更增加模型工具权限或解除回源限制。

#### Scenario: 采集账号可读但用户不可读
- **WHEN** 候选来自拥有更广范围的采集身份，而调用用户没有对应 KB 授权或本人 ONES 可读权限
- **THEN** MCP 不返回该工作项的标题、摘要、分数或引用，不暴露采集身份作为替代凭据

#### Scenario: 检索过程中发布版本切换
- **WHEN** 检索开始固定旧发布，而返回前已激活新发布
- **THEN** 本次请求安全失败并提示重试，不拼接新旧语料；后续请求使用新发布和当前权限

#### Scenario: 本地模拟验收通过
- **WHEN** 合成 Provider、实际本地数据与本地 Embedding/Qdrant 的链路测试通过
- **THEN** 报告分别说明各类证据，不宣称真实 ONES 采集合同、本人可读性或业务召回质量已完成验收
