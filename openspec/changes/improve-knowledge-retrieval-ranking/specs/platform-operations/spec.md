## ADDED Requirements

### Requirement: 本地知识重排服务必须使用固定且可验证的模型
系统 SHALL 通过固定本地重排服务提供 query/document 配对评分，模型、tokenizer、revision、文件摘要、dtype、架构依赖及输入/排序参数 MUST 纳入可验证 ranking profile。模型准备 SHALL 是显式运维步骤，运行服务 MUST 离线加载只读模型文件、限制网络与资源，不接受 Agent/Job 请求覆盖模型、地址或任意代码。重排 SHALL 作为查询时派生计算复用现有索引，不修改 embedding/chunk profile、不重建 collection、不改写知识资源发布或同步状态。

#### Scenario: 固定模型准备完成
- **WHEN** 运维显式准备固定模型且文件及运行 profile 校验通过
- **THEN** 重排服务可以加载只读模型并报告对应 profile 就绪，模型准备本身不授予工具/知识库权限

#### Scenario: 模型或运行依赖漂移
- **WHEN** revision、文件摘要、架构锁或服务 profile 与代码固定值不一致
- **THEN** 服务不报告可用重排能力，调用返回稳定依赖错误，不自动下载替代文件或使用其他模型

#### Scenario: 接入既有知识部署
- **WHEN** 运维部署新排序服务与 Knowledge MCP
- **THEN** 使用现有知识 Compose 边界和内部网络，模型进程没有宿主机公开端口、ONES 凭据或平台主密钥
- **AND** 现有文档、collection、资源发布身份与小时同步保持不变

### Requirement: 知识重排的输入排队推理必须有界并继承截止时间
重排服务 MUST 限制单请求最多 50 文档、每文档最多两个候选块、请求体最多 1 MiB、文档窗口最多 1024 token、配对总长最多 4096 token，以及微批最多 8 对且总 token 最多 8192；token 计数使用固定重排 tokenizer。query MUST 完整保留，文档窗口还须受配对剩余空间限制；没有有效文档空间时返回明确输入上限错误。在线推理 SHALL 最多一个执行和三个等待，排队、分批推理及收尾 MUST 共用传入截止时间与当前 Job 剩余预算，不重新获得 360 秒。请求取消或超时 MUST 终止后续微批，实际正在计算的微批结束前不得释放执行槽位。服务 MUST 校验输出数量、对应关系、有限分数和 profile，不回显文本，不记录原始输入或异常。

#### Scenario: 多个请求同时到达
- **WHEN** 一个请求执行中且已有三个请求等待
- **THEN** 新请求返回明确 busy 错误，不扩大队列或开启额外模型执行线程

#### Scenario: 请求在等待时预算耗尽
- **WHEN** 请求等待期间到达原始截止时间
- **THEN** 移除等待项并返回超时，不进入模型推理，也不获得新的推理预算

#### Scenario: 计算中的请求被取消
- **WHEN** 请求断连或超时而一个微批仍在执行
- **THEN** 停止后续微批，当前执行槽位直到实际计算退出才释放，禁止超额并发

#### Scenario: query 占满配对窗口
- **WHEN** 完整 query 与特殊 token 已无法为文档留下有效输入空间
- **THEN** 返回稳定输入上限错误，不静默截断 query 后继续评分

#### Scenario: 模型返回非法结果
- **WHEN** 返回项数不匹配、分数非有限数值或 profile 不匹配
- **THEN** Knowledge MCP 返回稳定重排依赖失败，不返回空命中、不静默使用原排序

### Requirement: 知识检索对照评测必须使用相同候选和实际模式
系统 SHALL 扩展既有离线评测入口，以一次查询产生的相同当前候选快照计算基线与重排结果，复用在线的 200 点召回、文档去重、前 50 文档选择、输入窗口及排序实现。报告 MUST 标明实际 dense / hybrid_rrf 召回及基线/重排方法，绑定数据集、代码、模型/profile、索引和实际候选修订摘要；所有标签在查询前校验有效，比较期间发生候选内容或相关版本漂移 MUST 使比较无效。评测 SHALL 分别报告候选覆盖、前 50 截断后的覆盖、Recall@5/10/20、MRR@10、Hit@3、阶段耗时、截断和失败；故障不得从有答案样本分母中静默移除。

#### Scenario: 混合索引对照评测
- **WHEN** auto 实际选择 hybrid_rrf
- **THEN** 报告标记实际模式，不再固定声称 offline_dense；基线和重排消费同一候选及文本快照

#### Scenario: 正确文档没有进入重排池
- **WHEN** 人工标注正例不在 200 点去重结果或未进入前 50 文档
- **THEN** 报告区分召回未命中与候选截断，不把它归为重排位置错误或更换标题查询掩盖

#### Scenario: 增量索引身份未变但内容改变
- **WHEN** collection/index 身份相同而本次候选文档修订或块 hash 已变化
- **THEN** 比较不再被视为同候选有效对照，不能仅因索引身份相同报告可比较收益

#### Scenario: 有答案问题遇到重排故障
- **WHEN** 某个有答案样本无法完成重排
- **THEN** 相应效果指标计失败且为零，另报固定故障类别，不删去该样本提高均值

#### Scenario: 无答案问题返回候选
- **WHEN** 无答案标注样本仍有检索结果
- **THEN** 报告该次候选返回事实，不将其直接称为 Agent 回答误报，也不把依赖失败算作正确拒答

### Requirement: 检索质量发布验收必须区分离线排序与真实回答
调优 SHALL 使用人工复核的独立自然问法与明确相关标签，覆盖复合症状、同义表达、相似干扰、长文本、跨项目和无答案；调参与验收问题 MUST 按问题/关联事项分组隔离，原文标题自查询与合成夹具不得替代自然问法质量验收。候选排名目标、冻结集基线比较规则以及目标硬件、负载和时延预算 MUST 在目标验收前固定，失败后不得静默放宽。真实模型离线、目标容器与真实 ONES / Agent 端到端证据 MUST 分别记录，未取得证据的任务保持未完成。真实业务原文、凭据和历史原始会话 MUST NOT 自动复制到仓库夹具、规范或普通日志，评测普通输出仅允许安全汇总、hash、耗时和固定失败码。

#### Scenario: 仅合成协议测试通过
- **WHEN** 单元测试和模拟推理/Provider 验证通过
- **THEN** 只能报告本地逻辑/协议证据，不勾选真实模型效果、CPU 性能或 ONES 端到端验收

#### Scenario: 冻结集质量或目标延迟不达标
- **WHEN** 前列排序质量、召回保持要求或预先固定的目标环境时延条件失败
- **THEN** 保留失败结论并暂停新排序的发布验收，不通过更换标题问法、删除失败样本或事后放宽门槛报告通过

#### Scenario: Agent 以相似机制作确定性回答
- **WHEN** 排序指标改善，但真实 Agent 在无答案或仅同族机制场景中作出没有证据的根因结论
- **THEN** 回答质量验收仍不通过，不能用排序指标代替证据核实验收

#### Scenario: 工具输出合同协调部署
- **WHEN** 新版知识检索输出及合同版本准备上线
- **THEN** 协调 MCP / Runtime / 发布快照，旧任务按既有规则排空或拒绝不匹配，新 Publication / Job 完成真实核实后才能声明端到端通过
- **AND** 回退恢复相互匹配的服务与工具发布，保留知识数据，不在同一新合同下隐藏切回旧排序
