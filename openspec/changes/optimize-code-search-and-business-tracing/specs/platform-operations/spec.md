## ADDED Requirements

### Requirement: 代码报错解释必须追踪实际业务判断
代码问答 Skill SHALL 从精确提示定位错误符号，再查实际引用、条件/状态定义、动作先后和相关入口。找到多个行为不同的入口后才据此请求用户消歧。仅有文案或枚举定义 MUST NOT 支持触发条件、状态流转、事务或前端展示链的确定结论；每个 claim 必须与实际 Read 证据的能力相符。重复拒绝或无进展搜索必须调整计划，敏感阻断不得绕过；关键链未核验则保存 partial 而非 supported。

#### Scenario: 只找到公共错误文案
- **WHEN** 已定位统一错误表，但没有读取具体抛错分支
- **THEN** 只确认文案来源，说明业务判断尚未核验，不宣称已确认允许/禁止状态及动作影响

#### Scenario: 拆批质量状态判断
- **WHEN** 已读取实际拆批判断及关联状态定义
- **THEN** 解释实际允许/禁止状态、配置例外与已核实的动作顺序，注明环境和数字 SVN 版本；缺少事务或入口证据时保留对应未知

#### Scenario: 发布与现场验证
- **WHEN** 更新源码搜索实现和版本化 Skill
- **THEN** 同步 Prompt 合同与 Runtime，通过现有发布流程仅切换获授权应用；本地合成/版本测试不得冒充另一环境的指定 SVN 版本验收
