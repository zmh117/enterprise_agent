## Context

当前 Grep 在读取前因 64 候选/10000 枚举直接失败；原生工具参数多于源码守卫支持集。原生 Grep 已通过临时规范化文本展示原路径，不是源码证据；Read 负责证据。用户要求先更新方案再实现与发布，保留敏感保护。

## Goals / Non-Goals

目标：一次搜索跨多个安全批次、能说明覆盖缺口；常见参数可安全归一化；业务回答追踪实际判断。非目标：开放 Shell、关闭敏感规则、引入 Graphify/图数据库、变更 SVN grant 或自动更新源码。

## Decisions

1. 保留原生 Grep：宿主分页枚举已跟踪、授权范围内的文件，按 glob/type 过滤；每批最多 32 文件/8 MiB。宿主固定调用 ripgrep 的 files-with-matches 模式筛选，立即删除未命中副本，至多保留 32 命中文件/32 MiB 给原生 Grep 展示。单次扫描预算为 256 MiB、100000 元数据项和 30 秒；命中上限或预算用尽是显式不完整结果，不是伪零命中。匹配率高时返回已有命中和最后安全路径，要求缩小搜索；不引入跨 Job 游标或持久索引。
2. ripgrep 是 Linux Runtime 镜像中的固定依赖，命令禁用配置与隐式忽略、限制线程，只接受固定旗标、已验证正则和宿主生成缓存路径；不提供 Bash 给 Agent。文件先经过完整性/编码/敏感检查再交给搜索。缓存仍受 Sandbox 文件槽与容量约束、单 Job 串行准备，失败/取消/终态清理。
3. 父目录可作为搜索范围，但枚举必须过滤到 grant 的实际子路径，不能获得父目录文件读取权限。无权限的相邻路径保持拒绝。
4. 支持常见 type（cpp/c/vue/js/ts 等）与有限简单扩展名花括号展开；head_limit 和上下文超上限只向下收紧并报告。未知字段、无效模式、危险路径仍拒绝，用固定字段和修正提示，不回显用户任意值；正则语法错误也返回可调整提示。
5. Skill 以错误符号引用驱动追踪，读取真实判断/状态定义/动作顺序，多个入口确有歧义再询问。只找到文案只能报告文案来源，不能宣称触发逻辑已核实。敏感拒绝后不能换工具绕过；记录缺口，允许其他独立证据。
6. 更新 Prompt 版本和版本化 Skill。通过应用服务发布，保留其他应用绑定；容器更新前确认无在途任务，不能只重启而造成版本漂移。

## Risks / Trade-offs

- 内部筛选与原生 Grep 两次匹配 → 使用同类 ripgrep 默认正则语义和相同大小写选项；筛选仅导航，Read 仍重新核实。
- 高命中率/超大工程 → 返回 bounded/partial 和安全范围提示，不能无限扫全仓；合成测试覆盖命中位于第 65 文件及第 10001 元数据项之后。
- 敏感文件仍可能阻止某条调用链 → 保留明确未知，不以改文案假装效果提升；本轮不实施局部敏感文件放行。
- 原问题在另一部署环境 → 本机仅验证本地可用版本与合成拆批案例，原 test2/r52422 待现场验证。

## Migration Plan

无数据库迁移。测试后构建并更新 Runtime 及 Prompt 合同调用方；发布 code-business-query 新 Agent 版本，仅切换 assist03。记录有效版本、健康状态、测试与真实任务证据。发布失败保持原绑定，不改变权限或其他应用。


## 本地验收补充

真实源码宽泛搜索遇到超 15 MiB 的依赖文件时，底层文件守卫返回 `code_source_file_size_or_type`。Grep 将此类不可读项与非文本项一起跳过，报告不完整且不展示路径，继续后续批次；直接 Read 仍拒绝。文件变化、身份不匹配、路径逃逸和读取异常仍中止，不将其当作零命中。
