## Context

当前检出按所选文件/目录创建固定版本稀疏工作副本，统一持有管理操作写占用。清单已经按选择读取，但 `external_declarations` 从仓库地址根递归查询；所有只读命令的硬时限都是 60 秒。Windows 用户报告混合勾选后约一分钟失败，与该时限一致，无法从旧错误码判断具体命令。

## Goals / Non-Goals

目标：检查实际要物化的内容，给予批量元数据读取合理的有界时间，并准确报告失败阶段。

本次不新增异步架构或配置层，不放宽字节/文件数/磁盘配额，不支持自动拉取 externals，不自动重试写操作，不调整已发布 Runtime 工具或回答索引。

## Decisions

1. `external_declarations` 接收经校验的可选相对路径。初次检出根据固定版本的 info 类型，只查询每个所选目录的递归属性；所选文件无需扫描其父目录。更新时按目标版本确认选中项类型再检查目录，避免文件在目标版本变成目录时漏检。稀疏祖先不是选中范围，不查询其未选子树，所有写命令继续 `--ignore-externals`。选中范围存在声明仍拒绝，不能按声明访问外部 URL。
2. `_run` 提供内部命令超时参数，默认 60 秒。递归 inventory、externals、工作副本 status/info 明确传共享常量 300 秒。普通 info、目录按层浏览、历史查询等保持 60 秒。没有对管理员或模型开放任意参数；每秒取消检查与原操作 deadline/heartbeat 继续限制总时长。
3. 沿用上一轮未提交的失败分类修复：超时错误包含固定操作名；启动阶段与启动后的 I/O 区分，页面用中文显示。停止并 wait 子进程后才能落失败状态，不持久化原始命令、stderr 或凭据。旧失败记录保持原样。

## Risks / Trade-offs

- 单个大型选中目录仍可能超过 300 秒或原 8 MiB/XML、文件数、磁盘限额；明确报错并缩小范围，不能无限增大缓冲或伪装完整成功。
- 每个命令变长不等于重置总期限；管理检出仍受原 1800 秒截止，问答来源操作继续受自己的授权/截止限制。
- 历史 `code_svn_unavailable` 无法补回丢失的原因。实际部署仍需新操作验证，此次不能声称现场已恢复。

## Migration Plan

本机合成测试和真实隔离 SVN 通过后更新部署说明；无数据库迁移。目标机器更新源代码后构建 knowledge-sync、admin-web，等待现有 SVN 写操作结束再应用镜像。需要回退时停止新任务并确认执行结束后恢复旧镜像；不改写、删除或重试原失败目录。
