## Context

当前 `ClaudeSdkClient` 与固定 MCP 客户端直接传 `max_turns=context.max_turns`，工具总预算由权限回调和源码 hook 处理。SDK 0.2.178 会将同一模型响应拆成多个 AssistantMessage；这些分块共享 message_id，不能逐消息或逐工具扣轮次。已有实际模型调用与工具审计必须保留。

## Goals / Non-Goals

目标：文件取证工具免计任务轮次，混合工具不绕过上限，耗尽不重试。无需新增可配置排除列表、数据库表或独立 Agent；不提高用户配置的超时与工具总上限。

## Decisions

1. 仅原生且在冻结可用集合中的 Read、Glob、Grep 可免计。只包含这些工具的模型响应免计一轮；混合其他工具、纯文字最终答复均计一次。相同 message_id 的文本、思考和工具分块合并；不能把工具次数从 SDK num_turns 中相减。无法可靠识别响应身份时不授予免计。
2. 使用 Runtime 本地轮次预算，观测模型响应后登记工具调用 ID。工具前置 hook 等待对应消息完成预算判定，防止 SDK 的并发处理让超限的非文件工具先执行；只保存 ID、工具名与计数。已有源码授权和普通文件权限回调继续独立检查。
3. 有文件工具时 SDK 兜底上限为 max_turns + max_tool_calls；每个免计轮次至少有一个工具请求，且全部工具仍受统一总上限，因此无需无限放开 SDK。无文件工具、模型连接 probe 沿用原 SDK 上限。原生工具被自动批准时也必须经过预算前置 hook，不能依赖 can_use_tool 一定会被调用。
4. 普通 max_turns 继续表达任务计入预算的轮次，不改 DB 字段。运行审计 usage 中增加仅含标量的 turn_budget 统计（真实观测、计入预算、免计、未结束轮次、SDK 兜底上限）。原有真实模型轮次和工具次数保持原义。
5. 使用稳定 max_turns_exhausted / NEVER。任何工具总上限、超时和取消继续独立硬停止；禁止通过重开 SDK 会话重置预算。宿主提前终止时显式关闭 SDK 异步生成器，结束子进程并释放 hook，不等待垃圾回收。若工具调用无法与 SDK 消息关联，有限等待后不可重试停止，不放行未知调用。

## Risks / Trade-offs

- 免计不会减少真实 Token 与耗时 → 审计保留真实统计，工具总上限与超时不变。
- SDK 消息分块与工具回调并发 → 按 message_id 合并、按 tool_use_id 关联，覆盖混合工具、重复分块、拒绝和先到 hook 的测试。
- 未暴露可靠响应身份 → 保守计入预算，不能猜测免计。
- 旧任务不能更改冻结事实 → 不回写历史 Job；协调更新节点，运行中先排空。

## Migration Plan

无需数据迁移。通过单元、SDK/Worker 合成链路与静态检查后，构建并排空更新两个 Runtime；保留原镜像供回退。检查节点代码摘要、READY 和提示词一致，不发起真实模型业务任务。按用户此次明确要求同步 execution-delivery 的计数口径。
