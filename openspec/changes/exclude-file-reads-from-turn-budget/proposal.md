## Why

源码分析需要多次 Grep、Glob、Read，当前将 Job 的 max_turns 直接传给 SDK，会让这些取证轮次提前耗尽任务预算。用户要求保留全部工具审计，但让这三类工具不消耗任务轮次。

## What Changes

- **BREAKING** max_turns 改为宿主计入预算的轮次上限：同一模型响应只包含原生 Grep、Glob、Read 工具时免计；包含其他工具或没有工具的响应计一次。相同模型响应的分块不得重复计数。
- 工具审计、真实模型调用数与 Token 继续完整记录；工具总次数及墙钟限制保持生效，拒绝/失败的工具调用也受总次数限制。
- Runtime 负责计入预算的轮次，SDK 保留由轮次上限和工具总上限推导出的有限兜底上限；预算耗尽停止同一执行，不自动重试。
- 保留安全的轮次预算统计，区分实际观测轮次、免计轮次与计入预算的轮次，不持久化源码或业务正文。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `execution-delivery`: 执行策略轮次语义、受控工具边界与执行审计。

## Impact

涉及 Python Runtime 消息处理、工具前置守卫、选项构造和运行审计，以及相关回归测试。无需新增数据库表、服务或模型依赖；不修改已有工具授权、源码读取范围及历史任务记录。两个 Runtime 协调更新，继续保留上一轮修复的不可重试分类。
