# SVN 原文结果的瞬时传输

状态：2026-11-09 用户已确认采用；纳入本变更实施合同，尚未完成接线或部署。

## 已核对的问题

`knowledge-sync` 当前是后台 Worker，没有提供结果读取 HTTP 端点。现有检出流程把结果写入 PostgreSQL 的 `result_json`，控制面再从数据库返回给调用者。新的 `code_svn_operation.result_json` 合同明确只允许有界元数据和摘要，不允许持久化原始 diff、源码或提交消息。

因此不能直接复用旧结果落库方式实现 `knowledge_svn_diff(mode=text)` 或带提交说明的 log；只有新增一个瞬时传输通道，才能同时满足“CLI 在 knowledge-sync 执行”和“不把原文写入数据库”。现有提案列出了调用链，但没有规定该通道的拥有者、认证和恢复行为。

## 已确认补充

在现有 `knowledge-sync` 容器内增加一个仅项目内部网络可达的窄 HTTP 结果端点，不增加容器，不新增面向 Agent 的 MCP 服务。对外仍由 `knowledge-mcp` 提供现有计划中的工具。

调用链：Runtime → knowledge-mcp → API 控制面（当前身份/来源/占用/截止核验）→ knowledge-sync 内部结果端点。

- 操作准入、幂等和执行状态仍在 PG；端点只接收已准入 `operation_id` 及当前执行代次，不接受命令串、路径、URL、凭据或新的查询参数。
- 使用现有服务凭据机制，只向控制面配置读取权限；Runtime 不获得此服务凭据。禁止宿主端口发布、Cookie/浏览器来源和任意 URL 转发。
- Worker 生成的原文响应只存有界进程内缓冲，单响应不超过 512 KiB，总缓冲不超过 8 MiB；有效期不超过原 Job 剩余时间及 60 秒。超限返回固定错误，不落盘、入库或写普通日志。
- PG 仅保留操作参数、固定版本、范围、计数、响应摘要和停止证明。控制面返回原文前再次验证原 Job/发布/权限/占用/代次，取消或撤权立即拒绝读取。
- 内存结果过期或 Worker 重启时，update 不重放。历史只读请求可在原截止及权限仍有效时重取同一固定请求；若观察结果摘要变化（如 SVN revision 属性被修改），返回 `CODE_HISTORY_RESULT_CHANGED`，不能把新结果冒充旧证据。需要新证据时显式发起新操作。
- 不以响应到期、请求断开或 Worker 租约过期作为实际进程停止证明，目录读写协调保持原合同。

本补充不恢复源码快照，不建立 File Service 源码副本；Runtime 继续从原检出目录的只读挂载分析文件。

## 补充验收

验证原文不进入 PG/普通日志；只有原授权 Job 可取结果；撤权/取消/过期和错误代次拒绝；Worker 重启不能重复 update；固定只读请求重取时摘要变化拒绝；缓冲容量和截止生效。三平台仍运行相同 Linux 容器内部通道。

Runtime 的代码分析会话同时关闭 SDK session persistence 与 prompt history；只限制 Worker 缓冲不足以保证原文不落盘。实际 CLI 验证覆盖 Read 返回原文、hook 替换内容和阻断结果，检查独立配置目录不产生会话转录。平台仍保留不含原文的初始化、工具和版本审计。

管理页面的目录预览不含源码或提交正文，允许最多 2 MiB 的固定字段路径清单，仍受总内存 8 MiB、60 秒过期和管理员权限约束。只有管理 browse 分支启用该限额；问答 SVN 原文维持单响应 512 KiB。两端校验目录预览结构，不能以该标记传递 diff 或任意正文。
