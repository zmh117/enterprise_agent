## Context

现有 Codec 将位置、请求指纹、资源状态及上下文绑定编码成长字符串。校验正确，但模型在续页时复制错误。审计正文可能截断；进程内字典不能跨实例或重启，因此不能作为可靠状态源。

## Goals / Non-Goals

目标：Schema 续页只传短引用；程序恢复精确原始值；安全校验、分页预算和每页授权保持。

非目标：不自动扫描全部目录，不提高 50 张表上限，不修改其他分页工具，不模糊修补错误游标，不修改模型、授权或业务数据。

## Decisions

- 在 ReadOnlyToolService 边界替换 Schema 的输入/输出 cursor；底层 Codec 与 Provider 不改变。模型仍用 `cursor` 和 `next_cursor`，无新增调用参数。
- 新增 `mcp_schema_pagination_cursor` 表，主键为 Job 与随机 16 位十六进制引用，外部形态 `pg_` 加引用。保存原始有界游标及创建/到期时间，不保存表内容、连接配置或认证材料。
- 引用不是授权凭据。恢复前验证当前 Job/调用授权，恢复后仍经原 Codec 校验上下文、目标、query、资源版本。未知、跨 Job、损坏引用不猜测、不回退第一页。
- 旧长游标继续经原 Codec 校验；新成功分页必须返回短引用。存储不可用失败关闭，不返回伪造成功或静默退回长游标。
- 状态保存 24 小时，覆盖最大单次运行时间及重试窗口；只允许 RUNNING Job 使用。tool-mcp 启动/运行期间每分钟有界清理已过期记录；Job 删除级联清理。状态插入和清理不跨业务 Provider 网络调用持有事务。
- 不引入新缓存服务或通用 KV 框架。复用平台数据库，迁移按当前 134 之后追加 135，保护知识库现有更改。

## Risks / Trade-offs

- 短标识仍可能被模型抄错 → 缩短传参长度但保留精确校验，不声称彻底消除模型错误。
- 临时状态过期或丢失 → 稳定错误提示从第一页重查，不隐式重复查询或混合结果。
- 新表需升级平台 schema → 跟随既有 migrator 和 readiness；不直接修改用户现有数据库。
- 本机 Mock 通过不代表远端修复 → Windows 环境重新部署后使用新 Job 验收完整多页结果。

## Migration Plan

追加迁移及事实源登记，现有实例执行正常迁移，新安装全链应用；已有 Job 的长游标仍可使用。重建并部署一致版本的 tool-mcp 与依赖 schema 的服务，不修改历史发布/Job。无破坏性回滚；旧代码可忽略新表，但版本就绪规则仍按部署版本执行。
