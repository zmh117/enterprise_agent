## Context

当前下载前 list/propget、下载进度、下载后 verbose status 与 depth-infinity info 都整体缓存；元数据或进度超过 8 MiB 失败，stderr 超过 64 KiB 也使用同一错误。下载异常会尝试删除目录，后置检查失败保留目录但不能恢复。现有 inspect 不能单独证明中断后的稀疏范围完整。

## Goals / Non-Goals

**Goals:** 大工程输出有界处理、明确阶段、保留下载、重新校验完整工作副本后复用。

**Non-Goals:** 不做断点续传，不自动 update/cleanup/revert，不导入任意宿主目录，不跳过证书/权限/来源检查，不根据目录体积判定成功。

## Decisions

- 下载命令使用 quiet，仍持续排空 stdout/stderr；不缓存进度正文。stderr 只保留有界数字 SVN 错误号与累计字节数，不能仅因警告超过 64 KiB 把成功命令判成失败。原查询文本与浏览响应上限保持独立。
- 增加受控 XML 流式解析，仅保留当前记录和必要的有界路径集合。递归元数据单命令最多 256 MiB，未完成单记录窗口最多 256 KiB、深度最多 32，拒绝 DTD/entity、非法编码、截断 XML；清单最多 100000 条，工程仍最多 20 GiB，空间按 3 倍文件大小加 512 MiB 预留。持续检查取消、原截止与独立心跳。
- 清单、属性、status/info 都采用流式路径。正常目录预览保持单层读取。完整性验证对比远端目标版本所选范围与本地版本化条目，并核实选中目录及后代的 infinity 深度、普通文件、来源/版本、缺失/修改/冲突/切换/外部引用和路径安全，不能仅用 SVN 命令退出成功或磁盘大小判断完整。
- 新建目录独占创建、空工作副本建立后（下载所选文件前）建立持久身份并绑定任务，失败保留目录且 checkout=invalid。新的“重新校验”操作引用原失败操作，不接收任意路径、版本或连接替换。复用 checkout/operation 表，operation_kind 仍为 checkout，request 增加 verification_only 和原操作 ID；不增加数据库状态或迁移。
- 只允许同知识资源最近一次、已真正停止的失败检出；重新检查当前管理权限、连接指纹、资源与原来源，取得现有独占写占用和本地执行锁，推进 generation。任何仍在读/写的任务都不能被抢占。重复同 request_key 返回同一任务；ready 目录不能被旧失败任务重置。
- 历史失败目录没有已记录物理身份时，仅允许此显式操作在原登记路径进行核验；已有物理身份必须匹配。验证成功原子标记 ready；不完整或已修改仍 invalid，保留原目录和明确原因，不触发下载。当前配置可继续按既有流程选择并绑定该目录。
- 阶段固定为连接、预检、下载、状态校验、信息/完整性校验及登记；运行时更新安全阶段，失败记录命令、输出类型、已读字节和限制（可用时）及 SVN 数字错误号，不保存原始输出、参数、目录清单或凭据。历史错误不伪补阶段。
- 页面在失败检出旁展示“重新校验已有目录”、目录保留状态和校验结果，说明不重新下载且未通过前不能使用；后端独立复核按钮条件。

## Risks / Trade-offs

- 大清单内存/CPU → 逐条解析并释放 XML 节点，有限条目集合，单条/总字节/时间都设限，测试超过旧 8 MiB 的真实 CLI 输出。
- 保留不完整目录占空间 → 显示保留状态并继续空间保护，不自动删除用户已下载内容。
- 稀疏工作副本表面正常 → 对比固定版本远端清单及深度，缺项一律不进入 ready。
- 重试与并发/换配置 → 原请求身份、最近操作、generation、租约、停止证明和物理身份逐层核验。
- 目标 Windows 环境不可直接访问 → 本机合成 SVN/Docker 验证与现场验收明确区分；不直接操作用户报告的 1.7 GB 目录。

## Migration Plan

无数据库迁移。同步 API、knowledge-sync 与管理前端所需镜像；共享 SVN 错误投影受影响的服务按实际依赖同步。无活动 SVN 写任务时更新本机容器。升级后在原失败任务点击重新校验，不需要删除目录或重新检出。旧服务回滚只能保留 invalid 状态，不能绕过新的完整性判断手动改 ready。
