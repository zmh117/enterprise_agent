## ADDED Requirements

### Requirement: SVN 大工程输出必须流式处理并保持完整性边界
完整工程的递归清单、属性、工作副本状态和信息 SHALL 流式解析，逐条释放 XML 节点，不因整体 XML 超过普通响应的 8 MiB 限制而误判。下载进度 SHALL 持续排空而不整体缓存；stderr 仅保留有界数字错误号及计数，正常命令不得仅因警告累计超过旧 64 KiB 限制失败。系统 MUST 继续限制单记录、XML 深度、总处理字节、条目数、工程大小、磁盘空间及原执行期限，拒绝 DTD/entity、截断和非法 XML，持续响应取消和失去执行权。

#### Scenario: 元数据超过旧限制
- **WHEN** 所选合法工程的 XML 超过 8 MiB 但未达到流式处理和工程上限
- **THEN** 正常完成预检及工作副本核验，不缓存完整 XML，不改变固定 SVN 版本和授权范围

#### Scenario: 实际超限或非法输出
- **WHEN** XML 达到新的总量/单条/深度/条目上限，或输出截断、含 DTD/entity
- **THEN** 中止并回收进程，返回具体安全分类与阶段，不以部分结果登记成功

### Requirement: 工作副本准入必须证明所选范围完整
检出完成、重新校验与版本更新后的准入 SHALL 核实同一固定版本远端所选清单与本地版本化条目一致，选中目录及后代为完整深度，且无修改、缺失、冲突、切换、外部引用或混合版本。MUST 保留路径、来源、物理身份与读写互斥约束，不凭命令退出码、目录体积或少数已存在文件推断完整。

#### Scenario: 稀疏目录伪装已完成
- **WHEN** 被中断工作副本版本正确且 status 正常，但选择范围存在缺项或非完整深度
- **THEN** 拒绝 ready，显示完整性不足，Runtime 不得取得读取权限
