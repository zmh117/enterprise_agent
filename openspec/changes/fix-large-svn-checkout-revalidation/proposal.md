## Why

完整工程的 SVN 清单、状态和信息 XML 目前复用 8 MiB 整体缓存限制，检出进度也整体累计。文件已下载后仍可能在校验阶段超限，失败提示没有准确阶段，用户只能重复下载。

## What Changes

- 大工程元数据采用有界流式解析，检出/更新进度持续排空而不整体缓存；保留条目、单条数据、总处理量、时间、空间和取消边界。
- 失败记录显示固定阶段、命令、输出类型及计数，不保存原始输出、文件清单或凭据。
- 保留失败的受管检出目录，维持不可用状态；提供管理员“重新校验”入口，复用原路径、仓库、选择范围和固定版本。
- 重新校验必须核对远端固定版本清单与本地完整工作副本，拒绝缺文件、修改、冲突、混合版本、链接或身份变化；不执行下载、update、cleanup 或覆盖。
- 校验通过后才标记 ready 并允许现有知识库绑定及 Runtime 读取。

## Capabilities

### New Capabilities

无，扩展既有领域。

### Modified Capabilities

- `platform-operations`：检出阶段诊断、保留失败目录、受管目录重新校验与复用。
- `builtin-tool-resource`：大规模 SVN 元数据流式读取与完整性准入，不弱化版本/读写占用约束。

## Impact

影响 SVN CLI 执行器、完整工作副本检查、管理任务存储/API、知识库检出页面和相关测试。复用现有 operation/checkout 表、result_json 和 knowledge-sync，不新增容器或 Agent。只更新必要容器；不启动模型提取，不改 ONES 知识库或答案索引。真实部署中的任务不能由本机直接核验，使用本机合成大仓库与已有 Docker SVN 链路验证并提供现场操作说明。
