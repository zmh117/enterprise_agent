# Design

## Context

动机与范围见 [proposal.md](proposal.md)，事实依据见 [evidence-audit.md](evidence-audit.md)。当前采用一个后台会话管理器、统一接受 gate、按目标管理的 debugger、rrweb 顶层统一流、IndexedDB Journal 和控制页 ZIP 导出，主流程已有真实浏览器证据，应继续使用这些边界。

本设计处理跨模块的身份、隐私、状态及契约缺口。四份 delta spec 定义目标行为；T01–T50 作为原规格验收清单保留，不能用 OpenSpec 的文件存在状态代替产品验收。

## Goals / Non-Goals

**Goals:**

- 对照 G01–G12 修正有依据的实现缺口，为其建立反例和真实场景证据。
- 优先恢复已有架构承诺的行为：范围明确、截止严格、归属可追溯、缺失可见、数据可独立导出。
- 让实现者可按任务组推进，每次变更有明确的测试入口和停止条件。

**Non-Goals:**

- 不改成每 document 独立 rrweb 流，不 fork rrweb，不建设通用规则引擎或新协调服务。
- 不默认启用截图，不追求最早请求零丢失，不采无法归属的共享 worker 内部流量。
- 不将生产 MES、上传、日志平台或源码平台接入当作本地开发的前置条件。
- 本轮只产出规划文档，不改实现、测试代码、原始开发规格或既有验收结论。

## Decisions

### 1. 先修正明确缺口，再补真实平台验收

采用“代码/包内事实 → 对应行为规格 → 有针对性的任务 → 验证产物”的顺序。G01–G05 和身份/隐私有关的 G09 优先处理，剩余契约与资源行为随后完成。保留现有有效断言，补上缺失的结果验证。

不采用“把所有待测项当作代码没实现”或“仅增加测试使总数增长”的做法。故障注入证明自身边界；原生浏览器事件、菜单和权限必须另有真实证据。无需建立新测试平台：在现有 Playwright 脚本旁按范围、生命周期、故障/权限、性能等场景适量拆分公共 fixture 和辅助函数即可。

### 2. 沿用分层状态，按通道收敛就绪

保留会话、目标存在性、采集状态和通道状态的分层，不增加状态组合枚举。每个实际启用通道都必须完成 ACTIVE、BLOCKED 或 LOST 的收敛；明确失败立即记录，缺少实际就绪证据时使用有界等待期限。页面就绪必须包含有效基线；语义就绪须能证明观察器已启动，而非仅靠注入 Promise。

`DebuggerManager.enable()` 的失败反馈进入通道状态；一个子 session 的失败作为该子范围的缺口，不随意使整个标签其他健康 session 的 token 失效。控制页按应启用的 page/semantic/network/runtime 覆盖计算部分采集，截图 disabled 单独展示。

权限仍由用户开始动作触发请求。请求返回后按具体 origin 的实际授权结果评估已选根：已获权限的有效根继续，未获权限根留在范围记录并说明原因。输入无效仍直接拒绝；输入有效但实际根全部失效或全通道失败时保存 FAILED 诊断会话。禁止借权限失败改为采集其他未选标签。

选择此方案是因为后台已有部分启动模型，主要缺口在 UI 入口、失败收敛和结果展示，无需另做任务调度框架。

### 3. 身份映射只使用可验证对应关系

保持三套身份分开：

| 身份域 | 主键及有效期 | 用途 |
| --- | --- | --- |
| 扩展文档 | tabInstanceId + chromeFrameId + documentId | 授权、真实消息发送方、导航边界 |
| CDP 上下文 | debuggerSessionKey + cdpFrameId / executionContextId + 文档区间 | 网络/错误来源，不直接等同 Chrome frameId |
| rrweb | recorderStreamId + nodeId | 页面节点引用及父统一流的 iframe attach |

扩展文档映射由真实 MessageSender 和 webNavigation 当前文档对账建立。CDP 对照优先采用已授权 frame 的扩展隔离上下文专用文档标记，与 execution context 的 frame 信息核对；只读取本扩展的元数据，不执行网页任意 getter，不通过 URL、排列或时间相近建立唯一对应。该路径先在同 URL 多 iframe、OOPIF、导航重建上做能力验证；当前浏览器不能唯一核对时输出 null 和具体原因，不降级为猜测。

rrweb 继续使用顶层统一流。同源节点使用真实 ownerDocument 与已登记文档对应；跨源采用锁定版本的父/子协作信息，只有可验证的重映射才填写具体节点归属。不能验证的跨源节点继续 unknown/multiple。不为追求字段非空而使用页面自报 documentId 作为授权来源。

`DocumentRecord` 增加明确的基线引用与承载流关系：顶层引用 Meta/FullSnapshot；子文档引用父流 attach 事件及对应根节点；语义专用流注明其页面基线来自父流，不等待不存在的独立 FullSnapshot。基线引用只指向已接受事件。frame 移除、导航、流重启和目标截止关闭相应映射区间。

不采用按 URL 对应 frame 或给所有事件默认顶层 document 的方法，它们无法区分相同 URL 与跨文档变化。新映射结构保持有限、可过期，不新增图数据库。

### 4. 敏感区域规则先于语义字段提取

在页面侧形成统一的“该元素是否敏感、字段是否允许”判定，所有 target/state/context 的值都经过它，包括普通 id、data-*、标签和上下文。命中敏感区域时只保留允许的结构描述与掩码状态；不能仅清理包含 token/password 字样的键。DOM/输入、网络正文、URL、错误预览仍分别执行其通道策略。

策略提交前用实际 DOM 选择器解析能力校验选择器；页面注入时再次校验。无法解释规则时停止受影响页面通道，避免后台已经记录就绪而页面私下停止。后台结构校验和清洗作为第二层，不能把 MAIN world 内容当作可信指令或新增授权。

回归 fixture 使用不含秘密关键词的随机哨兵，避免脱敏测试只验证正则自己认识的样例；同时验证合法业务值 `3.00`、版本和业务 ID 没被误删。截图沿用 §14.1 的停用选择，测试“没有截图读取”和显式原因；若未来需要截图，另提 target 绑定及像素脱敏变更。

### 5. 语义快照保留观察时间和省略范围

关键动作读取相关表单、弹框或提示区，减少每次动作全页扫描。before 使用此前已接受状态的引用/观察时间；没有依据则 unavailable。直接读到的状态继续与动作同批接受，保持现有原子引用优势；响应后和异步变化是新的观测，不回填成动作瞬间的结果。

区分原生 dialog open 属性变化、角色弹框显隐、节点移除和 toast 内容变化。补测 checked、selectedIndex 及不派发 DOM 事件的程序修改。字段数、属性数、文本长度达到预算时记录计数/省略原因并传播到 quality；必要时只停止受影响流，不伪造完整快照。

BFCache 由实际 persisted/平台证据确认：继续原实例需证明实例存活；发生停止后重启则更换流和基线，不能让新 recorder 从 seq=1 回到旧 ticket。此项先补真实复现，再对照现有握手路径修正，不假定单靠 pageshow 监听已经正确。

### 6. 使用同一结构契约，并显式校验跨记录关系

扩展现有 JSON Schema，覆盖 recording、target/document、事件信封及主要 payload、网络记录、正文、能力/缺口和导出清单。使用构建期预编译的静态校验函数，供消息接受和问题包验证复用；关系、截止和 rrweb 依赖检查保留为清晰的显式代码。

采用 Ajv 的 standalone 生成方式作为构建工具，锁定依赖，扩展内不动态编译 schema、不使用 `eval` 或 `Function`。官方说明支持构建时生成独立校验代码，并用于受 CSP 限制的环境，见 [Ajv standalone 文档](https://ajv.js.org/standalone.html)。本提案不安装新依赖，实施时接入构建步骤并验证生产构建符合现有 CSP。

选择预编译方案而非继续维护互相独立的简版 schema 和手写类型检查，减少必填字段与枚举漂移；不引入代码生成平台，也不重写 rrweb 的完整协议。关系检查包含：

- 必要文件、清单/hash、所属 recording/run、唯一身份和流内顺序。
- target/document/stream、基线和已知节点映射的闭包；明确 unknown 的部分证据可保留。
- 语义 action 引用的 state_snapshot 属于正确目标/文档；网络 evidenceRefs 与 requestKey、标签和调试会话一致。
- actionCandidates 指向真实动作且仍为候选，bodyRef 与双侧状态/字节信息一致，已声明覆盖的文档不能引用不存在的基线。
- 非法字段、数组/对象混淆、路径越界、必要文件缺失以及重新计算 hash 后的语义篡改均有负例。

在不兼容约束确定时统一提升 schemaVersion、同步样例与说明；不为旧开发数据做迁移层。

### 7. 版本、日志与错误使用轻量确定性关联

在冻结策略中增加有限的来源描述：允许的头名称、已观察响应中的 JSON Pointer、明确页面元数据选择器，以及按环境/组件/构建 ID 给出的源码快照映射。只处理已授权且已发生的观测，不主动探测新版本接口。

保存每个观测值及来源 requestKey/eventId，汇总只作投影；前后端分开，多版本并存保留所有来源，不用最后一次值覆盖。人工配置的映射记录配置来源，不能伪装成已检索验证过的源码；未知与冲突保持 unresolved，后续 Agent 仍须验证实际源码与部署关系。

错误观测保留原文来源的脱敏记录，在导出时按标签/文档、栈及消息形成有界候选组；可证明重复的事件按稳定身份去重，不删除不同来源的有效证据。不建立模糊根因引擎，不把时间接近直接作为同一故障证明。

摘要优先列人工标记、相关状态和异常请求，设置整体长度/条目预算，显式说明省略数量与读取入口。现有 NDJSON/正文布局继续支持按需定位；不为 T49 另建检索服务。

### 8. 标签预算和保存状态独立于子 session 数量

将正文读取队列提升为每 tabInstance 共享，子 debugger session 提交携带自身 token 和发送函数的任务；会话重建后旧 token 失效。并发限制是该标签合计，不随 iframe/worker 数量放大。

停止先同步关 gate，持久化终结标记、释放连接和已接受批次排空分别报告。5 秒作为阶段等待诊断阈值，从停止开始观察，不只是 cleanup 的计时。挂起事务未确定完成/失败前不同时启动替代写入；重试复用稳定批次/事件身份，不因 UI 超时就清空已接受队列。

保持现有分批 Journal。先测量元数据保留、排队/in-flight 字节、网络固定链上限和封包内存；发现确实越界再收敛缓存/迭代读取。不能提前宣称需要新存储架构或 unlimitedStorage；申请权限、改为增量封包须有测量依据。

### 9. 验收记录区分自动化、人工与不适用

验收输出至少包含 T 编号、具体断言、运行版本/系统/权限模式、复现步骤、关联产物及通过/失败/待测/不适用。使用独立测试 profile。普通自动化可以预授权 fixture，但权限验收必须加载未经修改的生产 manifest。

BFCache/replacement 必须取得实际平台事件；环境不能产生时明确待验收。右键菜单、F12、调试提示取消和开发者模式扩展重载可采用人工辅助，不用脚本调用替代它们。时钟测试在隔离进程/虚拟环境进行，不修改用户系统时间。

性能按 1、10、30 标签及持续约 30 分钟的声明预算场景逐级测量，记录实际硬件、数据规模、页面延迟/卡顿、CPU/内存层级、队列峰值、吞吐和缺口；先验证安全停止与有界资源，不凭一次平均时延制定“零开销”承诺。机器或浏览器不支持的规模写明未完成，不能据此声称默认容量已验收。

### 10. 真实录制网络补充（2026-11-17）

- 用户本轮明确要求默认仅保护登录密码。`policyVersion=3.0.0` 以 `["*"]` 放行普通输入/查询值，默认没有额外敏感选择器且不全量掩码文本；通用 token/Cookie/Bearer/JWT 清洗移除。密码输入、autocomplete 与明确密码字段以及 Basic 中的密码继续保护。该决定覆盖本设计第 4 节原默认隐私范围，手动额外选择器仍可用。
- `text/plain` 支持结构化 JSON 和自由文本，仅保护密码；JSON 标量也可保存。application/json 允许精确 XSSI 前缀 `)]}'` 加 LF/CRLF，去掉前缀后必须完整解析，不执行脚本。无需密码替换时保留原始 JSON/表单格式（XSSI 前缀除外），有密码时安全序列化且表单重复键不丢失。旧通用 token 正则移除后不再出现长连续文本回溯；独立子进程超时验证大文本处理及密码保护。
- `Network.dataReceived.dataLength` 累加解码后字节；超过正文预算时不读取、不截断，记录明确排除原因。压缩 Content-Length 不作为解码大小。CDP 每资源缓冲取正文预算两倍、总缓冲取至少 8 MiB 或正文预算四倍；这是每调试会话的 Inspector 限额，不替代每标签正文队列预算。缓存淘汰与编码/协议失败分别报告，不重发请求。
- 已选目标调试会话内的 `requestWillBeSent.documentURL` 是浏览器提供的请求文档授权依据，必须同时有 CDP frameId 且满足当前页面策略和实际权限；不能使用 API URL 或 initiator 代替。缺少 documentURL 时仅可使用相同 loader 的已知 frame；元数据不足保留缺口。此判断不创造 Chrome document 身份，绑定还须符合已验证隔离上下文和同一 loader。
- 页面/接口策略排除的重定向仍保留空 hop 以消费对应 ExtraInfo 顺序，不存该 hop 业务内容。协议明确 false 的额外头状态为 `not_expected`；未知标志保持顺序屏障；只有确实未完成匹配的请求在截止时标 `unresolved_at_cutoff`。

## Risks / Trade-offs

- [隔离上下文或 rrweb 跨源重映射能力不足] → 用限定 fixture 先确认，不能建立映射就保留具体 unknown/partial；不得擅自 fork 库或猜 ID。
- [敏感区域扩大后减少诊断信息] → 保留掩码原因和经允许业务字段，现场调整显式允许规则；不牺牲凭据保护换取完整度。
- [更严格校验使旧样例不通过] → 显式升版/重新采集并说明差异，保留历史验收事实，不将旧样例静默修改成新实现证据。
- [原生菜单、BFCache、replacement 或企业策略难以自动复现] → 单测和真实验收分别记账；待实测不会被自动通过标记覆盖。
- [慢写与封包峰值暴露容量不足] → 保留已接受数据和诊断，依据测量调整缓存/导出方式，不自动申请额外权限或删除唯一副本。
- [真实环境配置未提供] → 本地 fixture 完成协议验证，现场接入另列；本提案不编造生产值。

## Migration Plan

1. 按任务 1–3 完成隐私、状态和归属修正，保留原 gate 与生命周期约束的回归。
2. 按任务 4–6 完成语义、契约、关联与资源行为；发生不兼容时统一更新 schema/数据库版本，清理受影响开发数据并重新采集样例，不新增兼容层。
3. 按任务 7–8 完成真实浏览器与故障验收，更新协议/消费说明、验收矩阵及安装范围。
4. 发布前保存可回退的构建产物。回退扩展代码时使用相应版本的数据/包校验器；不承诺跨版本读取不兼容的本地开发数据。
5. 只有实际实现和适用验收完成后才勾选任务及归档变更；待验收、明确限制、生产接入状态分别保留。
