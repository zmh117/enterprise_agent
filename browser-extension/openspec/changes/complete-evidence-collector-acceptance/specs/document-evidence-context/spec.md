# Spec Delta

## Purpose

让问题包中的页面状态、节点、操作和接口能够准确指向实际被观察的文档及其录制上下文，避免跨标签、跨导航、跨 iframe 或录制重启后的身份混淆；对于不能证明的对应关系保留明确的未知状态和覆盖范围。

## ADDED Requirements

### Requirement: 发送文档和观测文档分别表达

系统 SHALL 保留经扩展真实发送上下文验证的 emitterContext，并根据已确认的文档关系填写 subjectContext 或节点上下文映射。已确认属于顶层或同源子文档的事件不得一律标成未知；跨文档或无法确认的事件不得借用发送方身份冒充观测对象。

#### Scenario: 顶层转发子文档变化
- **WHEN** 顶层录制流转发一个已能确认归属的同源 iframe 节点变化
- **THEN** 发送方仍为顶层文档，节点观测上下文指向对应子文档，两者在包中可分别检查

#### Scenario: 跨源节点不能可靠映射
- **WHEN** 跨源协作录制产生事件，但节点重映射不足以证明某个 Chrome 文档身份
- **THEN** 事件保留 unknown 或 multiple、具体原因及已知范围，不填造文档 ID，也不把整个目标宣称为完整映射

### Requirement: 每个覆盖文档有可引用的基线

系统 SHALL 为声明已覆盖的每个文档保留其有效基线引用。子文档可以引用父统一流中的 iframe attach 基线；语义专用流不得被误认为另一份 rrweb 完整流。没有确认基线的文档必须标记为未覆盖或部分覆盖。

#### Scenario: 同源和跨源 iframe 动态加入
- **WHEN** 页面加入已授权的同源与跨源 iframe
- **THEN** 每个已声明覆盖的子文档能定位到属于自身的基线事件或 attach 节点及承载流
- **AND** 同源 iframe 不产生父递归录制和子独立录制的重复证据

#### Scenario: iframe 导航或未获权限
- **WHEN** iframe 更换文档或进入未获权限的页面
- **THEN** 旧基线不自动授权新文档，新覆盖建立新的关联；未覆盖部分明确记录原因

### Requirement: 网络 frame 身份保留验证依据

系统 SHALL 分开保存 CDP frame/loader 与 Chrome frame/document 身份，并在有可靠映射时关联到目标文档。映射必须属于相同标签实例、调试会话及文档有效区间；未确认的映射保持空值和原因，不通过相同 URL 推断。

#### Scenario: 多个 iframe 使用相同 URL
- **WHEN** 两个已授权 iframe 使用相同 URL 并并发请求同一接口
- **THEN** 请求仍依据已验证的 frame/document 身份区分；证据不足的请求不伪造唯一归属

#### Scenario: 子会话重建
- **WHEN** 一个专属 iframe 调试会话被重建，且浏览器复用了请求或 frame 标识
- **THEN** 新旧调试会话和文档区间分开，旧映射不能覆盖新请求的身份

#### Scenario: 导航请求早于 frameNavigated
- **WHEN** 已选目标的 CDP 请求具有 frameId 及已获权限的 documentURL，但新文档尚未提交
- **THEN** 系统 SHALL 根据浏览器提供的请求文档元数据授权该请求，Chrome document 绑定不能借用旧 loader
- **AND** 无 frame、未知来源、未授权来源仍排除并分别说明原因；接口 URL 被允许不能替代页面授权

### Requirement: 录制重启与节点编号隔离

系统 SHALL 以录制流和节点 ID 联合标识元素。完整导航、BFCache 恢复后确需新建录制实例或异常恢复时，新实例必须使用新流并建立基线；SPA 路由变化保持实际文档身份。旧流引用不得解析为新流节点。

#### Scenario: 两个流同时出现节点 42
- **WHEN** 两个标签或两个先后创建的录制实例都包含 nodeId 为 42 的节点
- **THEN** 各元素引用仍能区分所属流、标签和文档，不能仅按数字 42 合并

#### Scenario: 真实 BFCache 恢复
- **WHEN** 浏览器实际命中 BFCache 并恢复原文档
- **THEN** 持续实例沿用可证明有效的流，重启实例产生新流及基线，未覆盖区间有缺口说明，状态和后续事件保持一致

#### Scenario: history 或 hash 更新
- **WHEN** 当前页面发生 SPA 路由更新而实际文档未更换
- **THEN** 记录路由及状态变化，保持文档身份，不伪造新的完整导航

### Requirement: 语义状态说明观察依据与完整程度

系统 SHALL 记录程序修改的 value、checked 和选择状态，以及重要提示、弹框开关、禁用和加载变化。before 状态必须能追溯到此前观测，无法获得时明确 unavailable；异步更新按实际观察时间记录。截断、数量限制或未覆盖区域必须可见。

#### Scenario: 只有程序赋值而没有输入事件
- **WHEN** 页面脚本修改复选框 checked、输入 value 或选择项，未派发 input/change
- **THEN** 相关状态快照或页面证据能反映真实值，语义引用指向实际保存的观测

#### Scenario: 原生弹框关闭及短暂提示
- **WHEN** 原生弹框仅改变 open 状态而未从 DOM 删除，或提示短暂出现后消失
- **THEN** 证据区分打开、关闭和可见性变化，并保留已观察到的短暂内容及来源

#### Scenario: 动作前状态未采集或读取范围超限
- **WHEN** 关键动作涉及尚无先前状态的控件，或相关区域超过读取数量与文本预算
- **THEN** before 标明未知依据，截断字段或遗漏范围附状态与原因，不宣称是完整的操作前后快照

### Requirement: 源时钟和源内顺序不被归一化覆盖

系统 SHALL 保留原始 sourceTime、sourceClock、observedAt 和源内序号。无法证明 UTC 对应关系时保持 normalizedAt 为空；使用时间映射时保留方法及偏差。授权与停止不依赖页面自报时间或跨 API 时钟的大小比较。

#### Scenario: 页面时钟偏移与系统时间跳变
- **WHEN** 测试环境使页面时间与扩展观察时间出现偏差或跳变
- **THEN** 原始时钟和序号仍可检查，已关闭入口不会因时间倒退恢复，日志检索继续使用配置余量及服务端关联 ID
