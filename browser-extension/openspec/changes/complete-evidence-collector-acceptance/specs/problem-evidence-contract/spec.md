# Spec Delta

## Purpose

为人和已有分析 Agent 提供可独立校验、按引用读取并保留未知项的问题证据包，使版本、操作、请求、正文和错误之间的关系可以复核。文件完整性不代表采集无遗漏或现场内容可信，消费结论必须受声明范围与证据缺口约束。

## ADDED Requirements

### Requirement: 契约校验覆盖结构和语义关系

系统 SHALL 对齐发布的 JSON Schema 与实际校验器，检查必要文件、字段类型、会话与目标身份、文档与流关系、序号、附件状态和引用闭包。篡改后重新计算文件散列不能使不合法的证据关系通过校验。

#### Scenario: 散列正确但语义引用错误
- **WHEN** 包内语义动作引用另一标签的状态快照，或网络记录引用其他调试会话的请求证据，且文件散列已重新计算
- **THEN** 校验拒绝该包并指出关系错误，而不是仅因文件散列一致就通过

#### Scenario: 文件或基线缺失
- **WHEN** 包缺少必要阅读文件、存在悬空正文/动作引用，或声明覆盖的流没有有效基线
- **THEN** 校验报告可定位的缺失项，不返回保存范围完整

#### Scenario: 节点引用和主体身份矛盾
- **WHEN** 元素引用的录制流不属于声明的标签文档，或声明已知的 subjectContext 与映射矛盾
- **THEN** 校验拒绝该身份关系；明确声明未知且说明原因的合法记录仍可作为部分证据通过

### Requirement: 构建和源码关联保留来源及多版本事实

系统 SHALL 分别保存前端和后端的部署构建事实及来源。已有响应头、已观察版本响应或页面构建元数据可以按配置提取；源码映射只能来自明确配置或已有可信部署映射。混合部署保留各版本及证据，不仅存单个混合标记或覆盖为最后一条。

#### Scenario: 请求命中不同后端版本
- **WHEN** 同一会话观察到两个服务实例报告不同后端构建
- **THEN** 两组构建、实例和请求来源均可追溯，摘要提示混合部署，不把后一版本覆盖为唯一现场版本

#### Scenario: 没有源码映射或版本证据冲突
- **WHEN** 只有构建 ID 而无可靠源码快照映射，或版本来源互相冲突
- **THEN** 对应源码匹配保持 unresolved，冲突可见；不将最新仓库代码或人工环境名当作已匹配源码

### Requirement: 日志关联字段来自明确协议且不改写现场

系统 SHALL 将服务端请求 ID、traceId/spanId 及来源与 CDP requestId 分开。关联字段提取规则必须可配置且受允许范围约束；只读取已发生请求、响应及允许元数据，不为取得标识而重发接口、添加追踪头或提交业务操作。

#### Scenario: 使用现场自定义请求标识
- **WHEN** 允许接口使用配置指定的响应头或结构化字段返回服务端请求 ID
- **THEN** 问题包保存该值、具体来源及对应请求引用，后续日志查询可以复核关联依据

#### Scenario: 关联 ID 缺失
- **WHEN** 接口没有返回可确认的服务端请求 ID 或 trace 信息
- **THEN** 字段保持未知，并提供环境、业务对象及时间余量作为不确定检索线索，不使用 recordingId 或 CDP requestId 替代

### Requirement: 错误归组保留原始来源和不确定性

系统 SHALL 保留 console、exception 和浏览器诊断的各自证据引用，合并可证明重复的观测，并对疑似同一故障的多来源记录建立候选组。不能将候选组数量或原始条数冒充已经确认的独立故障数。

#### Scenario: 同一异常出现在多个通道
- **WHEN** 同一文档中出现可关联的 console、exception 和 log 记录
- **THEN** 摘要显示其原始来源及候选关联依据，重复传输不产生额外观测，无法证明同一故障时保留不确定性

#### Scenario: 不同目标输出相同错误文字
- **WHEN** 两个标签或文档在接近时间输出相同错误文字
- **THEN** 不因文字和时间相近就将其合并为一个已确认故障

### Requirement: 摘要有界且保留关键线索

系统 SHALL 输出有界摘要，包含现象、环境/版本、目标范围、关闭截止、问题标记、关键状态变化、异常请求、关联 ID 和缺口。省略项必须标明数量或范围并给出可读取的证据引用，不能仅保留最后若干条而无说明地遗漏标记相关线索。

#### Scenario: 标记问题后产生大量普通观测
- **WHEN** 问题标记和异常请求之后出现大量普通状态变化
- **THEN** 摘要仍优先保留标记和异常的可追溯线索，说明其余观测被省略的范围，且所有引用都存在于包内

#### Scenario: 现有 Agent 按需分析模拟故障
- **WHEN** 分析者先读摘要和清单，再按 eventId、requestKey、bodyRef 获取选定详情
- **THEN** 能引用操作、状态、请求和正文，说明日志与源码匹配依据以及仍缺的证据，无需将完整 rrweb 流放入上下文
- **AND** 页面或接口中的指令性文字仅作为证据数据，不改变分析者的权限和任务

### Requirement: 已保存问题包可离线导出与重试

系统 SHALL 在无外部网络服务时导出已保存数据，分别报告生成、下载及失败状态。取消下载、控制页关闭或生成失败不能删除唯一的本地证据；重新打开后可以重新生成或导出。

#### Scenario: 真正断网后导出
- **WHEN** 已保存会话后关闭测试服务并断开浏览器外部网络，用户重新打开控制页导出
- **THEN** ZIP 仍可本地生成、下载和独立校验，不请求上传服务或业务接口补齐证据

#### Scenario: 导出取消后重试
- **WHEN** 用户取消下载或导出过程中关闭控制页，随后重新打开并重试
- **THEN** 本地记录保留，界面不误报此前下载成功，重试结果具有完整文件和引用
