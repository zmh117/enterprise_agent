# Design

## Context

阅读浮窗使用 React 时间线，控制台使用 DOM 渲染。两者共用输入区。提交消息与收到 Job 标识之间有一段时间，连接中断后可按客户端消息标识找回回执。

## Goals / Non-Goals

同一按钮控制本轮提问与停止。回答区负责展示平台状态，输入框独立保存追问草稿。本页持续采集仍由图标菜单控制。

## Decisions

1. 共用输入区在提交时立刻显示「停止回答」，同步更新图标、可访问名称和禁用状态。输入框的 Enter 只走发送逻辑，避免编辑下一条问题时误停任务。
2. 停止操作绑定到本轮提交。如果已取得回执，向该 Job 发起取消；如果回执尚未返回，先记下停止意图。提交结果丢失时按原消息标识查询回执，避免为停止操作再次发送问题。
3. 两种时间线将 Job 状态交还给同一个输入区。排队任务的取消回执可立即恢复发送，运行中任务等待原回答流或快照结束。停止请求失败时显示错误并允许重试。

## Risks / Trade-offs

- 历史消息也可能更新。只有当前轮次的回调可以改变按钮状态。
- 连接故障可能使回执或终态暂时不可确认。界面提示重新核对，避免在平台结果未知时显示「已取消」。
