# Spec Delta

## Purpose

让 MES 用户从浏览器扩展控制台以本人的平台身份选择应用，共享一段录制中允许使用的操作与接口证据并连续提问，在网络中断、凭据过期或重新打开控制台后可以接续原来的工作。

## ADDED Requirements

### Requirement: 在受信控制台登录指定平台

插件 MUST 在用户主动连接后，以所选内网 HTTP 系统网址的精确 Origin 和发行版本固定的 Chrome 回调完成系统账号授权。不同安装目录 MUST 使用同一发行客户端 ID，用户和部署人员均无需单独登记插件或平台地址。业务凭据只进入受信扩展内存，应用选择、上传、问答和读流均限定到该 Origin。

#### Scenario: 首次通过内网 HTTP 连接
- **WHEN** 用户首次配置含端口的内网 HTTP 地址并授权该主机，且尚无平台登录会话
- **THEN** 插件打开平台登录页，以 state 与 PKCE S256 完成一次性授权码兑换，按平台确认的内部账号列出其可用应用

#### Scenario: 系统用户登录后选择应用
- **WHEN** 用户首次粘贴系统网址，用现有系统账号完成登录和授权
- **THEN** 插件 MUST 展示服务端返回的本人可用且已启用插件入口的活动应用，并以所选应用发送问题；列表为空时显示原因并保持发送按钮禁用

#### Scenario: 来源或账号发生变化
- **WHEN** 认证回调不匹配，业务请求重定向到其他 Origin，或用户切换平台、账号
- **THEN** 无效回调被丢弃，凭据不发给其他 Origin，旧账号的待发问题、录制回执及回答草稿不会在新身份下恢复；网页与内容脚本无法代用户登录或上传

### Requirement: 进行中的业务自动换取短期凭据

插件 SHALL 按兑换返回的剩余有效期安排换证。存在提问、上传或回答订阅且父登录会话和插件授权有效时，用新的 state 和 PKCE 静默取得新凭据。插件仅在有业务需要时续期。

#### Scenario: 分片与答复同时遇到凭据到期
- **WHEN** 多个操作需要续期，或插件休眠后第一次业务请求遇到到期的 401
- **THEN** 同一身份合并换证，无需输入密码。每次失败请求仅用新凭据恢复一次，迟到的旧 401 不会清掉新凭据或触发换证循环

#### Scenario: 重新登录、确认授权及拒绝访问
- **WHEN** 父 Session 已退出、闲置或绝对过期、被撤销，或平台要求用户重新同意
- **THEN** 插件暂停工作，分别提示重新登录或继续授权；原账号与业务范围通过复核后才继续。账号停用、插件禁用或权限撤销时停止对应访问。暂时离线时保留可恢复进度并有限重试

#### Scenario: 换号后才收到旧换证结果
- **WHEN** 同一浏览器先为账号 A 静默授权，再切换到 B，而 A 的回调或兑换结果较晚返回
- **THEN** 双方 MUST 按发起时的 Origin、state 和账号边界处理，插件丢弃失效流程的结果。只有 credential_expired 进入一次自动换证；login_required、consent_required、access_denied 分别进入登录、确认或停止流程

### Requirement: 主动共享可核对的录制投影

插件 MUST 仅从用户确认的已封存录制构造上传数据。用户确认共享后，已采集的接口请求、响应和操作中的业务字段按实际名称、嵌套层级、类型和值传递。新增业务字段和首次出现的接口自动纳入，无需管理员登记路径模板或维护字段清单。确认前展示业务字段样例、请求数、操作数、采集缺口和预估传输量。核对源总数、可共享数与平台自身流量排除数，每个可共享的 requestKey 与 ui.action 的 eventId 各保留一行。插件在生成分片前处理凭据、原始业务消息和平台自身流量。密码、Cookie、访问令牌、模型密钥和数据库凭据的值不得出现在分片、日志或 Agent 输入中。无法安全拆分的原文标记为省略并保留请求或操作索引。服务端在持久化前独立复核，拒绝违规分片且不回显原值。

#### Scenario: 选择包含未知路径和不完整响应的录制
- **WHEN** 录制有重复调用、HTTP 200 业务失败、未知路径或未取得的请求或响应正文
- **THEN** 逐次保留标识、业务字段及新增嵌套字段，分别记录 HTTP 状态、业务结果、两侧缺失或省略原因；只因时间相邻的操作与请求标为线索。可共享源集合的唯一 ID 数和摘要与待提交投影核对一致才可发布

#### Scenario: 没有选择录制
- **WHEN** 用户离线完成录制或导出 ZIP，或在新会话中仅提交文字
- **THEN** 插件不会自动读取和上传录制，本地保存和导出可独立完成

### Requirement: 已确认录制按版本上传一次

插件 MUST 复用同一平台授权范围内同一份封存录制与投影版本的稳定键和清单。以服务端已提交的分片和完成回执为准，只上传缺片。服务端确认版本就绪后才允许绑定。

#### Scenario: 大录制跨过凭据有效期或页面重开
- **WHEN** 分片在传输或确认时中断，或完成请求的回执丢失
- **THEN** 暂停调度，同人恢复授权后以原清单查询进度。已收分片跳过，缺片按原序号和摘要补传，已发布直接复用同一 recording_id。重试不删除本地录制

#### Scenario: 清单冲突、校验失败或暂存已清理
- **WHEN** 服务端报告内容冲突、超额、缺片以外的完整性错误或暂存过期
- **THEN** 控制台展示对应状态，不将不可用版本标记为就绪；暂存过期时提示用户重新发起上传

#### Scenario: 续传时范围变化或旧暂存已过期
- **WHEN** 插件用原 scope_ref、upload_attempt_id 与清单恢复，或重新开始后旧分片仍在途
- **THEN** 平台 MUST 在创建任何暂存前复核原范围，范围改变返回 scope_changed。已过期的暂存返回 upload_expired；须经用户确认才能以新 attempt 开始，旧 recording_id 的迟到写入被拒。已就绪的有效版本始终复用

### Requirement: 追问复用原会话与受理时的录制版本

插件 SHALL 用稳定 client_message_id 提交问题。可在首问创建会话或纯文字提问。显式 recording_id 绑定或切换已就绪版本，省略沿用当前会话，显式 null 解除。普通追问只提交问题、消息标识与会话引用，使用选定范围的请求头防止旧请求在新发布下执行。

#### Scenario: 追问受理结果未知
- **WHEN** 服务端可能已受理问题，但插件在得到回执前超时或凭据到期
- **THEN** 同人恢复后使用原消息 ID、文本、会话以及原绑定指令重试。有回执则直接跟踪原 Job；不重传录制，不生成新的消息 ID

#### Scenario: 在两个排队问题之间切换录制
- **WHEN** 问题一绑定 A，问题二切换到 B，或服务端因发布或授权边界变化返回新会话
- **THEN** 界面按各自回执展示实际会话、Job 和录制来源。旧问题仍指向 A；新隔离会话不继承旧录制或历史。当前绑定失效时提示解除或重新选择

#### Scenario: 首问无回执就关闭控制台
- **WHEN** 首问已使用 client_message_id 发送，重开后既无正文也无 conversation_id，随后用户还要继续追问
- **THEN** 客户端 MUST 先按原账号、应用和消息 ID 查受理回执，命中便恢复原会话及 Job；暂未命中时不自动创建新消息。连续提问按受理回执确定顺序，无需等待前一 Job 完成

### Requirement: 增量回答按原 Job 游标恢复

插件 MUST 按 Job 和当前执行尝试拼接 Markdown 原文，安全渲染主对话助手的全部正文，包括工具前后的普通说明。成功时使用已提交全文整体替换草稿，断开订阅不取消执行。

#### Scenario: Markdown 标记跨越增量及断线
- **WHEN** 同一回复的加粗、表格行或代码围栏分布在不同事件中，插件在中途断线后续读
- **THEN** 插件使用累积原文边收边展示，收齐后与一次渲染相同全文一致。成功和重开历史时工具前后正文各出现一次。原始 HTML 按普通文字展示，危险链接不可点击，图片不会触发外部请求

#### Scenario: 回答生成、重试或失败
- **WHEN** 收到 status、answer_delta、reset、completed 或 failed
- **THEN** 依次按事件语义显示状态、追加未渲染文字、重置旧尝试、以最终消息替换或清除未完成草稿并显示失败。仅有终态时直接显示结果，不模拟实时生成

#### Scenario: 已读到一半时断线、换证或重新打开
- **WHEN** 用户在原权限下恢复读取，有最后已渲染的游标与对应草稿
- **THEN** 使用新认证头和 Last-Event-ID 订阅原 Job，不重跑任务、不重复追加。草稿丢失或游标过期时取原 Job 快照或终态；登录期间已完成则直接显示持久结果，旧流的迟到事件被忽略

#### Scenario: 快照与重连之间产生重试或终态
- **WHEN** 本地只剩游标却没有对应草稿，或打开事件流时收到 cursor_invalid，且读取快照后出现 reset 或终态
- **THEN** 客户端 MUST 使用 GET /jobs/{id} 返回的同一版本草稿及 through_cursor 整体恢复，再订阅该游标之后的全部事件。终态直接呈现。没有终态的 EOF 不能标记成功；原 Job 继续运行

### Requirement: 插件仅持有自然人的业务授权

插件 MUST 通过用户确认的应用及录制提交分片。服务端为单片写入和本轮 Job 的单条证据读取管理内部授权；插件不得取得或配置内部服务身份。

#### Scenario: 用户在同一录制上追问
- **WHEN** 已就绪的录制绑定到当前会话，用户继续提问
- **THEN** 插件仅提交问题并展示服务端回答；服务端工具按当前 Job 查询，插件无需保持在线或再次上传
