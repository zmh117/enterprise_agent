# Design

## Context

`extension/ui/control.ts` 已提供录制历史、本地预览和 ZIP 导出。历史查看和 `loadBundle()` 会整包读取，`extension/storage/database.ts` 的 `bundle()` 会加载 chunks、network 及 blobs。本地预览能显示原始请求头与正文，直接复用会超出远程共享范围。扩展的网页采集功能使用 HTTP/HTTPS 可选主机权限。本次在同一控制台增加使用 `identity` 登录的 Agent 工作区。

## Goals / Non-Goals

插件负责登录、投影、分片发送和问答展示。Enterprise Agent 负责身份与应用路由、版本核对、PostgreSQL 检索索引、File Service/MinIO 明细及 Job 执行。Agent 的 `search_recording` 和 `get_recording_evidence` 在服务端按当前 Job 授权取证，因此录制就绪后用户可在任一轮提问，Runtime 沙箱的回收不影响下轮。插件无需对 Agent 暴露 IndexedDB、远程控制页面或提供额外 MCP 服务。

## Decisions

### 1. 连接与登录

本期平台接入和目标验收使用内网 HTTP。用户首次在控制台粘贴系统网址，插件提取并记住 Origin（协议、主机、有效端口），通过用户操作申请相应主机权限并发起 `chrome.identity.launchWebAuthFlow`。每次携凭据的 fetch 复核完整 Origin，禁止跨 Origin 重定向。扩展受信上下文独占授权与联网，增加 manifest 的 identity 权限。采集侧排除平台授权页和插件 API 流量，即使捕获范围与平台主机重叠也不得记录凭据或业务消息。页面脚本无权发起问答和更换平台。

首次登录在所选 HTTP 平台页面完成，服务端建立专供插件授权和续期的父 Session。内网 HTTP 的登录及业务流量以明文传输。插件校验本次 state 与固定回调，以 PKCE S256 兑换单次授权码（最长 60 秒），读取平台确认的账号归属和实际剩余有效期。凭据最长 15 分钟且不超过父 Session 剩余期限，仅保存在受信扩展内存。应用列表来自平台，用户身份和权限由服务端解析。

| 活动期间的状态 | 控制台与传输行为 |
| --- | --- |
| 业务凭据临期或已过期 | 有待发问题、在途上传或活动订阅时提前换证；从休眠恢复则先检查有效期。用同一平台父 Session、新 state 和新 PKCE 发起非交互授权。提问、分片和 SSE 共享进行中的换证。旧 401 复用新凭据，每次失败请求仅恢复一次，截止时间未推进时等到实际到期再复核。 |
| 父登录失效或缺少同意 | 退出、闲置过期、绝对过期或 Session 被撤销，提示「重新登录以继续」。平台只要求补充同意时提示「继续授权」。由用户启动交互，核对返回账号及业务范围后再发原请求。 |
| 暂时离线或权限撤销 | 暂停相关操作，网络恢复后有限重试。账号停用、插件禁用、应用无权时停止对应访问。切换账号或平台时清理旧内存状态、取消旧订阅，按归属隔离可恢复的引用。 |

闲置时停止换证。可持久化平台地址、范围内的上传回执、会话或 Job 等非敏感引用。凭据、校验材料、待发问题正文和临时回答草稿均不写入本地持久存储。同一打开的控制台可从内存按原文重试。重开后先按已保存的会话或待确认的消息 ID 查回执与历史，丢失草稿时通过快照及后续事件重建。

业务请求只在收到 `401 credential_expired` 时自动换证一次。`login_required` 提示重新登录，`consent_required` 提示用户确认，`access_denied` 或对当前业务的 403 停止对应操作。授权回调在匹配 state 后才采纳这些结果。无回调的断网、超时或关闭窗口保留进度，不据此认定用户退出。插件只采纳当前连接发起的授权结果，并核对发起时的 Origin 和预期账号（首次登录除外）。若用户已退出、换号或切换平台，迟到的成功兑换及失败通知均丢弃。按认证响应中的租户与内部用户匹配原工作，最终仍由平台复核资源权限。

### 2. 插件与平台的 HTTP 契约

以下业务请求均位于 `/api/browser-extension`，由插件持业务凭据调用。发行包的 manifest 公钥固定扩展 ID，平台版本内置同一客户端 ID 和 Chrome 回调。用户和部署人员均无需另外登记插件和平台地址。授权路由也使用该前缀。授权页凭父 Session 工作，兑换使用 PKCE，两者不要求先有业务凭据。所有业务读写与回执查询独立复核当前授权。消息字段、事件枚举和业务明细结构使用服务端配套提案的版本化契约及合成样例。

| 请求 | 插件输入和处理 |
| --- | --- |
| `GET /auth/authorize` | 在所选平台打开授权页，校验并绑定发行版的 `client_id`、`redirect_uri`、`state`、`code_challenge` 与 `code_challenge_method=S256`。静默请求携 `prompt=none`。成功或可判定的拒绝均经固定回调返回原 state 以及 code 或 error。 |
| `POST /auth/token` | 受信插件用同一 client_id、redirect_uri、code 和 `code_verifier` 兑换。成功返回 `access_token`、`expires_in`（秒）、`tenant_id` 和不可变 `user_id`；后续业务请求使用 Bearer 认证。 |
| `GET /applications` | 展示可用应用的 ID 和显示名，保存所选应用的 scope_ref 供创建录制和提交问题时比对。 |
| `POST /applications/{id}/recordings` | 初始化或恢复。提交 upload_attempt_id、稳定本地版本键、投影版本、两类行数与 ID 集摘要、每片序号/展开大小/摘要及采集缺口。返回 `recording_id`、状态、缺片序号。 |
| `PUT /recordings/{id}/parts/{n}` | 只发缺片，版本化 UTF-8 NDJSON，可 gzip 传输；按确定性展开字节校验摘要。 |
| `POST /recordings/{id}/complete` | 请求核验并发布，显示平台确认的就绪状态。重复完成须取得同一录制引用。 |
| `POST /applications/{id}/messages` | 发送 `client_message_id`、`question`、可选 `conversation_id` 和绑定指令。问题最多 4,000 字符，消息信封最多 64 KiB。以 202 中实际会话、Session、Job 与本轮绑定为准。 |
| `GET /applications/{id}/messages/{client_message_id}` | 在当前授权归属内只读查询已提交的原 202 回执，含实际会话、Job 与绑定。未找到可见回执返回 404，不创建 Job。 |
| `GET /conversations/{id}` | 分页恢复原会话的有序问答、录制状态、在途 Job 与已提交结果。 |
| `GET /jobs/{id}` | 返回经授权的回答快照及其 through_cursor，或持久终态。快照可直接用于重开或补读事件。 |
| `GET /jobs/{id}/events` | 带 Authorization 的 fetch 解析 SSE，按原 Job 使用 `Last-Event-ID` 续读。 |

### 3. 共享一次封存的录制

用户只选业务应用。平台按本站、本人、当前应用部署与发布、插件连接和路由项目确定共享范围。录制中的 MES 环境名称保留在本地；实际 MES 查询另走平台原有的环境授权。

只允许选择已封存的录制。按 recordingId 游标分页读取 network、chunks 中的 ui.action 和关联 blob。共享流程绕开 bundle()。用户确认共享后，已采集的接口请求、响应和操作中的业务字段按实际名称、嵌套层级、类型和值传递。新增业务字段和首次出现的接口自动纳入，无需管理员登记路径模板或维护字段清单。录制投影版本 2 将固定索引与开放的业务明细分开。请求、响应和操作的明细分别使用 `request_details`、`response_details` 和 `details`，`value` 保留业务结构，`omissions` 逐项说明省略位置和原因。路径模板为空时仍可保留该条记录的业务明细。请求与响应分别保留采集状态；时间相邻只作为线索。

插件在生成分片前处理凭据、原始业务消息和平台自身流量。密码、Cookie、访问令牌、模型密钥和数据库凭据的值不得出现在分片、日志或 Agent 输入中。无法安全拆分的原文标记为省略并保留请求或操作索引。服务端在持久化前独立复核，拒绝违规分片且不回显原值。

源端按请求、操作分别核对「已保存总数 = 可共享唯一行数 + 因平台自身流量排除的数量」。若历史录制已含平台登录或插件 API 自身流量，只报告排除计数，相关 ID、字段和明细均不上传。ID 集摘要仅对可共享行计算；普通 MES 首次出现的路径保留索引和业务字段，单项省略注明原因。对照可共享集合独立核验投影的唯一数和稳定排序的 ID 摘要。确认前展示覆盖、缺口、投影样例和预估字节。用户按「共享」才向应用发送清单与分片。稳定键涵盖本地录制、封存检查点及投影版本，回执按平台 Origin、账号和应用授权范围隔离。确认分片前的网络断开、凭据到期及控制台关闭都可以留下未知提交结果；恢复时先用原清单问服务端，只补尚缺部分。已发布版本直接绑定，暂存过期提示重新上传，任何失败都保留本地证据。

确认共享时保存非敏感清单、版本键、应用返回的 `scope_ref` 和一次上传的随机 `upload_attempt_id`，再发初始化。scope_ref 是服务端对租户、用户、应用发布、Connector 和执行范围的比对值，只作前置条件，当前权限另行复核。原清单恢复时若范围改变，返回 `409 scope_changed` 并要求重新选择和确认，避免旧录制被自动送入新范围。投影版本固定排序、NDJSON 编码、分片边界和分片摘要算法（SHA-256 作用于未压缩 UTF-8 字节），清单中的分片大小也以展开字节计。插件重开后照原清单生成缺片，核对摘要再发送；本地数据缺失或升级后无法复现时停止并提示原因。完成请求返回 `409 parts_missing` 时按缺片序号恢复；`409 manifest_conflict` 或摘要不符时停止，不能将同键异内容当作缺片。

初始化重复使用同一 attempt 查回当前进度。对已过期的未发布暂存返回 `410 upload_expired`，保留可识别旧尝试的最小回执。只有用户重新确认才可生成新的 upload_attempt_id；同版本仍在上传时返回同一有效上传，已就绪时返回原 recording_id。重新开始未发布暂存分配新 recording_id，迟到的旧 PUT 或 complete 不能写入新尝试。首次回执丢失、两个窗口和并发完成均受同一授权范围与封存版本唯一约束。已发布内容到期后的读取报告不可用，不能触发自动重传。

### 4. 连续提问与流式回答

首次可只发文字，或显式传就绪的 `recording_id`。同一会话省略该字段沿用当前录制，传新 ID 切换，显式 null 解除。发送前生成一次 `client_message_id` 并记下原绑定指令。请求未确认时换证或重试均复用原输入，拿到回执后只跟踪原 Job。普通追问跳过整套录制接口。切换 A 到 B 后已受理的 A 问题仍显示 A 的引用；发布、执行范围或连续会话策略变化时使用服务端返回的实际会话。

发送前按账号与应用保存非敏感的 client_message_id 及原会话和绑定指令，不持久化问题正文。单个控制台按用户提交顺序等待上一条受理回执后再发送下一条，不等上一轮回答结束；多窗口以服务端受理事务的顺序为准。原文仍在内存时可按原请求幂等重试。首问回执丢失且控制台已重开时，用消息 ID 查询回执，即使没有 conversation_id 也能找到原 Job。查询暂未命中可能是原请求仍在途，允许有限重查；没有可恢复正文时提示用户确认输入，以原键再次提交。同键异内容返回冲突，禁止自动换键重发。

初始化录制与提交消息均在 `X-Application-Scope` 头回传用户选择应用时取得的 scope_ref。服务端先校验当前身份和资源访问；未受理的旧请求遇到范围变化返回 `409 scope_changed`，不在新发布下自动创建任务。已受理请求只可在仍有读取权时返回原回执。用户重新选择当前范围后提交的新问题按既有规则分配会话。

按 SSE 帧边界增量解码 UTF-8，处理跨网络块的多字节字符和事件。按 Job 与 attempt 保存 Markdown 原文草稿。通过游标去重后按顺序追加文本，包括 Agent 在工具前后的说明和结论。合并短时间内到达的增量后，用随扩展打包的 markdown-it 重新渲染当前草稿。每批展示后一起确认对应原文和游标，断线续读时跳过已应用的事件。

草稿、快照及持久回答使用相同的渲染配置。支持标题、加粗、列表、表格与围栏代码块，保留原文中的空格和换行。关闭原始 HTML，仅允许用户点击 HTTP/HTTPS 链接，图片只展示替代文字，避免自动向外部地址发请求。reset、终态或切换 Job 时废弃旧草稿待执行的渲染，防止覆盖当前内容。

| 事件 | 展示与恢复 |
| --- | --- |
| `status` | 展示排队、分析、重试状态。 |
| `answer_delta` | 在当前草稿追加新游标对应的公开文本，忽略重复和过时连接的事件。 |
| `reset` | 丢弃先前 attempt 的预览，新草稿只接收当前尝试的增量。 |
| `completed` | 用持久助手消息整体替换草稿，只保留一条最终回答。 |
| `failed` | 清除未完成草稿，展示取消、超时或失败终态并结束订阅。 |

凭据失效时停止旧流，Job 继续执行。换证后在原 Job 上用最后已渲染游标重连。重开控制台时先从会话历史定位在途 Job；无草稿或游标过期时读取快照，已经完成时直接呈现权威终态。只收到终态的链路如实显示等待和结果，实时首段另行验收。

同一草稿与其游标一起推进。无匹配草稿、游标不可用或收到开流前的 `409 cursor_invalid` 时，经 `GET /jobs/{id}` 获取同一已提交位置的快照。快照包含 `job_id`、`state`、`attempt_id`、`through_cursor` 及对应的公开草稿（尚无文本时为空）；终态返回持久最终回答或安全失败。先整体替换本地状态，再从 through_cursor 严格向后重放并接上实时事件，覆盖读取快照与建立订阅之间的增量、reset 或终态。每个事件的 id 只在该 Job 内有效；使用十进制非负整数游标，0 表示尚未消费事件。切换 Job 时不得复用游标。终态后不再订阅。

SSE 响应头已发出后，到期或撤权通过停止数据并关闭连接生效。没有收到终态的 EOF 仅表示需要恢复；以当前身份读取 Job 快照或重新订阅，根据新 HTTP 响应处理认证、撤权、终态或网络重试。旧连接及旧尝试的迟到事件不得改变新草稿。

## Risks / Trade-offs

- 录制大小与字段分布差异大。以超过 100 MiB 的合成录制分别测量投影、实际传输字节和峰值内存，核对每个请求及操作的覆盖。压缩率取实测值。
- 目标部署的允许路径及诊断字段、分片预算与代理缓冲设置影响实机效果。使用固定身份的发行构建、真实 Chrome 和目标平台逐项验收，分别记录合成及实际模型证据。

## Migration Plan

先取得平台已发布的契约版本及非敏感合成样例，再接入试点应用。平台未配置或停用时保留控制台的本地采集入口；回退插件集成时保留本地录制，服务端已受理的 Job 按其既有策略结束。

## 平台内部录制权限

控制台使用已登录用户的业务凭据提交清单和分片。平台为当前用户确认的版本及指定分片签发内部写授权；Agent 工具仅可按本轮运行中的 Job 读取命中证据。插件只保存同一来源、用户、应用和发布范围内的上传回执。内部授权、存储地址及模型凭据均由服务端管理。
