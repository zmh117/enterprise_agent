# 任务工作区文本文件使用说明

业务应用只有在新发布版本选择 `text-v2` 后，才会把 `.log` 和 `.md` 纳入任务工作区；历史发布版本继续按 TXT-only 运行。

| 格式 | 可以发送给 Agent | Agent 可以创建/编辑 | 可以发送回会话 |
|---|---:|---:|---:|
| `.txt` | 是 | 是 | 是 |
| `.log` | 是 | 否 | 是，仅限清单中已有的精确版本 |
| `.md` | 是 | 是 | 是 |
| `.markdown` | 不进入任务工作区 | 否 | 仅保留旧附件兼容行为 |

三种工作区格式都必须是 UTF-8 且不超过 15 MiB。输入可以包含 UTF-8 BOM；Agent 新创建或编辑的输出不能包含 BOM。平台拒绝 NUL、无效 UTF-8、UTF-16、GBK 以及伪装成文本的二进制内容。`.log` 可以由上游声明为 `text/plain` 或 `application/octet-stream`，但后一种仍必须通过完整文本验证。

Markdown 只按不可信纯文本处理：管理端不预览或渲染正文，平台不执行内嵌 HTML、不解析链接、不抓取远程资源。需要 Agent 生成 Markdown 文件时，应明确说明“创建/编辑/保存/导出 `.md` 文件”；仅要求聊天回复使用 Markdown 排版、讨论 Markdown 语法或分析日志，不会自动开启文件写入。

LOG 被视为只读诊断证据。Agent 可以读取、搜索并把 Manifest 中已有的精确版本原样发送回会话，但不能写入、追加、改名后提交或创建新 LOG 版本。若需要整理日志内容，应明确要求生成新的 `.txt` 或 `.md` 报告。

默认交付只发送 Agent 明确提交的 TXT/Markdown 精确版本；“只保存到工作区”不会发送回会话。Delivery 重试同一版本，不会重新运行 Agent。切换回 `text-v1` 不会删除已创建的 Markdown 版本，已有且仍获授权的历史精确版本继续按保留策略只读保存和交付。
